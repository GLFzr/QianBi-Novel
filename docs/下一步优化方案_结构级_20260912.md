### 1.2 三个结构性缺陷（按影响排序）

**缺陷一：清算管道的"截断→重试→再截断"自我放大（37.9k/章，第一大鲸鱼）**
- 实测：5.8 笔/章（正常应 1.1），平均每笔输出 4,973 tok——**恰好贴着 5000 上限**。
- 机理：书变稠（30+ 实体）后清算 JSON 变长 → 顶到 max_tokens 截断 → JSON 解析失败 →
  重试（独立单发、全价重发 ~110k 输入）→ 又截断 → 升级 pro → 再花一笔。
  **上限从 8192 砍到 4000/5000 治好了爆炸，却制造了截断级联**——治标引出了新病。
- v11 对照：1.07 笔/章、out 3.7k/章（书稀 + 无截断级联）。

**缺陷二：头部 =「按卷拼接」而非「单一追加流」（卷界塌陷的根因）**
- 每个卷界：设定底册/世界书快照重冻结（卷内反哺使字节必变）+ 语料快照换新文件
  → 头部从变化点起全部失效 → 塌陷章（ch14/15/26/27）X 翻倍至 130-220k。
- 语料滚动（corpus_roll）解决了"卷内"的追加，但**卷界本身仍是头部重置事件**——
  因为基座层（底册/世界书）和语料层（章节全文）被绑在同一个按卷重建的文件里。

**缺陷三：字数超标链（trim 9.7k/章 + 一次彩票抽奖）**
- 细纲「预算合计」行与正文实际产出偏差 → 超标 → trim 独立单发（40k 级 miss/笔）
  → 修完还可能再触发。

### 1.3 为什么"稳态能到 95%"没有意义（用户判断的机理确认）

稳态章 87-91.6% 的曲线，每遇到一个卷界就被打回 70-80% 两章。按 13 章卷长：
**每卷 26% 的章节处于塌陷区**——全窗累计被结构事件锁死在 85-88%。曲线不平滑
的根源不是命中率工程没做好，而是**头部结构把"卷界"定义成了重置事件**。

## 二、结构级调整方案（S1-S5）

### S1 清算管道重构（第一优先，-25k/章）

1. **上限与解析匹配**：max_tokens 回到 8192；解析器加**截断 JSON 修复**
   （按最后完整数组元素截断 + 闭合括号），截断不再是失败。
2. **重试入会话**：重试与 pro 终审升级改为会话追加轮（失败轮 rollback 不留史，
   重试措辞扰动保留）——重试从"全价重发 110k"变"会话增量 ~5k"。
3. **输出瘦身 schema**：adoptions 数组 ≤12 条（超收编走下一章）、ledger_updates
   只记 delta——从源头把清算输出压回 3k 内。
- 预期：5.8 → ~1.2 笔/章，37.9k → **~12k/章**。
- 质量门：雷章召回 B01-D01 不降（E9' 教训：清算是最不能弱的闸）。

### S2 书级单一追加流头部（第二优先，卷界税归零 + H 单调）

1. **基座冻结上移到书级**：设定底册/世界书/卷纲在 ch1 冻结一次，全书不再重建；
   世界书卷内反哺走开幕轮近场字段（现状已有，正补偿）。
2. **语料流全书一个文件**：章节全文+细纲+摘要链只追加，卷界零事件。
3. 迁移：已有书首次切换时装配一次书级流（一次性 ~150k miss，此后永不再付）。
- 预期：每卷 2 个塌陷章消失（26% 塌陷占比 → 0）；H 每章严格单调。
- 风险：底册/世界书头部陈旧 → 近场补偿 + 人工检查点重冻（预注册一次性）。

### S3 字数链治理（第三优先，-7k/章）

- 细纲预算行抽检进预生成校验（预算合计 vs 章纲内容密度）；
- prose 首稿字数自检强提示已有 → 追加"超标立即自收束"；
- trim 触发 ≥2 次的章打标（产出质量观测）。

### S4 开幕轮密度压缩（-5~8k/章，第二批次）

- 八节中已被语料库覆盖的成分继续引用行化（corpus_mode 深化）；
- 角色状态/时间线等动态节保留（合法新料）但压缩格式密度。

### S5 调用数合并（-1~2 次抽奖/章）

- 章摘要+全局摘要合并（调整七遗留）；每减一次调用 = 少一次彩票抽奖
  （期望 3-5k/次）+ 少一次头重读。

## 三、数学：这些调整能把命中率带到哪

- X 稳态 = 彩票 25-45k（不可控外部项）+ 清算 12k + 开幕新料 12-15k + deslop/review
  材料 12-15k + tracking 5k + 输出残余（audit 治理后）≈ **65-80k/章**
- H = 头部 tok × 每章调用数。成熟书（45+ 章，书级流）头 180-250k tok × 8-9 笔
  ≈ **1.6-2.2M/章**
- **稳态综合 = 1800/(1800+70) ≈ 96%**；30 章新书窗约 88-91%（头部尺寸所限，
  结构性，与调优无关）。
- 新增曲线健康度指标（用户判断的量化）：**单章综合较前章跌幅 ≥5pt 的次数 = 0**
  ——卷界塌陷归零后此指标应恒真。

# 修订 v2：质量不变量深研后的修正（同日）

> 用户约束：**结构性调整不能影响输出作品的成熟度和质量**。据此对 S1/S2 做了
> 数据级深研，两处根因判定修正，方案重写如下；v1 中与之冲突的表述以本节为准。

## 一、根因修正一：清算级联 = 思考溢出，不是 JSON 截断

实测（v15_tail 30 份清算报告 + 逐笔 usage）：
- 清算产物极轻：violations **0.3 条/章**、adoptions **0.2 条/章**、ledger **0.3 条/章**
  ——可见 JSON 结论每笔只有几十 token；
- 但 audit 推理/输出比 = **100%**（推理 28,639 tok/章 ≈ 输出 28,678 tok/章），
  每笔输出贴着 5000 上限——**全部是思考，结论还没开始写就到顶**；
- 思考到顶 → 无可见输出 → JSON 解析失败 → 重试再想 5000 → 再失败 → 升级 pro
  → 5.8 笔/章级联。**v13 时代"截断级联"的定性是错的，真正的机制是思考溢出**。
- effort=low 实证无效（ReasonIF：推理模型对软提示的思考控制遵循率低）——
  思考治理必须走 thinking 参数本身。

### S1（修订）：清算思考治理三件套

| 件 | 内容 | 质量风险与门 |
|---|---|---|
| 1a | 清算预扫 **thinking: disabled**（对照检查任务，V4 报告：机械任务无差距） | 雷章召回 B01-D01 实测定案（现成测试资产）；引证验真与 beat_check 程序复核在环；召回降即回退 |
| 1b | 重试/pro 升级**入会话 + 失败轮 rollback**（同前缀命中价重发，无上下文污染——rollback 后上下文与首试逐字一致） | 零语义差异（同提示同上下文），纯缓存路径改造 |
| 1c | max_tokens 维持 5000（思考关后 out=结论 JSON ~1-2k，不再触顶；同时保住 v12 教训的爆炸闸） | 无 |

- 预期：5.8 笔/章 → ~1.2；audit 38k → **8-12k/章**（推理 28.6k→~0.5k）。
- 依据强化：v15 实测 violations 仅 0.3 条/章——当前"思考到顶"并没有换来更多
  发现，说明溢出的思考是无效复查而非深度检出；雷章召回门兜底。

## 二、根因修正二：卷界税实测隔离 + S2 的双写歧义消除

- 卷界章（14/15/26/27）X = **224.6k/章** vs 稳态章 **98.7k/章**——每卷 2 章
  共多花 ~25 万 tok miss，纯结构税。
- S2 质量风险重审：v1 版让"世界书卷首冻结进书级头"——但世界书是**动态文件**
  （卷内反哺持续追加），书级冻结会使头部副本越来越陈旧，与开幕轮近场新鲜副本
  形成**双写歧义**（模型看到两个版本的世界书）。修正：
  **世界书不入书级头，保持开幕轮近场单副本**（现状对 prose 本就双写，
  本修正消除而非引入歧义）；书级冻结只收**真静态**：题材定位底册 + 卷纲 +
  语料流（已锁章节全文/细纲/摘要链）。

### S2（修订）：书级单一追加流（三段真静态）

| 段 | 内容 | 为什么静态安全 |
|---|---|---|
| 基座 | 题材定位（底册）+ 卷纲 | 反哺不写这两文件；作者改动走人工检查点重冻 |
| 语料流 | 已锁章节全文 + 全部细纲 + 章节摘要链 | write-once，追加式 |
| 世界书 | **不入头**——开幕轮/审校/清算近场单副本（现状字段） | 消除双写歧义，陈旧性问题不存在 |

- 预期不变：卷界税归零（每卷 2 塌陷章消失），H 随章数严格单调。

## 三、质量不变量总表（每项调整的"质量为什么不变"）
