## 0. 一页结论

1. **外部证据全面印证本项目已验证的三大支柱**：append-only 前缀结构（= deepseek-harness 99.93% / Manus "KV 命中率第一指标" 的同构物）、级联清算（= FrugalGPT/AutoMix 谱系，我们实测 -82%）、任务性质决定思考档位（= OptimalThinkingBench / overthinking 研究线的结论）。**这三块不用再测，方向被独立证据确认。**
2. 账单 81% 在输出侧。本轮找到的**未用杠杆**按性价比排序：**O1 span 级修订输出**（deslop/trim/enrich/review_fix 只回改动段落，理论砍这些相位 50-80% 输出——SWE-agent 与 show-me-the-story 双源印证）→ **O2 prompt 内显式输出长度预算**（L1/s1 的 budget forcing，对 outline/prose）→ **O3 机械相位外迁便宜厂商**（doubao-lite 输出 8 倍差价、qwen-flash 3 倍、GLM-4.7-Flash 免费；DeepSeek 本家无 batch API 实锤）→ **O5 置信加权投票 + O6 条目级早停** → **O7 缓存卫生把 73-88% 推向 95%**（值总账单 10-15%）。
3. **三个实测反直觉结论进"不要做"清单**：章内 LLM 摘要式压缩（独立评测 +24-94% 成本，N1）；会话中途换模型/换厂商（缓存清零，ProjectDiscovery 实测 7%→84% 靠粘性路由救回，N2）；压缩已缓存的前缀（省的是 1/31 价的钱，负 ROI，N3）。
4. **方法论必须升级**：v1 的 4 颗埋雷样本按 Anthropic《Adding Error Bars to Evals》标准不够——需配对设计、雷数扩容（≥12-16 颗全维覆盖）、雷集轮换、双人核验（SWE-bench Verified 连官方 500 例里都审出 164 例缺陷测试）。**否则"-82%"级结论自身不可靠。**
5. promptfoo 可作"配置×变量"矩阵实验底座（原生 DeepSeek provider + cost/latency 断言），但其内置 DeepSeek 价目是促销旧价，**必须用 config 覆盖为台账口径**。

## 1. 分析基线：本项目成本结构（v0.18.4 逐笔还原 + 0.19 演进）

v1 报告已还原 0.18.4 验收跑（57 笔，off-peak）：输出 799k tok 占账单 **81%**，输入 miss 523k 占 18%，输入 hit 717k 占 1%。相位级输出大头：review 17.1k/笔（19 笔）→ **0.19 已改 disabled 档（612 tok/票，-65%）**；outline 38k/笔（0% 命中，431s）→ 0.19 已接前缀+批 2 章+low 档；prose 24.7k/笔；review_fix 32.6k（0% 命中）→ 0.19 已接前缀；trim 16k；canon_audit → E9 级联后 -82%。

**0.19 之后的预期结构（待 E0.1 重定基线确认）**：输出大头只剩 prose（~25k/章，含思考）、outline（low 档，量待测）、trim（16k/笔）、review_fix（~30k/笔，按触发率摊销）、级联预扫（~5k/章）。**因此本轮调研的杠杆全部指向：① 让"修订类"相位少输出（O1）；② 让"思考类"相位少思考（O2/O6）；③ 让"机械类"相位去更便宜的地方（O3）；④ 让剩余 miss 更少（O7）。**

单章成本演进（诚实口径）：0.18.3 ~¥0.26 → 0.18.4 ¥0.78（口径变化）→ 0.19 五章 e2e ¥0.33 → 级联后预计 ~¥0.25（待 E0.1）。台账合计 ¥26.84 / 577 笔。

### 2.1 DeepSeek 官方机制——增量细节（在 v1 已知机制之外）

| 发现 | 内容 | 对项目的动作 |
|---|---|---|
| **缓存单元三种固化** | 每请求在「用户输入末尾」「模型输出末尾」+ 长输入固定间隔切 unit；SWA 下命中要求**完整匹配某个 unit**（A+B→A+C 不命中，但 A 会被公共前缀检测固化） | 已知并利用；补充：**部分相同前缀 = 0 命中**，任何 unit 边界漂移都是全灭 |

| **reasoning_content 回放规则**（[thinking 指南](https://api-docs.deepseek.com/guides/thinking_mode/)） | 不开 tools：历史轮思考串不进上下文（传了也忽略，**不计费**）；开 tools：历史思考串必须原样传回，缺失直接 400 | 纯写作链无影响；**任何相位若引入工具调用，须处理思考串回放，否则 400/计费膨胀** |
| **effort 映射** | `medium`/`xhigh` 静默映射 `high`；实际只有 low/high/max | 已知；写进预设校验器防呆 |
| **无官方 Batch API** | sitemap 中 `/api/create-batch-file`、`/api/retrieve-batch` 均为死链（重定向首页），changelog 无记录 | **跨厂商 batch 才是 batch 通道**（见 2.5）；DeepSeek 内的等价物就是 off-peak 挂机 |
| **64 tok 最小缓存门槛（旧公告）** | [news0802](https://api-docs.deepseek.com/news/news0802)：<64 tok 不缓存；官方点名受益场景含"角色设定庞大多轮对话的 role-play" | 小说流水线是官方点名场景；超短调用（<64 tok 输入）不存在 |
| **缓存注册异步、TTL 小时~天** | 官方 "best-effort"，数秒构建、秒~分钟注册、闲置数小时~数天清除 | 已实测（enrich 0% 事件）；调用紧凑性纪律保持 |

### 2.2 deepseek-harness（dsh）99.93% 案例全链——结构拆解

**来源**：[官方页](https://www.deepseek.com/harness/en/)、[agent-loop README](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/core/agent-loop/README.md)、[inferloop 前缀稳定性实验](https://inferloop.dev/deepseek-harness/prefix-stability/)、[Designly 复盘](https://blog.designly.biz/how-deepseek-harness-saves-tokens-by-not-editing-history)、[discussion #2064 审计](https://github.com/deepseek-ai/deepseek-harness/discussions/2064)、[discussion #3304 零命中反例](https://github.com/deepseek-ai/deepseek-harness/discussions/3304)、[36kr](https://eu.36kr.com/en/p/3934404658642055)、[HN 交叉验证](https://news.ycombinator.com/item?id=48257509)（OpenCode 用户 30M token 实测 98.6%）。

**四件套设计**（与本项目章会话栈同构，验证我们的路线）：
1. 不可变前缀：system prompt + 工具表 + 会话派生态冻结，默认 system prompt 极简到一句话；
2. append-only："never edits sent tokens"，历史只追加（同负载下重写式贵 ~19 倍）；
3. **动态状态全部挪到消息末尾**（权限模式从 system prompt 挪到尾部 PromptContext——放前缀里一次切换命中从 14.7k 掉到 256）；
4. **压缩/摘要请求 = 原样重放上一请求 + 尾部追加指令**（严格前缀扩展；甚至给不调工具的摘要请求也照发全套 tool schemas 只为字节对齐）。

**inferloop 10 变量实验数字**（一手数据，最值得参考）：

| 扰动 | 命中率 |
|---|---|
| 基线（append-only） | 98.8% |
| 末尾追加消息 | **98.7%（免费）** |
| 改 system prompt | **归零** |
| 改最后一个工具描述 / 末尾新增工具 | 最好只保 17-18% |
| **交换两个工具顺序** | **100% 作废** |
| 换模型 | 清零（缓存按模型索引） |

**#2064 社区审计**（650 请求 / 155.9M prompt tok，实测 98.09%）：**会话首个请求占整单成本 ~52%**（每次同样的 8,246 miss tok 冷启动）；**tool schemas 占前缀 30,282 字符中的 26,182（86%）**，其中一半是根本不会调的工具；裁剪工具（[dsh-lean](https://github.com/sjh9714/dsh-lean)）省 ~20%。→ **对本项目**：我们没有工具表，对应物是 **project_header 里的"设定全家桶"**——审计一次 project_header 的逐块利用率（哪些块从没被任何下游相位真正用到），是零成本高确定性动作（并入 E0.2）。

**反例清单**（0% 命中的坑，全部有 issue 实锤）：#3304（前缀不稳定+27KB 工具开销）；[SillyTavern #4260](https://github.com/SillyTavern/SillyTavern/issues/4260)（开向量检索后命中 80%→5%，**检索块插进 prompt 中部破坏前缀**）；[Cherry Studio #14695](https://github.com/CherryHQ/cherry-studio/issues/14695)（42,681 miss vs 1,280 hit）；[new-api #6212](https://github.com/QuantumNous/new-api/issues/6212)（**streaming 与非 streaming 的 prompt_tokens 计数差 400-1000，打碎上游缓存**）；LiteLLM [#28045/#26395](https://github.com/BerriAI/litellm/issues/28045)（代理剥离 reasoning_content 导致 400）；[openclaw #94518](https://github.com/openclaw/openclaw/issues/94518)（升级后 95%→<10%）。另有框架复盘：[Reasonix 三区结构](https://dev.to/esengine/how-a-deepseek-only-agent-framework-hit-85-prefix-cache-rate-and-saved-93-vs-claude-5c9g)（不可变前缀 + append-only 日志 + 绝不发送的 scratch 区，命中 85-95%，连 **tool schema 重新序列化时的空白字符差异**都会毁缓存）。

### 2.4 论文机制表（按杠杆分类）

**级联与路由**：
- FrugalGPT（[2305.05176](https://arxiv.org/abs/2305.05176)）：级联 + **学习型打分器**（DistilBERT 回归）判答案可接受度，Headlines -98.7% 成本匹配 GPT-4。→ 我们用 flash 预扫 flag；未用的是"打分器"：积累 flagged/未 flagged 历史后可训练轻量打分替代逐项预扫（O9，远期）。
- AutoMix（[2310.12963](https://arxiv.org/abs/2310.12963)）：小模型自答→**自验证**→POMDP 路由（验证不确定时倾向升级）。→ 给 E9 级联加"预扫自验证"降低漏检风险（O9）。
- EcoAssistant（[2310.03046](https://arxiv.org/abs/2310.03046)）：**成功解法入库，相似问题检索作示例**，只花基线 ~10% 成本。→ **修复示例库（O4）**：历史成功 REVIEW_FIX diff 按缺陷类型检索注入，让修复在 flash 一次过。性价比极高、风险低。
- RouteLLM（[2406.18665](https://arxiv.org/abs/2406.18665)）/ Hybrid-LLM（[2404.14618](https://arxiv.org/abs/2404.14618)）：偏好数据训路由器、按质量目标路由——任务级路由我们已有，远期可用埋雷结果当偏好对训练相位级路由。

**上下文压缩**（先记住前提：**DeepSeek hit 价是 miss 的 1/31，压缩已缓存前缀是负 ROI**——压缩只该作用于 miss 尾巴）：
- LongLLMLingua（[2310.06839](https://arxiv.org/abs/2310.06839)）：**任务感知**压缩——只保留与当前问题相关的文档，-94% 成本且性能 +21.4%（去 distract 提分）。→ **对账清算改为"按对账条目检索相关设定片段"而非整段设定注入**（O10，远期 100+ 章规模）。
- RECOMP（[2310.04408](https://arxiv.org/abs/2310.04408)）：检索文档抽成 6% 长度要点再注入。→ 同上，作用于追踪器/设定集的注入方式。
- LLMLingua-2（[2403.12968](https://arxiv.org/abs/2403.12968)）/ Selective Context（[2310.06201](https://arxiv.org/abs/2310.06201)）：抽取式压缩 2-5x——工程成本高于收益，暂缓。
- Gist tokens（[2304.08467](https://arxiv.org/abs/2304.08467)）：需改模型内部，API 场景不可用。

**思考预算控制**（输出侧 81% 的主战场）：
- s1 budget forcing（[2501.19393](https://arxiv.org/abs/2501.19393)）/ **L1**（[2503.04697](https://arxiv.org/abs/2503.04697)）：**把目标长度显式写进 prompt**（"think about N tokens"）能实际改变推理长度，得到平滑 length-accuracy Pareto 面。→ **O2：outline/prose 加显式长度预算提示**，这是纯 prompt 改动、零基建。
- Certaindex/Dynasor（[2412.20993](https://arxiv.org/abs/2412.20993)）：**答案稳定即早停**，-50% 计算精度不掉；answer convergence（[2506.02536](https://arxiv.org/abs/2506.02536)）：60% 步骤后答案收敛，token -40%+。→ **O6：清算/审校条目级早停**。
- Overthinking（[2412.21187](https://arxiv.org/abs/2412.21187)，ICML 2025）/ OptimalThinkingBench（[2508.13141](https://arxiv.org/abs/2508.13141)）：简单判断任务过度思考**掉分**。→ **印证我们"checklist 型任务关思考"的分型结论**（v1 埋雷实验的学术版）。
- Thinkless（[2505.13379](https://arxiv.org/abs/2505.13379)）/ AdaptThink（[2505.13417](https://arxiv.org/abs/2505.13417)）：NoThinking 在简单任务持平。→ 支持审校平票确认票进一步降档。
- **文献空位（有价值）**：没有人做过"截断思考对检测类 vs 生成类任务"的直接对照实验——我们的埋雷法恰好能产出这个证据。

**投票与一致性**：
- Self-Consistency（[2203.11171](https://arxiv.org/abs/2203.11171)）：收益 ~10-20 票饱和（三票是下限，靠埋雷标定）。
- Adaptive-Consistency（[2305.11860](https://arxiv.org/abs/2305.11860)）：贝叶斯早停，采样 -7.9x 精度损失 <0.1%；ESC（[2401.10480](https://arxiv.org/abs/2401.10480)）：滑动一致窗口，-33.8~-84.2%。→ 已用（review_pass_fast），**窗口参数可按任务调**。
- **CISC**（[2502.06233](https://arxiv.org/abs/2502.06233)）：**按自报置信度加权投票**，路径数 -40%+ 仍胜普通 SC。→ **O5：三票带 confidence 字段加权重裁**，平票免补投。
- MAKER（[2511.09030](https://arxiv.org/abs/2511.09030)）：first-to-k 流式收票，百万步级零错误。→ 清算=海量小判定，逐条流式收票领先即停（远期与 O6 合并）。

**缓存系统论文**（自托管向，API 不可用但设计启示直接）：SGLang RadixAttention（[2312.07104](https://arxiv.org/abs/2312.07104)，**fork 共享前缀 = 三票审校的理论模型**）、Parrot（[2405.19888](https://arxiv.org/abs/2405.19888)，把流水线声明为 DAG 做前缀去重）、Mooncake（[2407.00079](https://arxiv.org/abs/2407.00079)，**同会话调用紧凑连打保 TTL**）、vLLM APC（一字之差毁其后所有 block）。

**评测方法论**（直接改造我们的埋雷法）：
- **Anthropic《Adding Error Bars to Evals》**（[2411.00640](https://arxiv.org/abs/2411.00640)）：问题为采样单元、**配对差分检验**、cluster bootstrap 处理章内聚类、power analysis 定样本量；误差棒按 1/√n 缩减。→ **v1 的 3 章 ±10-18% 噪声地板与此一致；检出 <20% 差异需加样本或配对**。
- LLM-as-judge 偏置（MT-Bench [2306.05685](https://arxiv.org/abs/2306.05685)、位置偏置 [2406.07791](https://arxiv.org/html/2406.07791v1)）：**每票随机化待检项顺序可消除首位偏置，零成本**。
- 埋雷集本身要核验：SWE-bench Verified（2294→500 例人工筛，每例 3 标注者；后续审计仍有 ~164 例缺陷测试）；CRUXEval 用"未来变体"防记忆化。→ **雷集轮换 + 双人核验**。

**2025-2026 新线**：
- **ACE**（[2510.04618](https://arxiv.org/abs/2510.04618)）：上下文作为"进化 playbook"，**条目级 delta 更新而非全量重写**——省钱+保缓存+防信息蒸发三合一。→ **O8：追踪器（角色状态/时间线/伏笔表）从"每章全量重写"改为"delta 条目更新"**。
- AgentDiet（[2509.23586](https://arxiv.org/html/2509.23586v2)）：轨迹删减 -21~36% 总成本。→ 修复循环的失败尝试可删减回灌。
- Mem0（[2504.19413](https://arxiv.org/abs/2504.19413)）：外置记忆层对 full-context **省 >90% token**。→ O10 的实现路径。
- 有效上下文实测（[2509.21361](https://arxiv.org/abs/2509.21361)）：实际可用窗口远小于标称——注入材料宜短不宜长（质量侧支持 O10）。

**混用陷阱（重要）**：缓存 per-vendor（甚至 per-replica），换厂商=前缀缓存全丢。[ProjectDiscovery 实战](https://projectdiscovery.io/blog/how-we-cut-llm-cost-with-prompt-caching)：名义开启缓存实际只 7%，改粘性路由（同会话钉死同 provider）后 84%，总成本 -59%。[Beri.net](https://www.beri.net/article/best-llm-gateways-multi-provider-cost-control-2026)："agentic 场景下 provider prompt caching 主导账单，跨厂商路由基本就是把它扔掉"。**结论：逐相位整段外迁（stateless 单发调用）安全；章会话栈内逐轮跨厂商 = 自毁缓存（N2）。**

| **O10** | **检索化对账**：清算/审校的设定注入改为"按对账条目检索相关片段"（含 ST 式 cooldown/probability 治理） | 输入 miss+质量 | 长书规模才显著；短书是质量正收益（去 distract） | 中高 | 中-高 | 低（LongLLMLingua 证据是正收益） | LongLLMLingua；Mem0；ST WI |
| **O11** | **promptfoo 矩阵台 + Langfuse 缓存曲线** | 方法论 | 实验效率翻倍；缓存回归可视化 | 高 | 低-中 | — | promptfoo；Langfuse |
| **O12** | **埋雷法 v2 统计加固**：雷 ≥12-16 颗全维、双种子、雷集轮换、双人核验、票序随机化 | 方法论 | 所有质量结论可信度↑ | 高 | 低 | — | Anthropic error bars；SWE-bench Verified |

### 3.3 反模式清单（N1-N9，全部有实测/实锤来源）
