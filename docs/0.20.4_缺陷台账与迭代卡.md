**A17 机制（本轮最重要的产品发现）**：

### 6.12 **A17 终裁：覆盖闸门误报率 100%（6 章 24 节点逐条裁定）**

裁定方法：子代理按 `app/core/stages.py:2039 _missing_cover_nodes` 现行代码原地复算 6 章 → **24/24 节点全判「缺失」**（与票面 4/5/4/3/4/4 项吻合）；再由人工逐条对照正文判定四类。

| 类别 | 定义 | 数量 |
|---|---|---|
| A 逐字/近义明确在场 | 节点要件能在正文里指认 | **19** |
| B 语义在场但换形态 | 事件发生，媒介/顺序/角色/细节被替换 | **5** |
| C 真未演 | 通读未见或要件缺失 | **0** |
| D 无法判定 | — | 0 |

⇒ **真漏演 0/24；「检测器过严」实测值即上界 = (A+B)/24 = 100%**。窄定义（纯字面失配、连换形态都不算）占 5/24 ≈ 21%。
按 rule of three 外推：全量两本 98 章共 **382 条节点缺失声明**，真漏演 ≤ 约 49 项 ⇒ **判定噪声 ≥ 87%**（样本为定向抽样非随机，但最终稿只会比中间稿更完整，结论不弱化）。

**三个机械失配（判定口径确为"字面命中"）**：
1. **标点即致命**：节点写作 `'别信那个打电话的人'`（含 ASCII 单引号），正文内容逐字在场但无引号 → 判缺失。
2. **节点内 `/` 被当作分支切碎**：`re.split(r"[|｜/／]", s)` 把括注切开，票面出现「信封物证检查（邮戳手工加盖」「纸张纹理）」这类**带悬挂括号的碎片**，永不命中。git 确认该正则自 3a3efa3 引入起从未包含 `、`（旁证：book01 第 3/4 章磁盘细纲该处现为 `、` ⇒ 那两章细纲在跑批后被改过）。
3. **`all()` 而非 OR**：分隔符两侧本是并列方面/近义写法，代码要求全部要件同时出现，任一缺席即整节点判缺失。
4. **代码与自己的 docstring 矛盾**：docstring 自称「宽容口径：模型复述要件即可，不要求逐字复现整行」，但该宽容**仅在节点含 `|｜/／` 时生效**；不含分隔符时 `need=[s]` 退化为逐字。
5. **票面被截断**：`_coverage_finding` 只取 `missing[:4]`，所以用户看到的永远是「3-4 项」，实际声明数更多（两本合计 382 条）。

**反向盲区（更严重的一半）：闸门只读 `must_cover_nodes` 字符串，完全不读 `法证级细节冻结表` 与 `forbidden_zones`**。本样本里**它 0 命中**的真实硬伤（全部由人工读出来的）：

| 01 ch2 | 冻结表要求「白色信封 / 邮戳江城」，正文主载体是电子邮件，章末信封却写「邮戳和寄件人栏都空着」 | 冻结细节被改写 |
| 01 ch30 | 栖霞路文件袋交付人由「顾远山留下」改成「沈知薇从包里翻出」 | 角色张冠李戴 |
