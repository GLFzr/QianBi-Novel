# Agent 化测试流程与验收矩阵 v1

> 目的：用数据决定「Agent 化做到哪一层」，并量化每一层对使用成本的影响。
> 原则：每一层的上线与否由黄金指令集的评测数据决定，不拍脑袋；
> 质量红线（写作链路的 prompt 基线与生成质量）不因 Agent 化改动而漂移。

## 一、成熟度阶梯（做几层，做到哪层停）

| 层级 | 形态 | 能力 | 边际成本 | 状态 |
|---|---|---|---|---|
| **L1 规则指令层** | 中文规则解析 → 6 工具执行 | 高频确定性指令（回退/重跑/重写/看章/开关设置），零延迟零 token | **0**（纯本地） | ✅ 已落地（0e028eb） |
| **L2 LLM 意图兜底** | 规则未命中且疑似指令 → helper 槽小调用解析为 JSON 工具调用 | 口语化/变体表达（"刚才那章不行，重来一遍"） | ~0.3-1k tok / 次未命中 | 本轮评测定夺 |
| L3 常驻操作助手 | 多轮会话 + 工具循环（看到执行结果继续操作）+ 破坏性操作确认流 | 连续任务（"看看第3章→嗯有问题→回退到去味"一条链） | 1-3k tok / 轮 + 会话上下文 | 待 L2 数据 + 公测使用率证明 |
| L4 流水线总控 Agent | 主循环由 Agent 自主决策（回退/重试/跳过的自主判断） | 全自动 | 不可预估 | **不做**：架构风险与质量不可控，与"作者掌舵"产品定位冲突 |

## 二、验收矩阵（每层的上线门槛，全部量化）

| 指标 | 定义 | L2 门槛 | L3 门槛 |
|---|---|---|---|
| 指令理解率 | 黄金集 A（明确）+ B（口语化）的 tool+args 全对率 | ≥ L1 + 15pct | ≥ L2 + 10pct |
| **误触发率** | D 类（非指令：审校问题清单/讨论/写作指导）被当成指令执行的比例 | **≤1%**（红线：审校问题清单绝不能被执行为操作） | ≤1% |
| 歧义处理 | C 类（缺宾语/多解）应返回澄清而不是猜 | ≥90% 走澄清 | 同 |
| 单指令边际成本 | 解析 + 执行的增量 token | ≤1.5k tok | ≤3k tok/轮 |
| 执行正确率 | 工具执行后状态断言（单测矩阵） | 100%（既有 25 项不回退） | 同 |
| 回归安全 | prompt 基线 / 双仓 / 写作链路 | 零漂移 | 同 |

## 三、黄金指令数据集规范（tests/evals/agent_instructions.json）

四类、每条带标准答案（tool + args 关键字段）或 `none`：
- **A 明确指令**（~15 条）：规则层必须命中的表达
- **B 口语化/变体**（~15 条）：规则层可 miss，是 L2 的价值区间
- **C 歧义/需澄清**（~8 条）：正确行为是返回澄清，不是猜
- **D 非指令干扰**（~18 条）：审校问题清单、讨论消息、含指令动词的写作指导——**绝不能触发**

数据集随评测器迭代扩充；每条误判都转化为回归用例。

## 四、运行方式

```bash
python scripts/agent_eval.py                 # L1 规则层报告（准确率/误触发/分类明细）
python scripts/agent_eval.py --llm           # L2：规则未命中时走 LLM 兜底（真机）
python scripts/agent_eval.py --verbose       # 逐条明细（含误判原因）
```

## 五、首轮评测结果（2026-09-06，数据驱动裁决）

| 指标 | L1 初版 | L1 数据驱动修复后 | L1+L2（对抗集） |
|---|---|---|---|
| 黄金集 A+B 理解率 | 70% | **100%**（A 15/15 + B 16/16） | —（全命中无兜底空间） |
| 黄金集 D 误触发 | 11.1% | **0%** | 0% |
| 黄金集 C 硬猜 | 12.5% | **0%** | 0% |
| 对抗集理解率 | 20%→44%（两轮修复） | 44.4% | **88.9%** |
| L2 兜底成本 | — | — | 均 **255 tok/次**（门槛 1.5k 的 1/6） |

- 评测器修出的真问题（全部转化为规则回归）：重写规则把写作讨论当指令（"重写这一段的时候…"）；
  status 把评价当查询（"状态写得不错"）；read 把"重新读一遍第二章，注意时间线的写法"当查看。
  修复手段：guess 级必须带**章级指示**；查询类必须**询问语气**；读章类带**修改意图后缀负向条件**。
- 中文数字章号（"第三章"）此前完全不支持——真实用户高频口径，已修。
- **裁决：L2 上线**（理解率 +44pct、误触发 0%、成本可忽略），挂接于共写对话：
  规则未命中 + 本地预过滤（消息含指令动词线索）→ L2 解析 → 执行 → 回显。
- L3 等公测使用率数据（指令功能使用频率）再定；L4 不做。

## 六、成本账框架（与写作主链路的关系）

写作主链路（基线实测）：~¥0.31/章（审校 disabled 后更低）。Agent 化成本按「每次作者交互」计：
- L1：0
- L2：仅规则未命中的指令触发，估 10-30% 的指令需要兜底 → 每次交互摊薄 ~0.1-0.3k tok ≈ ¥0.0002——**相对主链路可忽略**
- L3：多轮会话每轮 1-3k tok；价值取决于使用频率（公测数据包有 phase 使用统计，可观测）
- 结论预写：L2 的成本几乎必然可忽略，决策变量是**理解率提升**与**误触发控制**；L3 看使用频率数据再定。
