# 0.20.0 全量台账与落地方案（design v1）

> **性质**：本轮唯一实施依据。用户裁决（2026-09-14）——
> ① v0.20.0 是「最接近正式版的版本」，前提是把**目前隐形的问题全改掉**；
> ② 隐形问题面 = **A 静默失效 + C 对外说谎（含不符合项目目的的使用逻辑）+ D 只有外人/干净机器才炸**；
> ③ **B 不可观测（钱/重试/票/崩溃遥测）本轮不做**，写进「明确不做」；
> ④ UI 线升为第二轮主干，**波次 2/3/4 全量做完**，解决「扁平化、无高级感、无确认感」；
> ⑤ 历史各轮排队的需求**全量并入 0.20.0 之前的范围**，本文即该全量统计。
>
> **发布冻结纪律不变**：用户明说「发布 0.20.0」之前，只进 main 与测试体系，绝不发版、绝不打 tag。
> **取证纪律**：阶段 0 只登记不改码；每修一项必须留下一道「下次再隐形就炸」的护栏。
>
> 取证方法：三路静态审计子代理 + 主代理复核，全部带 `file:line`。
> 标 **[待取证]** 的条目=断言来自旧文档或单一读码路径，修复前必须二次确认。

## 1. 判据尺（审计与验收共用，五把尺来自用户原话）

| 尺 | 内容 | 谁违反算缺陷 |
|---|---|---|
| **1 作者掌舵有没有被削弱** | 任何让作者在不知情/不方便下被代做决定的交互：预设值替你定了、绕过了闸门却不留名、停下来了但没给可点的下一步 | 门/锁定/预设/默认值 |
| **2 流水线说不清自己** | 跑得动但说不清干了什么：状态错报、失败只写日志、分不清在跑还是卡死、账对不上 | 状态呈现/回执/统计 |
| **3 新人能不能走通** | 第一次打开→贴 Key→写出一章→拿到导出之间的断点与术语墙 | 引导/文案/黑话 |
| **4 长书用家用不了** | 规模上来才出现的逻辑断裂：50+ 章队列、世界书条目变多、多卷切换、书架计数 | 信息架构 |
| **5 Agent 帮不帮得到** | 用户原话：「agent 是否能帮用户实际改用户提到的所有问题，用户可能在任何一个环节提出不在该环节可能要改的问题」 | Agent 行动半径与诚实度 |

**三态判定**（每条缺陷登记时必须给）：`代码在` / `有路径能触发` / `用户能感知`。
只有「代码在」的功能对用户不存在——本轮绝大多数 P0 都是这一类。
