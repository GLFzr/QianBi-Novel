## 实验有效性注记（读表前必看）

- **E1-E4 跑在「全 pro」事故配置下**（模型分布 pro×24/28 如实记录）：当时实验台
  _mk_cfg 的 pro 连接拼接存在 Python 运算符优先级 bug（`A if pro else [] + [...]`），
  三条连接只剩 pro——E1「基线」实际是全 pro 底色，¥1.943/3 章不代表 0.18.5 默认配置。
  E5b 起修复（flash×9/pro×3），其审校/追踪相位才是 flash。E2/E3 的对比结论方向不变
  （同底色下变量对照），但绝对成本数值不可与修复后的变体直接互比。
- **E5b vs E9b 是同输入同模式的清算对照**：跑级成本 ¥0.879 → ¥0.281（-68%，含追踪/摘要
  等其他相位噪声）；**相位级**（只看 canon_audit 相位）pro 全量 47.3k tok → flash 预扫
  14.1k + pro 复核 3.7k，**-82%**——两个口径都对，正文引用注明层级。
- **单章成本演进（诚实口径，注意字数目标不可直接比）**：0.18.3 能力轮 ~¥0.26/章
  （2000 字目标 + off-peak）；0.18.4 验收 ¥0.78/章（3000 字目标 + 细纲 41k 输出时代）；
  0.19 五章端到端 ¥0.33/章（2500 字目标 + 级联前架构）；0.19 级联后清算环节 -68%，
  全流程预计 ~¥0.25/章（待正式对照跑）。
- 全部调用走 off-peak 时段（除 09-05 验收部分白天），若含 peak 价成本更高。

## 数据完整性说明（已知缺口，诚实列账）

1. **0.18.4 期间约 544 行丢失**（2026-09-01 ~ 09-05 白天）：一次实验台冒烟测试
   误截断了真实目录的 usage.jsonl，当时已披露并从日志恢复出 08-31 的 151 行；
   丢失段含能力轮后续迭代与部分手动测试，**无法恢复**——故 0.18.4 的单章成本
   口径只有 09-05 晚间验收跑（57 笔）这一个样本。
2. **5 章 e2e 的一次完整跑丢失**（0.18.5 架构，61 笔请求、5/5 章 verdict 全过）：
   当时 e2e 收尾脚本直接 rmtree 了 fake home，用量与章节产物一起被清；
   之后 e2e 已改为「先留存 artifact+usage 再清理」，现台账收录的是留存版
   （46 笔）与被杀前幸存的残留（31 笔）。
3. **非真机调用不在账内**：单测/mock/离线探针零 API 消耗；mock 客户端跑的
   端到端（test_5ch_mock 等）不计成本。
4. 价格若按 peak 档（北京时间工作日 09:00-12:00 / 14:00-18:00 全价）则翻倍，
   本账全部按实际发生时段的 off-peak 口径。
