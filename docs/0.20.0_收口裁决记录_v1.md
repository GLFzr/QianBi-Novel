  `installer.iss` 的 `;SignTool` 开关位维持注释状态。

## 3. Q4 · 更新私钥备份：本地加密备份（不上云）

- **裁决内容**：三个备选（云盘 / 纸质助记词 / 换签名方案）之外，采纳**「本地加密备份」**
  方案：`scripts/update_keys.py` 增加本地加密备份能力——私钥用口令加密后在本机（及用户
  自选的本地介质）留存副本，**不上传任何云服务**。由主控实施。
- **理由**：L3-05 的敞口是「私钥只在 `%LOCALAPPDATA%\qianbi_sign\ed25519.key` 单机单份，
  机器坏了就再也签不出可自动安装的版本」。云盘方案把「能推包的能力」暴露给第三方托管，
  与本项目「全本地、无云端」的隐私立场冲突；换签名方案要发新版且老客户端不认新公钥，
  代价最大。本地加密备份在零外泄面的前提下消解单机故障风险，与 update_keys.py 现有的
  「私钥绝不落工作树」纪律（`--gen` 直接拒绝仓库内路径）同构。
- **影响面**：`scripts/update_keys.py` 新增备份/恢复子命令（主控实施）；README 更新链路
  文档不变（对用户无感知）；台账 L3-05 行由「敞口仍在」更新为「方案已定，待实施销号」。

## 4. Q5②③ · 命中率验收渠道与 miss 判据

- **裁决内容**：
  - **Q5②（99% 命中率在哪条渠道验收）**：定**生产主渠道**——DeepSeek 官方
    （`ds-official-flash` 行对应的 `https://api.deepseek.com`）。网关类渠道（TokenRhythm 等）
    的缓存写入/保留特性会使同一套代码差出 4-6 个百分点，对外口径只认生产主渠道实测；
    其他渠道数据仅作内部归因参考，不进对外承诺。
  - **Q5③（miss 判据）**：`miss ≤15k/章` 与「卷末 hit%」单点判据**弃用**，改采
    **「整卷均值 + 重复测量」**口径：命中率按整卷累计均值评估，关键结论须重复测量
    （同配置多章/多卷复跑）再定案。
- **理由（旧口径为何弃）**：**单章噪声大、卷末点值不稳**——T1 二十章长跑实测网关记账
  抖动下单章 hit 最低 75.4%、卷末单笔在 93.8%/95.9% 间跳动，单点值会被一次冷击或一次
  网关缓存驱逐整个带偏；整卷均值把这些抖动摊掉，重复测量则把「抖动」与「退化」区分开。
  原判据是按直连渠道记账习惯定的，网关时代照用等于拿骰子当尺子。
- **影响面**：`docs/测试共享状态.md` §6 决策 2/3 落定；后续长测（L5-C2 T3 压力终验等）
  的验收判据按新口径执行；README/CHANGELOG 涉及命中率数字时继续沿用
  「94-96% 为理论终点推算值，非长跑实测」的既有标注纪律。
