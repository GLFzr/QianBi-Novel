## 四、B-1 升级前后行为差异表（按四类用户分列；R17 验收件，交用户过目）

出厂 `writing.run_mode` 已 auto→cw。改动**只通过两条通道触达用户**：①全新安装
的出厂 config；②新项目创建时点（newProject 显式把出厂档位写进 state.cw.mode）。
既有项目的 `state.cw.mode` 全程不被读写改写（`st.raw_cw_mode` 只读；
`test_open_project_never_writes_mode` 钉死）。四类用户升级前后可感知行为：

| 用户类别 | 升级前（≤0.19.x） | 升级后（本改动） | 可感知差异 |
|---|---|---|---|
| **全新安装**（首次运行生成 config） | 出厂 auto：首屏「全自动」选中，点「开始」直接全自动跑完整本 | 出厂 **cw**：首屏共写六阶段导航，从立项开始对话式推进；「开始」按钮在共写档会提示走「确定」流程 | **有**——第一天即共写（用户裁决的意图本体）；自动档仍在流水线面板可一键切回 |
| **未表态旧项目**（老版本创建，state 无 cw.mode；config 盘上值=auto） | 自动档运行（ensure_cw 缺省填 auto） | **保持自动档**（raw_cw_mode 为空 ⇒ 读 config；老 config 盘上显式 auto 原样保留） | **无**——这正是 R17「不许回填」的落点（test_unexpressed_old_project_stays_auto 钉死） |
| **显式 auto 旧项目**（作者曾切到自动，state.cw.mode='auto'） | 自动档 | 自动档原样（raw 读到显式值，出厂默认不覆盖） | **无**（test_project_explicit_mode_respected 钉死） |
| **显式 cw 旧项目**（state.cw.mode='cw'） | 共写档 | 共写档原样 | **无**（同上） |

config 层旁证：所有旧版升级到 v1.2+ 的 config 都会**显式**落 `run_mode`
（v1.2 迁移 `_migrate_run_mode` 写 auto，或盘上既有值），load 的 merge 只补
缺失键 ⇒ 出厂 cw **触达不了任何一位存量用户的 config**（
`test_legacy_explicit_auto_survives_load` 钉死）。全新的软开局方案
