# 出问题了怎么办（排障 v1）

- 版本：v1（0.22.0 试验版，2026-09-29 建）。
- **文案纪律**：下表「屏幕文案」一列逐字抄自当前源码 `app/llm/client.py` 与
  `app/ui/bridge.py`（f-string 变量以 `{name}` 或 … 原样标注），并由
  `scripts/check_docs.py` 第 4/5 项检查钉死——文档文案与屏幕文案一旦漂移，脚本即红。
  出处列只给文件不给行号：行号随版本漂移，以能 grep 到文案为准。
- 每条格式：**你看到什么 → 意味着什么 → 现在做什么 → 还不行就报障包**。

## 怎么用这一页

1. 在下面「错误对照表」里 Ctrl+F 搜你屏幕上的那句话（抄一段原文即可）。
2. 按「意味着什么 / 现在做什么」处理。
3. 还不行 → 按文末「日志与现场三件套」导出**报障包**，提
   [Issue](https://github.com/GLFzr/QianBi-Novel/issues/new/choose) 时附上。

## 不在应用内的报错（系统 / 环境级，文案随系统版本不同）

- **Windows 蓝框「已保护你的电脑」**：安装包没有代码签名证书（独立项目证书年费不划算），
  这是缺证书、不是文件坏了。点 **「更多信息」→「仍要运行」**；不放心先对 SHA-256
  （每个 Release 附 `SHA256SUMS.txt`）。详见 README「Windows 弹『已保护你的电脑』」一节。
- **更新面板里四条通道各自的死因**（连接被重置 / 404 / 超时等）：面板逐条列出每条通道
  是怎么死的，据此判断该配代理还是走「导入离线清单」。死因文案来自
  `app/update_check.py` 的人话版错误解释，随网络环境变化，不做逐字对照。
- **首启动在无网环境等待**：更新检查四通道逐条试错不影响进入应用；离线机器可在更新面板
  关掉「启动时自动检查」，之后启动零请求。

## 日志与现场三件套（报障前的现场在哪）

| 现场 | 位置 | 说明 |
|---|---|---|
| 程序日志 | `%USERPROFILE%\.qianbi_novel\logs\qianbi.log` | 滚动日志：单文件 2MB × 5 份，自动轮转（`app/logger.py`） |
| 崩溃 dump | `%USERPROFILE%\.qianbi_novel\crashes\` | 崩溃现场自动留档，统一脱敏（`app/crash.py`） |
| 报障包 | 「导出」对话框一键生成 `报障包_<时间戳>.zip`，落在书目录（无书时在配置目录） | 两档：**含书稿档**（对话记录=书稿正文 + 日志 + 版本 + 脱敏配置摘要）/ **仅日志档**；包内文本全部过脱敏（api_key 整段剔除、家目录替换为 `<HOME>`），生成后 toast 会提示「确认内容后再发给开发者」（`app/report_bundle.py`） |

## 现场保命三招（崩溃 / 断电 / 改崩了）

- **断点续跑**：每本书的 `pipeline_state.json` 记录流水线断点，崩溃/断电后重开应用从断点
  继续，不重跑已完成的章。
- **防抖草稿 + 版本**：共写正文 5 秒防抖草稿暂存（`正文/.drafts/`）；保存驱动版本
  30 版/章（`正文/.versions/`），diff 与回退随意。
- **审校不收敛不会烧钱**：反馈环 3 轮熔断，不收敛的章节标「待人工」停止自动重试——
  不会无限重试烧 token。
