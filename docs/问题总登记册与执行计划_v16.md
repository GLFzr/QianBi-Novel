## A 类：缓存/成本结构问题

### A1 清算会话化旗标静默失效 + 思考溢出（第一大鲸鱼，37.9k/章）□

- **现象**：canon_audit 5.8 笔/章（应 1.1），每笔 in 仅 ~6.3k tok（独立单发签名），
  每笔 out 恰好 5,000（思考打满上限）。30 章 173 笔 × 5k = **865k tok 纯思考
  输出（28.8k/章）**，而实际产出仅 violations 0.3 条/章、adoptions 0.2 条/章。
- **根因（两层）**：
  1. `in_session` 旗标静默失效——S2 入会话分支从未触发（v13 的 47k/笔同为独立
     单发签名，该功能可能从未生效）。疑点：`_phase_flags` 的 flags 传递 /
     `same_domain` 判定 / session 传递，需 debug 定案。**这是 V1-③"静默失效"
     类事故的第二次发生。**
  2. **思考溢出**：思考/输出比 = 100%（推理 28.6k/章 = 全部输出），effort=low
     实证无效。思考到顶 → 无可见结论 → 解析失败 → 重试再想 5000 → 级联。
- **解决**：
  1. debug in_session 旗标链（离线复现 `_phase_flags` + `same_domain` 判定），
     修复后加**生效断言单测**（会话内清算 in 必须含头部尺寸）——防第三次静默；
  2. 清算预扫 `thinking: disabled`（对照检查任务；结论由程序复核在环：
     pattern_check/beat_check/引证验真）；雷章召回 B01-D01 实测不降才收货，
     降即回退；
  3. 重试/pro 升级入会话 + 失败轮 rollback（同前缀命中价重发，无上下文污染，
     单测钉 rollback 后上下文与首试一致）；
  4. max_tokens 维持 5000（思考关后 out=结论 JSON ~1-2k，不再触顶）。
- **预期**：5.8 → ~1.2 笔/章，37.9k → **8-12k/章**。
- **质量不变量**：结论由程序复核在环 + 雷章门；violations 基线 0.3 条/章说明
  溢出思考是无效复查。

### A2 卷界重冻结税（头部按卷拼接的结构缺陷，~8-10k/章摊派 + 塌陷）□

- **现象**：卷界章（14/15/26/27）X = 224.6k/章 vs 稳态 98.7k——每卷 2 章塌陷，
  单章综合被打回 70-80%。
- **根因**：卷界时①设定底册/世界书快照重冻结（世界书卷内反哺使字节必变）→
  头部从变化点起全灭；②语料快照换新文件 → 全部首贴 miss。
- **解决（S2 书级单一追加流）**：
  - 书级冻结**只收真静态**：题材定位底册 + 卷纲 + 语料流（已锁章节全文/全部
    细纲/章节摘要链，write-once 追加式）；
  - **世界书不入书级头**（动态文件，防双写歧义）——保持开幕轮/审校/清算近场
    单副本；
  - 迁移：已有书首次切换装配一次书级流（一次性 ~150k miss），此后卷界零事件。
- **验证门**：快照字节=源文件逐字拼接单测；追加前缀性质单测；塌陷指标=0。
- **预期**：卷界税归零（每卷省 ~25 万 tok），H 每章严格单调。
- **质量不变量**：章节全文/细纲/摘要逐字入头零损失；世界书近场单副本（消除
  而非引入双写歧义）。

### A3 路由冷击（16.9k/章，外部项但可控期望）□

- **现象**：100 次冷击事件、实付 miss 506k tok/30 章。分布：audit 143k（实为
  A1 的独立单发重付）、trim 108.8k、deslop 107.6k、prose 103.3k、enrich 43.6k。
  集中于 prose→trim/deslop/review 紧邻转换（prose 刚写完，下一笔大请求落冷
  节点全头重付，ch27 trim 单笔 miss 108,754）。
- **根因**：服务商多节点缓存同步差（E0 已证非写延迟、非 TTL）。
- **解决**：服务商层不可控——**结构抓手是减少"大请求次数"**（=减少抽奖）：
  A6 快速道修复（-2 笔/章）、S5 摘要合并（-1 次/章）、A4 会话化（enrich 大
  请求变小）。45s 写延迟窗对冷击无效（v15 实证），不再加码。
- **验证门**：lottery_scan 实付 miss ≤10k/章；超出标注外部因素。

### A4 enrich 全部独立单发（新发现，~2.9k/章）□

- **现象**：12 笔 enrich in 中位 9,022 tok（独立单发签名）——trim/deslop/review
  都骑会话（in 60-136k），**唯独 enrich 不骑**。
- **根因**：待代码追查（enrich_tail 分支的会话传递或 _use_session 判定）。
- **解决**：与 A1 同批 debug 修复 + 生效断言单测。
- **预期**：enrich X 3.3k → ~1.5k/章。

### A5 世界书/正则块多相位重复注入（4-6k/章）□

- **现象**：worldbook_block 在 PROSE 开幕轮/REVIEW 轮/TRACKING 轮各携带一份
  近场拷贝（~1.9k tok/份），同一章内同内容在 3-4 个字节位置各付一次 miss；
  regex_block 同理 ×2。
- **解决**：世界书以「卷首快照 + 卷内追加登记」**追加进书级语料流**（append-only
  无双写、无陈旧——每卷追加上一卷增量），PROSE 开幕轮保留近场基准，REVIEW/
  TRACKING 近场改引用行。
- **验证门**：盲评 D 维不降（审校近场对表便利性）——这是本项唯一质量风险。
- **预期**：-4~6k miss/章。

### A6 审校快速道失效（24/24 章满投 3 票，≈2 次大请求/章）□

- **现象**：`review_pass_fast` 判据（首票 PASS/PASS_WITH_NOTES 且零 blocking）
  应触发而未触发——首票日志明确 "PASS_WITH_NOTES（fail=0）" 仍投满 3 票。
- **根因**：待查（疑点：CISC 置信票干扰判据取值 / blocking 在 marginal 场景
  非空的代码路径）。
- **解决**：debug 判据链；修复后每章 -2 次大请求（同时减少 2 次冷击抽奖）。
- **验证门**：审校裁决一致性（快速道章 vs 满票章抽检盲评）。

### A7 <10s 紧邻调用 83 次（写延迟窗口缺口，小额）□

- **现象**：章内相邻调用间隔 <10s 共 83 次（review→review 副本 1s、
  tracking→摘要 2s 等）。
- **解决**：已有 pace_boundaries 框架补边界项（如 summary 前小窗 8s）；
  优先级最低，随 S5 一并处理。

### A8 prose 开幕轮密度压缩（5-8k/章）□

- **现象**：prose miss/章 18.9k（开幕轮八节共享段 + 世界书/正则近场块首贴）。
- **解决**：corpus_mode 深化（已被语料库覆盖的成分继续引用行化）；角色状态/
  时间线等动态节保留但压缩格式密度。
- **验证门**：盲评 D2/D4 前置（开幕材料密度影响写作质量）——第二批次执行。

### A9 字数超标链（trim 4.9k/章 + 质量副作用）□

- **现象**：trim 0.23 笔/章、每笔独立大 miss；ch25 首稿 3000 字 vs 目标 2000。
- **解决**：细纲预算行质量进预生成校验；prose 首稿超标即时自收束强化；
  trim ≥2 次的章打标观测。
- **预期**：trim 触发率减半，9.7k → ~4k/章。

### A10 tracking 上下文字段全量重写（3.4k out/章）◐

- **现象**：TRACKING_PATCH 的 context 字段每章全量重写写作上下文（3.4k out）。
- **解决**：delta 化（只追加本章变化行）——W 轮实测该字段 633 han/章"不值钱"
  的旧结论在 30 实体书上已过时，重新评估。
- **验证门**：上下文文件连续性抽检 + 盲评。

### A11 调用数合并（每减一次 = 少一次冷击抽奖，期望 3-5k/次）□

### A12 卷界章的细纲双份（已评估，作为不作为）✗

## 5.1 S 级修正一：A1 根因定案——outline_pregen 整文件覆盖 state，抹掉了 genre_preset

- 证据链：①两跑终态 pipeline_state.json 均无 genre_preset 键（bench_base 有
  urban_destiny）；②cost_bench.py 的 pregen 块 `st.save_state(proj, {"stage": ...})`
  **整文件覆盖**，抹掉 424 行刚写入的 genre_preset；③canon_audit._phase_flags
  实时读 state 的 genre_preset → 读到空 → stage_params("") = {} → in_session
  缺失 → S2 分支静默跳过（该路径零日志，与两份 console 取证吻合）；
  ④max_tokens=5000 仍生效是因为 router 保留了构造时刻的参数档——**两条通道
  分叉**，恰好解释"5000 生效而 in_session 失效"的表面矛盾。
- 放大器（新登记缺陷）：llm/client.py 空内容降级重发用 `thinking=""`——空串在
  _build_payload 里导致 thinking 键**整体不下发**（模型默认思考开），降级重发
  是空操作。每章 6 笔 = 2 次循环 × 3 次 HTTP（空流→降级→retry 2/2），每笔
  reasoning 贴 5000 顶。
- **P1 工单改写（定修，非 debug）**：
  1. pregen 块改 load→mutate→save（不整文件覆盖）；
  2. 降级重发显式 `thinking={"type":"disabled"}`（单测钉 payload 字节）；
  3. 生效断言单测钉**双通道一致性**：`_phase_flags` 与 `router.stage_params`
     对 canon_audit 相位必须同源（同断言一并钉住内置表 8192 与预设 5000 的
     合流结果）；
  4. "从未生效"表述逐时代复核（v13 无抹除行但同为单发签名，断言须落产品代码）。
- 附带质量事故登记（新 C 项）：**v15_tail ch25-30 六章清算全部失败**（空内容
  贴顶，36 笔仅 1 笔可解析）→ 六章"未对账+台账断档"。P5 开跑前补跑清算或
  明示接受带伤种子。"violations 0.3 条/章"基线混入失败章，不得单独作为
  "溢出思考无价值"论据。

## 5.2 S 级修正二：A6 是误诊——bench 里 review_pass_fast 根本没开

- _mk_cfg 显式 `review_pass_fast: bool(fast_path)`（--fast-path 缺省 False），
  v15_stack gates 未覆盖 → 全程关闭；两份 console "快速道"零出现、全部 3 票
  满投即关断预期行为。现行判据链对该场景逻辑正确（compact 票 fail=0 →
  blocking=[] → _fast 应为 True）；CISC 置信票不进 blocking，无干扰。
- **处置改写**：A6 销号 = v16 stack gates 显式 `"review_pass_fast": true` +
  零成本确定性单测（喂 PASS_WITH_NOTES/fail=0 票断言 _fast 为真）。删除
  "CISC 干扰"误导线索。P5 机制判据"快速道触发率 ≥50%"首次真正可测。
- 收益口径修正：快速道的收益是**减少调用数与冷击抽奖**（副本票 hit 98.3%、
  单笔 miss 仅 138-425 tok），不是 miss 节省——账本行改口径。
