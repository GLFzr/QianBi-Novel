# 成本实验战役报告 v1（v0.18.5 后深度优化轮）

> 方法：同源种子书克隆 + 变量数据化预设（不改代码）+ 固定草稿确定性对比（`--seed-drafts`）
> + 全流程 3 章真机测量（off-peak，deepseek-v4-flash/pro 官方）。
> 台子：`scripts/cost_bench.py`；产物：`tests_output/bench/*.metrics.json` 与 `*.chapters/`。

## 一、结论速览

| 实验 | 变量 | 成本（3章） | 质量信号 | 裁决 |
|---|---|---|---|---|
| E1 | 基线 | ¥0.647 | 参照 | — |
| E2 | prose=low | ¥0.679（**+4.9%**） | 正文推理 11.6k→1.9k ✓，但审校修复链 3→6 笔；清算硬伤 3→7 | **否决**：正文变弱，下游修复吃掉全部节省 |
| E3 | review=low + PASS快速道 | ¥0.765（噪声主导） | 快速道触发 1 次（1 票放行）机制 ✓；审校检出 REJECT-HARD 仍工作 | 快速道**保留为可选开关**（默认关）；review=low 存疑 |
| E4 | audit medium+12288 | 中止 | medium 推理仍撞 12288 上限→截断重试 | 上限需 ≥16384 |
| E5 | audit=low（flash） | 清算成本 **-84%** | 检出集合**改变而非缩水**：14→8 项、硬伤 9→5，两档各有独有真实发现；引文全部命中原文 | **否决默认 adoption**（见下"用户选项"） |
| E6 | audit=high（flash）+16k | flash 确定性**空流**（API 侧） | 无法完成→仍升 pro | 不可行（这就是升 pro 设计存在的原因） |

## 二、结构性发现（比单个实验更重要）

1. **清算（canon_audit）占章成本的 ~54%**：flash 首判在 high 档必然空流（API 侧对
   该提示词+flash+high 的确定性空响应，与预算无关），按 F1 设计升级 **V4-pro 严格档**
   （~16k 输出 tok/章，pro 输出价是 flash 的 3 倍 ≈ ¥0.18/章）。**这是质量卫兵的合理
   价格，不是浪费**：pro 的硬伤引文 100% 命中原文、跨章连续性主张具体可查；低/中档
   检出的是"另一批"违规（双方各有对方漏掉的真实发现），检出深度随思考档位单调上升。
2. **正文变弱是负优化**：prose 降档省下的推理钱，会被下游审校修复链加倍吃回去
   （E2：省 9k tok 正文推理 → 多花 24k tok 审校修复）。
3. **3 章样本的噪声地板 ±10-18%**（prose/审校链的随机波动）：小于 20% 的成本效应
   在这个样本规模下不可分辨——小杠杆不值得动。
4. **空流现象**：直连官方 API 的长流式约每章 1 次空内容（传输层），客户端"关思考
   降级重发"可恢复，代价是作废一次已计费的尝试。属网络现实，暂无低风险解法。
5. **输入侧已近最优**：混合命中 73-79%，hit 价为 miss 的 1/31；输入优化的边际收益
   已尽，输出侧（尤其思考档位）才是主战场——而输出侧的大头（audit/审校）恰恰是
   质量闸门本体。

## 三、给用户的可选档（不改变默认，预设一行即可）

轻量清算档（省钱 ~84% 清算成本，检出风格改变——适合预算敏感的作者，配合
审校六维仍能把关）：

```json
{ "stage_params": { "canon_audit": { "reasoning_effort": "low", "max_tokens": 16384 } } }
```

审校快速道（干净章免投副本票，`gates.review_pass_fast: true`）已内置为可选开关。

## 四、与 v0.18.5 已发布内容的关系

- 0.18.5 已含：outline=low、机械相位关思考、章会话、双层前缀、离峰挂机、reasoning 口径
  ——本轮实验**验证了这些默认值正处在该质量水平的成本最优点附近**；
- 本轮**未采纳**任何新的默认值变更（所有降档方案均在质量信号上被否决）；
- `review_pass_fast` 与轻量清算预设作为**用户可选档**存在，默认关闭。

## 五、第二波追加实验（人工审校模式 + 清算三档终测）

### 人工审校模式（v0.18.6 新特性，`gates.review_mode: manual`）

作者本人在定稿前的 G8 门里当审校：填阻断问题（每行一条）→ AI 按 REVIEW_FIX 修复 →
作者复验（循环至放行/回退）。审校 LLM 调用归零（自动模式审校约 5-15k 输出 tok/章 +
3 次调用墙钟），只保留修复调用（有问题才花）。设置面板「一致性审校」区有开关。
保留：字数预检提示进门文案、修复稿健全性守卫、回退=保留原稿、断点续跑兼容。

### 清算三档效果-成本对比（固定草稿、同 3 章输入，pro 价已计入）

| 档位 | 清算成本/3章 | 延迟/次 | 检出 | 硬伤 | 引文真实性 |
|---|---|---|---|---|---|
| **high+pro（默认）** | ~¥0.67 | 200-255s | 9 | 7 | 78% |
| **low+flash** | ~¥0.05（-93%） | ~30s | 8 | 5 | **88%** |
| **disabled+flash** | ~¥0.007（-99%） | 12s | 17 | 8 | **59%** |

- disabled 的检出量翻倍是**噪声**：抽查显示跨章连续性硬伤检测完全消失（第2章 0 硬伤
  vs pro 4 条已人工核实的真硬伤），2/4 条引文系编造，其余是"把细纲暗示当违规"的过度解读。
  **结论：关推理 = 负优化，不提供任何档位。**
- low 是唯一"效率可谈"的轻量档：成本 -93%、引文真实性反而最高（88%）、检出略少但真实。
  作为**用户可选档**（预算敏感的作者）保留，预设：
  `{"stage_params": {"canon_audit": {"reasoning_effort": "low", "max_tokens": 16384}}}`
- 默认维持 high+pro：清算的跨章连续性硬伤检测（pro 强项）需要真推理，这是质量卫兵的合理价格。

## 六、审校三档埋雷测试（v0.18.6 第二项档位变更，已切默认）

方法升级：不再比"检出集合"，而是**埋雷**——在第 2 章草稿人为植入 4 颗已知缺陷，
每颗落在 FINAL_REVIEW_PROMPT 六维的明文硬规则上（A 开章纯铺陈 / C 金手指对已发生
事实落墨生效 / D 幻影引用从未出场人物 / F"他不知道的是"禁用章尾），以植入标记的
召回率为标准答案；干净原章做假阳性对照；每档 2 票 + 全流程 3 章 9 票验证。

| 档位 | 埋雷召回 | 引文真实性 | 假阳性 | 单票输出 | 延迟 |
|---|---|---|---|---|---|
| high（原默认） | 3/4（稳定漏开章雷） | 9/10 | 0 | 5.2k tok | 82-215s |
| **low** | 2-3/4 不稳定 | 11/12 | **1 次灾难性**（干净章 REJECT-HARD 全维 fail、引文全空） | 1-4k tok | 10-39s |
| **disabled（新默认）** | **4/4 稳定** | **12/12** | 0 | 612 tok | **5.4s** |

- 与清算完全相反的结论，机制清晰：**审校=对照检查表任务**（六维 checklist + 提示词
  内锚定示例，模式匹配即可），推理非必需；**清算=跨章事实对账任务**（记住前章细节
  并比对），推理必需。任务性质决定档位，不能一概而论。
- 全流程验证（E10，3 章 × 3 票）：9 票零格式崩坏、零假阳性，verdict 分布正常
  （PASS/PASS_WITH_NOTES），阻塞检出与修复环交互正常；审校相位输出 15.6k → 5.5k
  tok、延迟 82s → 5.4s。三票制保留（独立采样兜底），总审校成本仍 **-65%**。
- **默认已切换**：`BUILTIN_PHASE_PARAMS["review"] = {"thinking": "disabled"}`。
  需要更强审校时预设一行覆盖：`{"stage_params": {"review": {"thinking": "enabled",
  "reasoning_effort": "high"}}}`。
- 局限声明：4 雷样本覆盖 A/C/D/F 四维，B（爽点闭环）与 E（人物声口）未埋雷；
  两维的 disabled 表现以全流程 verdict 与后续公测数据观察兜底。

## 七、E9 清算级联（v0.19 落地项，真机对照）

采纳调研报告（FrugalGPT/ESC 级联模式 + DeepSeek 官方 effort 路由口径）：
**flash+low 全文预扫 → 干净采信 / 有硬伤才升 pro 只复核 flagged 项**（pro 输入=清单+定位
片段+邻章结尾，输出=紧凑裁决，双缩水）；预扫失败/退化仍走 pro 全量兜底（F1 质量上限保留）。
同轮落地：AUDIT_PROMPT schema 瘦身（why≤40 字、紧凑 JSON、推理进思考通道——官方确认
思考与输出同价，瘦身省的是总量）；审校重试的换温扰动改为措辞扰动（thinking 模式
temperature 静默失效）；pro 复检显式传思考档（不再依赖模型默认值）。

E9 对照（同 3 章固定草稿，E5b pro 全量为基线）：

| 项 | pro 全量（基线） | 级联（E9b） |
|---|---|---|
| 调用形态 | 3 × pro 全文 | flash 预扫 ×3 + pro 复核 ×2（第 1 章预扫干净零 pro） |
| 输出 tok | 47.3k（pro 价） | flash 14.2k + pro 3.8k |
| 清算成本（相位级） | ~¥0.675 | **~¥0.122（-82%）** |
| 清算成本（跑级，含其他相位噪声） | ¥0.879 | ¥0.281（-68%） |
| 质量守恒 | — | pro 终审确认 flagged + new_items 补漏权限；预扫引文真实性 88% |

叠加 schema 瘦身：预扫输出 8.3/8.8/6.0k → 4.2/5.6/4.3k（-45%），`_degenerate` 退化率同降。
review_pass_fast 默认开（ESC/AdaptiveConsistency 动态投票，干净章 3 票→1 票）。

口径注记：E1-E4 跑在实验台「全 pro」事故配置下（bench 脚本连接拼接 bug，模型分布
pro×24/28 如实记录于成本台账），其绝对成本不代表 0.18.5 默认配置；E5b 起修复。
全部跑次的逐行分价重算见 [成本台账](成本台账.md)。
