## 二、驱动层缺陷（1 项，一测报告勘误的源头）

**一测第4章"扩写悬挂"的真凶不是网关**：`long_run` 驱动的熔断自动处置用 `QTimer.singleShot(1000, orch.resume)`，而 `sig_auto_paused` 的发射线程（管线线程）无事件循环——**定时器永不触发**，管线在熔断后下一个 `checkpoint` 卡死（py-spy 定桩：线程停在 `checkpoint → _resume_evt.wait`）。一测 §3.2 已按此勘误。二测改为直接调 `orch.resume()`（threading.Event 线程安全），同位置**秒过**。

## 八、结论

**换上可用的通道后，0.23.0 的全部机制在 1.5 小时内跑完了预注册全流程，5 章全自动全部完成，总分 90% 达标**。二测的真正价值在三处：

1. **两条压舱守卫从死代码变成活的**（压缩过度删减/去味长度骤减），且都在实弹中拦下了真实毁稿——弱模型恰恰是护栏最好的试金石；
2. **一测的错误归因被纠正**（第4章主因是驱动 resume 定时器 bug 而非网关墙），测试方法论上 py-spy 定桩 > 日志推断；
3. **遗留清单明确**：字数双带对会话轮巨上下文模型的收敛（ch6 过冲/压缩过冲）、supervisor 报告输出契约的模型遵循度（可在比对 prompt 侧加「结论行」强约束）、qwen 写章偏短属模型文风。
