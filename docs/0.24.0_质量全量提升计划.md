# 0.24.0 质量全量提升计划（预注册版）

- **输入**：三轮实测（一测结构 72.5% / 二测结构 90% / 三测质量 4/7）+ 环节归因取证（本文 §一）+ 两份外部解法研究（`_scratch/quality_plan/research_harness.md` 405 行、`research_fiction.md` 304 行）。
- **纪律**：本计划为预注册——每张卡写明因果链（为什么改了**必然**动哪个指标）与验收判据；测后不改判据。验收协议统一用 `tests/quality_suite.py`（五层，盲评协议按 LitBench 升级为位置置换+长度配平）。
- **总目标**：自动章盲评均分 **4.6 → ≥6.5**，AI 味读感 **2.7-3.4 → ≥5.0**，one-shot 与管线差距 **2.5 分 → ≤0.5 分**。结构分（90%）不回退。

### 1.2 根因树（五个根因，两个 P0）

**P0-1【写手环节】卷会话逐字历史无界累积 → 注意力稀释 + 风格污染。**
环节定位：`stages._mc_assemble/_mc_draft` 骑卷会话（VolumeSession）写正文，栈内是逐字历史（前章全文+历次改写轮）。E1/E2/E4 是它的时间序列证据；E3 是它的对照实验证据（同模型同题，唯一变量=上下文，差 2.5 分）。外部实证：微软《LLMs Get Lost in Multi-Turn Conversation》（arXiv:2505.06120，ICLR 2026 杰出论文）多轮化平均最高 -39%；Lost in the Middle 的 U 型曲线——首尾被利用、中部暴跌（我们 170k 栈里大部分正文躺在中部）。**这不是玄学，是把窗口 90% 塞历史后留给"写好这一章"的注意力所剩无几的直接后果。**
讽刺点（E8）：解药早就在药箱里——接力压缩 T2 实测 -93.8%，但按成本标定 800k 阈值+默认关，质量在 100-180k 区间崩塌时它全程旁观。

**P0-2【改写环节】写后处理链结构性破坏（扩写堆料 / 压缩过冲 / 去味毁稿）。**
环节定位：字数闸门（`_mc_word_gate` 的 enrich/trim）+ 去味（`_mc_deslop`）。三个子病：① **形态错误**——"整章字数不足→自动扩写"是行业不存在的形态（Sudowrite/NovelCrafter/游蜂全部是段落级选中重写，NovelCrafter 干脆用 Scene Beats 在生成侧预防），整章重写式扩写的自然产物就是复读堆料（E5 的 0.44 复现率）；② **无净增益校验**——采纳判据只有长度与非空（守卫是"不比原来差多少"而非"比原来好"），ICLR 2024《LLMs Cannot Self-Correct Reasoning Yet》（arXiv:2310.01798）证明无外部信号的自我改写倾向变差，Re3 消融显示孤立写后修补无收益，FlawedFictions 实测改写任务制造连续性错误 +278%；③ **缝合怪**——ch4 30 发调用后终稿=草案+部分改写的拼接（E5）。

**P1-3【起草环节】生成侧零防味。**
环节定位：`_mc_draft` 的 prompt 装配。陈词/句式癖的词表早就在 deslop_metrics 里（M6/M9），但**只进读数不进规则、不进 prompt**；没有文风锚（每次生成不附本书已定稿范文）；句长方差 0.22× 无任何杠杆（E6）。外部五源收敛（chinese-novelist-skill/ainovel/Sudowrite/NovelAI/POLARIS 实证）：文风 few-shot 锚 + 全书统计镜像回注是生成侧防味的标准件。

**P1-4【装配与细纲环节】承接与开篇没有工程回路。**
环节定位：装配无「上一章结尾+应答义务」块；细纲合同的 CBN/CEN（承接/章末节点对）字段存在但共写细纲缺填 8-9 字段仅 fail 候选不阻断，且**无相邻章对齐校验**；钩子账本有数据无回路（不驱动下章换型）；开篇无独立相位（整章一次生成，前 300 字承担冷启动损耗，读者恰在前 300 字决定去留）（E7）。

**P2-5【记账环节（成本放大器）】记账相位共享同一膨胀栈。**
环节定位：`_update_tracking/canon_audit/chapter_summary` 骑卷会话，ch7 记账单发 179k 入 / 473 tok 出（E2）——读 179k 写 473，纯浪费且同受劣化之害。

### 1.3 因果总链（一句话版）

> 逐字历史把写手窗口吃掉 90%（P0-1），使草稿先天不足；字数不足又触发行业不存在形态的整章扩写（P0-2），堆料毁稿后靠守卫反复拒收重试烧出缝合怪；全程没有文风锚与防味约束（P1-3），也没有承接/开篇工程（P1-4）——四层叠加，自动章从 5.5 跌到 3.8，而 one-shot 用 5k 精装上下文拿 7.9 分，证明**模型不是瓶颈，管线才是**。

## 二、外部解法映射（两份研究的合成结论）

| 我们的根因 | 外部对症解法（证据级） | 报告出处 |
|---|---|---|
| P0-1 长会话劣化 | ①上下文分层重组：两端=指令+近场（上一章结尾/文风锚/细纲），中部=账本快照（Lost in the Middle [实证]）；②接力压缩压中部保首尾（StoryWriter [实证]）；③Sudowrite 全文回溯在 ~5 万词后崩——**长篇不能用全文回溯**[产品]；④装配式交接块替换逐字历史（ainovel 二级压缩 [产品]；FlawedFictions 警告别用 LLM 摘要压缩 [实证]——我们的交接块恰好是零 LLM 装配式，已合规） | fiction §6 / harness F1 |
| P0-2 改写破坏 | ①扩写=段落级选中重写+"情节不变"约束（Sudowrite Expand [产品]）；②改写卡片化：锚点吸附+逐句比对防搬运+「返工→剔除→留痕」三段处置+幅度封顶（游蜂 [产品]）；③信息项保留清单：改前登记/改后对照在场性（qu-ai-wei [产品]）——我们有事实账本，原料现成；④轮次升压制（DOC [实证]）；⑤**反证**：Agents' Room 分块生成 trigram 复现 44-47 vs 端到端 28——fresh-context/分块必须与重复闸同装 | fiction §1 / harness F2 |
| P1-3 AI 味 | ①文风基准四件套+第 1 章回填校准段+「动笔前最后读入=正文语态」末位纪律（五源收敛 [产品×4+实证]）；②全书统计镜像回注（"本章主动压低 top3 高频项"，ainovel [产品]）；③起草期防味优于写后去味（webnovel-writer issue #134 同结论）；④段落 rerank 标注为实验项（无实证） | fiction §4 / harness F3 |
| P1-4 承接/开篇 | ①previous_tail 500-800 字恒注入（五个系统不约而同 [产品×5]）；②CBN/CEN 纲层字段+相邻章 L0 对齐+HARD-002 应答判据（webnovel-writer [产品-开源]）；③成品对偶检测（章首 vs 上章钩子，游蜂 [产品]）；④hook_history 统计→连续同型强制换型（ainovel [产品]）；⑤章首 best-of-N 择优（v7 规格 [产品-开源]+Re3 候选段 [实证]+LitBench 选优可靠性 [实证]）；⑥字数预算进细纲拍段（AgentWrite/Scene Beats 思想）从源头免扩写 | fiction §2/§3 / harness F5 |
| P2-5 记账膨胀 | 记账相位独立有界装配（不需要卷会话，需要章文本+账本）——无外部反证，纯工程 | 取证 E2 |

**编辑位置的产业共识**（fiction §5.1 光谱表）：没有任何成功系统做"改写前全文 gate"，也没有系统让编辑直接改稿；收敛形态=**生成前合同（细纲合同已有）+ 写后独立审（已有）+ 按问题的定点改写授权（缺，即 P0-2 的卡片化）**。

## 三、提升计划（五个波次，18 张卡）

### W1 上下文治理（治 P0-1 + P2-5）——「让管线像 one-shot 那样写作」

| 卡 | 内容 | 因果链（为什么必然提升） | 验收 |
|---|---|---|---|
| Q1-a 压缩质量标定 | `writing.compaction` 默认开；阈值从 800k 改为 `min(质量阈, 成本阈)`，质量阈=**模型窗口×25%**（192k 窗→48k tok）按窗口自适应 | E8 已证 -93.8% 输入缩减；E1/E3 证 5k 级上下文出 7.9 分。把写手上下文从 157k 压回 ~50k 内，直接退出劣化区（E4 曲线的前半段） | prose 单发入 ≤60k；盲评自动章 ≥6.0 |
| Q1-b 写手上下文配方化（A/B 定架构） | 三臂对照实验（同书同细纲各 5 章）：臂1=现状；臂2=Q1-a 压缩；臂3=**fresh 装配式写章**（正文相位脱离卷会话：顶部=纪律+本章合同，中部=账本快照（每项条数×字符×开关三件套），底部=文风锚→上一章结尾 500-800 字→本章细纲；同章改写相位可共享章内有界会话） | E3 就是臂3 的先导实验（7.9 分）；Lost in the Middle 的位置纪律+五系统 previous_tail 共识给装配顺序；Sudowrite 教训给中部预算上限。**以盲评定胜负，输的臂退役** | 三臂盲评报告；胜臂差距 ≥0.5 分 |
| Q1-c 记账相位独立装配 | tracking/canon_audit/summary 不再骑卷会话；输入=章文本+相关账本+全局摘要（有界） | E2：179k 入换 473 tok 出，纯成本无收益；脱离后记账质量同样受益 | 记账单发入 ≤30k；账本产物 diff 一致 |
| Q1-d 上下文可观测面板 | 装配预览面板（已有）扩展为「每注入项字节数+占比」的写前体检（NovelAI Context Viewer 同款） | 「AI 忘设定先查是没收到还是没听」；给 Q1-b 调参闭环 | 面板显示与实发 prompt 逐字节一致 |

## 五、风险与不做什么

1. **不做** LLM 摘要式压缩（FlawedFictions +50% 连续性错误——我们的装配式交接块恰好避开）；
2. **不做** 全文回溯式长上下文（Sudowrite 在 ~5 万词后设定栏被挤崩的教训）；
3. fresh 装配/分块生成**必须**与重复闸同装（Agents' Room 反证：分块 trigram 复现 44-47 高于端到端 28——我们的 0.44 复现正是同病）；
4. 段落 rerank 仅作实验项（无实证），不进主线；
5. 番茄/起点检测特征传闻级来源只取方向（平台测文本特征），不做检测对抗——延续既有红线。
