## 1. 问题的统一：一个病根，两个症状

T3 的 53 章长跑把成本与质量两条曲线指向了**同一个病根**：

- **成本**：栈每章 +40k 无界增长 → 卷内 5.9×（¥0.095→¥0.564/章）、卷二末单笔 862k tok；
  输入的 97% 是命中价读量——**钱花在反复读整个历史上**（E1）。
- **质量**：前 20 章平（+0.0145/章），之后转负（-0.042/章）；掉分集中 D2 爽点闭环 -1.17、
  D4 一致性 -0.42（E1）。衰减是"跨卷累积+上下文膨胀"的函数，不是章数的单调函数。
- **文献裁定（L）**：这不是巧合。长上下文有效性衰减有大量实证
  （Lost in the Middle、RULER、NoLiMa——B 路引文），业界长篇系统全部以
  "有界上下文+外部状态"为设计第一原则（A 路：RecurrentGPT/DOC/DOME/MemGPT/2025KG 系全部 O(1) 上下文）。
  **无界膨胀的栈同时是钱和质量的敌人——修它就是同时治两个症状。**

## 2. 文献收敛点：逐章写作的正确上下文构造（A 路，L）

五个流派（滚动记忆 / 递归大纲 / 时序 KG / 分页记忆 / 蒸馏长期记忆）全部收敛到三件套：

1. **近程逐字窗口**：只保留最近 1-2 个叙事单元的原文（RecurrentGPT 最近一段+计划；
   2025 KG 论文只留最近两份大纲）——我们的"栈内最近章历史"已经是这个形态 ✅；
2. **蒸馏后的结构化状态**：实体/时间线/伏笔的紧凑状态库，**增量更新**而非全文重述；
3. **按需检索子集**：写第 N 章时只注入本章相关实体的状态子集（SillyTavern World Info
   在海量长对话中验证过 keyword 触发+token 预算模式；GraphRAG/HippoRAG 是其学术形态）。

**关键反证（L）**：没有任何一个成功系统采用"整卷历史无限追加"。
我们的栈架构保留（缓存友好），但栈的**内容增长必须改为近常数**。

## 3. 缓存语义下的约束（官方文档，L + 我方 E1）

DeepSeek 官方：缓存以"完整前缀单元"为命中单位；单元在请求边界/公共前缀/超长输入固定
间隔三时机持久化，**best-effort 不保证**；"超长输入按固定 token 间隔切分"——巨型栈的
单元粒度粗、时滞面大（章界 32k 抖动的官方定性，结案）；缓存数小时~数天不用即清。

**设计约束（从语义直接推出）**：
- append-only 轮次结构**保留**（官方多轮示例即此模式）；
- **每章请求规模有界** ⇒ 单元持久化及时、粒度细 ⇒ 章界抖动面缩小；
- 老历史**出栈**后由外部状态承载——不靠栈内检索。

## 4. 增量状态与压缩：Anthropic memory tool 是工业先例（C 路，L）

- **Anthropic memory tool**：str_replace 式增量更新 + context editing（旧轮工具结果清除），
  官方 100 轮 agent 实测**省 84% 输入 token**——方案 (a)+(d) 的直接工业验证。
- **可靠性红线（aider 实测）**：弱模型做 diff 不可靠 ⇒ 必须 schema 约束解码 +
  apply 失败整节重写回退 + 每 N 章全量对账防漂移。
- **LLMLingua-2 排除**：英文会议数据蒸馏、抽取式压缩把叙事压成电报体——不适合中文叙事。
- **RAPTOR 分层折叠**：>15 章的老章折叠为卷摘要；**伏笔台账永不折叠**
  （T2 的教训：压缩交接块丢热缓存掉记忆）。

### 算术估算（C 路，E2；基准=中值拆分 ①追踪5k ②快照6.7k ③审校指令4.6k ④清算重复3k + 必要追加20.7k ≈ 40k/章）

| 方案 | 每章增量 | 状态风险 |
|---|---|---|
| (a) 仅台账 diff | ≈36k | 中（需 schema+回退） |
| (a+d) diff+实体子集注入+③模板化+④修复 | **≈21-24k（必要值下限）** | 低-中 |
| (a+d)+context editing+正文落盘引用 | **≈5-8k（近常数）** | 需验证 |

## 5. 一致性校验（D 路，L）——L0 确定性预检层的设计依据

### 5.1 理论锚点（解释我们审校召回 0/2 的根因）

- **Huang et al.（ICLR 2024, 2310.01798）：无外部反馈的内在自校正会退化**；
- **CRITIC（2305.11738）：确定性/工具性外部反馈才有效**（GSM8K 72.5→78.2 等）；
- CoVe（+19pp FactScore）/Reflexion（HumanEval 80.1→91.0）量级佐证：外部确定性
  反馈带来 +8~22 点；Reflexion 同时证明**弱模型无增益**。
⇒ 大模型审校漏掉钟点/伤情/爽点穿帮，缺的是**确定性证据**不是智力。L0 的定位 =
**审校前置的证据定位器**（违例+证据句注入审校 prompt，CRITIC 式），不是独立裁决者。
- 先例：**DOC（ACL 2023, 2212.10077）细纲→beat 清单→控制器强制对齐**：人评情节
  连贯 +22.5%、大纲贴合 +28.2%——"承诺清单→逐项检查"的直接文献验证。

### 5.2 三个校验目标的最小可行组合（全 CPU、零 API 增量，每章 5-15s）

| 目标 | 方案 | 预期召回 | 延迟 |
|---|---|---|---|
| 钟点 | regex+Duckling-ZH/HeidelTime 归一化 → 与台账精确 diff | **高（近确定性）** | <0.5s |
| 伤情/状态 | Qwen2.5-0.5B(GGUF) 抽"实体-状态-时段"JSON → 增量台账 → 规则查漂移/无源引用 | 中-高 | 数秒 |
| 爽点 | 细纲 beat 承诺清单 + bge-small-zh-v1.5 检索兑现句 + 推迟语词典 → 逐 beat 判兑现/推迟/缺失 | 中-高 | <1s |

**诚实边界**：中文无现成叙事事实核查 checkpoint；纯 NLI 有 ~81 AUC 上限
（TRUE 基准），只能做兜底二次确认，不能独担；文献无"网文穿帮"直接召回数据，
上述预期由"钟点归一化近确定性 + DOC/CRITIC/Reflexion 增益区间"外推，落地后实测校准。

## 6. 长上下文衰减量化与缓存理论（B 路，L）

### 6.1 衰减数据点（生成任务 vs 检索任务要分开看）

| 证据 | 长度 | 衰减 | 来源 |
|---|---|---|---|
| NoLiMa（联想推理） | 32K | 12 模型中 11 个跌破短文基线 50%；GPT-4o 99.3%→69.7% | arxiv 2502.05167 |
| RULER（声称 vs 有效长度） | 32-128K | 多数模型有效长度 ≤64K；仅 Gemini-1.5-Pro >128K | arxiv 2404.06654 |
| Context Rot（18 模型至 1M） | 100K-1M | 简单任务也非均匀退化；相关信息增多即伤害 | trychroma.com |
| LongMemEval | ~113K | **focused(~300 tok) 全模型显著优于全量提示** | 同上 |
| 多轮分片对话 | 会话级 | 平均 **-39% 且不可自恢复** | arxiv 2505.06120 |
| Lost in the Middle | 位置 | 相关信息在中段性能降 >20%（U 型） | arxiv 2307.03172 |

**裁定**：检索/复述任务 1M 仍稳；**"需全局一致性+联想整合"的生成任务在 32-128K 普遍腰斩**
——网文写作（跨章伏笔/人设/时间线）恰属此类。我方 20 章后 -0.042/章与文献同源。
多轮分片的"不可自恢复"同时**否定**"继续在长栈里修"的路线。

### 6.2 缓存理论（服务端论文 → API 消费者的推论）

- CacheBlend：非前缀块复用需**~15% 选择性重算**——服务端特权，API 拿不到
  ⇒ **实体状态注入必须放请求尾部**（新消息区），中部插入其后 KV 全价重读；
- PromptCache/CacheGen/Mooncake/AttentionStore 同向：产业界对"长会话读放大"的答案
  都在服务端；AttentionStore 甚至按对话窗口**主动淘汰**老 KV——服务端都不假设无限保留；
- **API 消费者唯一可用的杠杆 = 布局（静态前置）+ 有界化**。

### 6.3 成本算术（E2，与 E1 互证）

命中率恒定时单章读成本 = 栈长 × 混合单价（97% 命中 ≈ $0.0134/M）——缓存只降斜率
（1/16.4）**不封顶**，成本仍线性于栈长 ⇒ 100k→862k 即 ×8.6，全程对章节数**二次增长**
（与 T3 实测 5.9× 卷内膨胀同构）。有界 100-150k：每章读成本封顶（卷末的 1/6-1/8），
重置一次性重预热 ≈$0.033 可忽略；TTL 断档期望损失同步压到 1/6。peak=off-peak 2×，
hit/miss 价差 31×。

### 6.4 三家官方最佳实践共识

静态前置/可变后置、append-only 追加、（Anthropic）上下文是"有限资源、边际收益递减、
attention budget 会被耗尽"；Anthropic 官方长会话方案 = **compaction + 结构化外部记忆
（memory tool/NOTES.md）+ 按需检索**——Claude Code 自身在长会话压缩重启。
无任何一家支持"无界增长无害"。

## 7. 由此升级的实施蓝图（V 轮 = U 轮的文献化重构）

**架构主张（一句话）**：栈保留 append-only 骨架，但每章**必要追加之外的一切**
（追踪输出、快照、指令体、重复前缀）改为「结构化状态库 + 增量 diff + 本章子集注入」，
使单章上下文从 +40k 增长收敛到近常数；老章按 RAPTOR 式折叠；伏笔台账独立永不折叠。

| 步骤 | 内容 | 理论预期（E2，落地后实测校准） | 来源 |
|---|---|---|---|
| V1 | ④清算前缀修复 + ③审校指令模板化（入冻结前缀） | -7.6k/章 | T 报告 §3.5 |
| V2 | ①台账 diff 化（schema 约束 + apply 校验 + 10 章对账） | 追踪输出 5k→1k；防 8192 截顶 | Anthropic 84%；aider |
| V3 | ②快照删除 → 实体子集注入（keyword/实体召回）——**注入一律放请求尾部新消息区**（CacheBlend：中部插入其后 KV 全价重读，API 无非前缀复用） | -6.7k→-1.5k；D4 材料反而更准 | World Info/DOME + B 路 |
| V4 | 有界窗口（100-150k 封顶）：老章 RAPTOR 折叠 + 伏笔台账独立；窗口重置=换代文件（成本 ≈$0.033/次一次性重预热，可忽略；卷界税由「按章数定界的有界重置」替代——卷长 13/25 不等，不再按卷定界） | 栈体积 O(1)；章界单元粒度细、抖动面收窄；TTL 断档损失 ×1/6 | RAPTOR + B 路成本算术 |
| V5 | D4/D2 的 L0 确定性预检 + 承诺清单注入 | 文献同款（DOME 冲突分析器/KG 闭环） | A/D 路 |
| V6 | 20 章复测对表 T1：hit%、¥/章、D2/D4、栈斜率四项 | 全部应显著改善 | — |

**理论效果的诚实边界**：文献给出的是方向确定性（bounded-context 双优）与
量级区间（-84% 输入、O(1) 上下文），我方 E2 估算 21-24k/章偏保守（只算已证实件）；
5-8k 近常数需 V2-V4 全部落地后实测。缓存命中率预期随栈规模下降而**波动面收窄**
（单元粒度细），但 99% 的确定性来自"卷界不重栈"（V4 并入）而非压缩本身。
