# 共写软开局方案 v1（方案-only，未实现）

> **性质**：B-1「软开局」的产品方案文档。0.20.0 收口裁决（2026-09-25）：**只交方案，
> 不实现**；实现排期到 0.20.x 后续版本，且实现前须过一次真机窗口走查（见 §7）。
> 读者：下一轮实现代理与主控。本文不改任何代码，文中引用的代码路径均为现状核实。

## 1. 问题：共写默认档把「空白页」推给了最不会用的人

0.20.0 起**新书默认进共写档**（`app/config.py` → `writing.run_mode` 出厂 `"cw"`，
B-1 v4 用户裁决；仅作用新装/未表态项目，老用户盘上的 `"auto"` 原样保留——R17）。
共写档的第一屏是「创建项目 → 核心设定」阶段的空对话区：新人要对着一个不认识的
界面想出第一条消息（题材？平台？一句话点子？），这是台账尺 3
（新人能不能走通）点名的那类断点。

现有两条缓解都各有边界：

- **演示引导**（`app/ui/demo_director.py`，0.20.0 已落地）：书架空态「先看 5 分钟演示
  （无需 Key）」。它是**演示**——硬隔离（demoActive 时 `startPipeline` 直接拒绝、
  不碰任何 LLM 模块、演示书打 demo 标记），看完与动手之间仍隔着一道鸿沟。
- **题材预设**（`app/presets/` 10 套）：给的是提示词特化，不是「第一步该说什么」。

**软开局**补的就是中间这一段：默认共写档下，前 1-2 步由应用**代填示例并解释**，
让作者先「批改」再「接管」，而不是先「命题作文」。

## 2. 一句话定义

> 软开局 = 共写档新项目的前 1-2 个阶段里，应用替作者填入**带「示例」标记**的输入
> 并逐字段解释它在问什么；第一章正文写完后再交还作者评判/接管。全程真实流水线、
> 真实计费、随时可跳过，演示隔离纪律原样保留。

## 3. 交互流程

### 3.1 触发与退出

- **触发**：仅当 ①新建项目（或新装首书）、②该项目档位为共写档、③项目级
  「软开局」标记未消费。三个条件缺一不触发。
- **退出**（任一即终止且不再触发）：作者点「跳过示例」；作者手改了代填内容
  （改过即视为表态）；第一章交还评判完成；项目关闭。

### 3.2 步骤 1｜核心设定阶段：代填 + 解释

1. 对话区出现一张**示例卡片**（非模型输出，本地文案）：预填一组安全的示例立项
   ——题材（取作者新建书时选的预设）、平台、目标字数、一句话点子。卡片逐字段
   旁注「这一栏是在定什么 / 填坏了会怎样」（例：目标字数决定细纲批次与节奏预算）。
2. 卡片三个按钮：**「就用这个开写」**（示例值作为作者输入真实提交，进对话记录，
   带 `[示例]` 前缀）/ **「我来改」**（表单原地可编辑，改完提交；提交后软开局终止）/
   **「跳过，我自己说」**（清空输入，软开局终止）。
3. 提交后走正常共写链：设定 Agent 讨论 → 生成草稿 → 作者点「确定」定稿。
   **「确定」这一下永远是人点的**，软开局不代点。

### 3.3 步骤 2｜剧情总纲阶段：示范一次「讨论」

1. 草稿生成后，示例卡片第二次出现（也是最后一次）：给一条**可直接发送**的示例
   追问（例：「第二章的反派动机再落地一点，别只用台词交代」），旁注解释
   「讨论 ≠ 重来，你可以只对局部提要求」。
2. 作者可发送、可改写、可无视。发送后流程照常；此步之后软开局**全部退场**，
   界面与当前版本行为完全一致。

### 3.4 第一章完成后：交还评判/接管

第一章锁定落库时（共写正文阶段「确定」之后），弹出**交还卡片**，内容三块：

- **这一章是怎么长出来的**：哪些输入来自示例、哪些是 Agent 决策、哪些过道门/审校
  （数据源：章级配置快照 `正文/.annotations/第N.json`，已有机制，零新增埋点）；
- **三个出口**：**「继续共写」**（软开局收官，此后一切如常）/ **「我来改」**
  （编辑器打开本章，读改 Agent 揣摩手改意图的既有链路承接）/
  **「换个方向重来」**（归档本章——走既有「先归档再删除」纪律，回到核心设定阶段，
  软开局不再代填）。

## 4. 边界（红线，违反即打回）

1. **不静默改用户档位（R17）**：软开局不写 `writing.run_mode`、不把任何项目切到
   自动档或从自动档切走；只对「新装/未表态」的**新**项目生效；作者随时可在流水线
   面板改档，改了软开局即退场。回归判据：老 config（`run_mode:"auto"`）升级后
   仍为 `"auto"`，有单测钉死（现有 `_migrate_run_mode` 的 R17 支点用例延续）。
2. **不伪装成作者**：代填内容一律带 `[示例]` 标记进对话记录（`<书>/.dialogue/`，
   WP-27 既有落盘）；设定文档中被示例触发的段落不假装是作者原话——立项信息
   落盘时在「选题信息」标注示例来源。
3. **演示隔离不共用**：软开局是**真实流水线**（真实 Key、真实计费），不进
   `demo_director` 的硬隔离，也不反向借用演示内容包；两者唯一的交集是视觉风格
   （同一套卡片组件）。
4. **可跳过、可清空**：每个代填步骤都有跳过；跳过与交还卡片选择全部留痕
   （项目级标记 + 日志），不做「已经替你选好了」式的单向门。
5. **计费诚实**：步骤 1/2 的示例提交会真实调用模型（与作者手输同价）。触发前
   的示例卡片必须写明「点『就用这个开写』会开始调用模型产生费用」；未贴 Key 时
   只允许走到卡片为止，不发起调用。
6. **不新增遥测**：软开局的漏斗统计不做（B 类不可观测是 0.20.0 明确不做项）；
   效果验证走真机走查取证（§7），不走埋点。

## 5. 明确不做

- 不做「全自动替写三章再交还」——交还点定在第一章后（§3.4），代填只覆盖前 1-2 步
  输入，不覆盖「确定」与任何门决策。
- 不做示例内容云下发/远程配置——示例值本地写死在资源里，随版本走。
- 不对存量项目做软开局补投——只影响触发条件里的新项目。

## 6. 验收判据（实现时逐条可测）

1. **尺 3 走通**：全新 profile + 真 Key 真机走查——首启 → 贴 Key → 建书 →
   「就用这个开写」→ 六阶段 → 第一章落库 → 交还卡片三出口各走一次，全程不查文档
   能说出每步在干什么；逐屏留证（该走查归入发布前人工窗口清单）。
2. **R17 回归**：老 `config.json`（`run_mode:"auto"`）升级 + 新建书 → 档位仍 `"auto"`
   且无软开局卡片；`"cw"` 新书关掉软开局标记后行为与本版本逐字节一致（回归面=0）。
3. **示例可追溯**：对话 JSONL 中示例消息带 `[示例]` 标记；「跳过」路径下
   `.dialogue/` 无示例提交条目。
4. **计费前置**：无 Key 状态点「就用这个开写」→ 明确报「未配置连接」，零网络请求
   （探针断言）。
5. **护栏**：探针覆盖「三条件触发」「三种退出」「交还卡片三出口」；软开局终止后
   二次建书不再触发。
