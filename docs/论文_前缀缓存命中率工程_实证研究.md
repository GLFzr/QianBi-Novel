## 摘要

长篇大语言模型（LLM）小说生成面临一个双重困境：为维持跨章一致性而无限累积的会话
上下文，既使**成本随时-book 长度二次增长**（每章请求需要反复重读整个历史），又因超出
模型有效上下文而引发**质量衰减**。本文以一个生产级中文网文生成系统（千笔一文）为对象，
在字节级前缀缓存（DeepSeek Context Caching）的约束下，系统研究了"上下文命中率工程"：
通过 20-53 章真机长跑、19 个章节边界的统计分析、134 条消息的逐字节哈希比对、30 次
同串字节重放与跨渠道交叉校定，我们（1）建立了服务商前缀缓存的工程语义模型（缓存单元、
best-effort 持久化、超长输入粗粒度切分）；（2）提出并验证了一套命中率工程组合——
卷级会话栈、静态指令冻结、台账 JSON 补丁（事件日志 + 键控 upsert）、追加式请求
构造——将长篇混合命中率从 80.4% 提升至 94-96%（真分母口径），输出侧三鲸鱼
（追踪/扩写/摘要）分别削减 43%/81%/68%，每章总成本较上一迭代下降 29%；（3）给出质量侧的独立发现：上下文压缩
不是成本手段而是质量手段（盲评 +1.03 分），长篇生成任务在 32-128K 区间的衰减
与文献一致且"多轮分片不可自恢复"，以及正文思考长度的百倍方差是命中率达标后的
下一个成本杠杆。全部优化以**旗标缺省关闭、请求体逐字节不变**的
方式上线，配套 926 件回归测试与静态前缀锁。

**关键词**：前缀缓存；KV Cache；长篇生成；上下文工程；成本优化；LLM 应用

## 1. 引言

### 1.1 问题：一个病根，两个症状

交互式长篇生成系统的自然设计，是把每章生成所需的全部上下文（设定、前文、状态账本）
逐轮追加进一个持续会话。这在功能上是对的——**在经济学上是错的**：

1. **成本**：主流 LLM 提供商的前缀缓存（DeepSeek/Anthropic/OpenAI/Gemini 均已上线）
   把"重复输入"的价格降到未命中的 1/16 至 1/31，但这只改变斜率、**不改变成本随时
   间线性于栈长的事实**。栈从 100k 增长到 862k token，单章读成本即 ×8.6；对章节数
   累加即二次增长。我们的 53 章真机长跑实测：卷内单章成本 5.9 倍（¥0.095 → ¥0.564），
   第二卷（25 章不重置）末单笔请求 862,766 token——而其中 97.2% 是按命中价计费的
   "读量"（E1）。
2. **质量**：需要"全局一致性 + 联想整合"的生成任务（跨章伏笔、人设、时间线）在
   32-128K 区间普遍显著退化（NoLiMa：32K 时 12 个模型中 11 个跌破短文基线一半
   [NoLiMa 2025]；RULER：多数模型有效长度 ≤64K [RULER 2024]；多轮分片对话平均
   -39% 且不可自恢复 [Laban 2025]）。我们 38 章的质量盲评斜率实测 **-0.042 分/章**
   （20 章以内为 +0.0145，拐点与"跨卷累积 + 上下文膨胀"重合，E1）。

两个症状同源：**上下文无界膨胀**。这决定了正确的优化方向不是"更好的缓存"，
而是"更小的每章必要上下文 + 有界的历史窗口 + 外部化的状态"。

### 1.2 贡献

- **C1（语义）**：以黑盒实验建立字节级前缀缓存的工程语义模型（缓存单元、best-effort
  持久化、超长输入固定间隔切分），并据此推导出应用侧的四条构造纪律（§4.1）。
- **C2（架构）**：一套在产品约束下（旗标缺省关闭、逐字节向后兼容）落地的命中率工程
  组合：卷级会话栈 + 静态指令冻结 + 台账增量更新 + 审校指令前置（§4）。
- **C3（方法）**：一套可复用的缓存异常诊断流程——统计分析 → 跨渠道交叉校定 →
  TTL/驱逐排除 → 逐消息哈希 → 同串重放——把"玄学抖动"逐步收敛为可判命题（§5）。
- **C4（实证）**：20/53 章两级真机长跑 + 26-36 份双评委盲评的完整数据（§6），包括
  与文献一致的衰减曲线，以及一个反直觉发现：**上下文压缩是质量装置，不是成本装置**。

## 2. 背景与相关工作

### 2.1 前缀缓存机制

DeepSeek Context Caching 以"完整前缀单元"为命中单位：后续请求必须完整匹配某个已
持久化的单元；单元在**请求边界（输入尾/输出尾）、多请求公共前缀、超长输入的固定
token 间隔**三处持久化，整体为 best-effort 不保证命中；缓存闲置数小时至数天清除
[DeepSeek KV Cache Guide]。命中/未命中价差约 31 倍（flash 档 off-peak：$0.007 vs
$0.22 /M），off-peak 为 peak 半价。Anthropic/OpenAI/Gemini 的官方最佳实践一致：
**静态内容前置、可变内容后置、多轮对话追加式构造**；Anthropic 进一步明确上下文是
"有限资源、边际收益递减"（attention budget），长会话官方方案为压缩 + 结构化外部
记忆 + 子代理 [Anthropic Context Engineering]。

服务端研究（CacheBlend [2405.16444]、PromptCache [2311.04934]、CacheGen [2310.07240]、
Mooncake [2407.00079]、AttentionStore [2403.19708]）沿两个方向推进：非前缀块复用
（需 ~15% 选择性重算修正交叉注意力）与 KV 分层存储/调度。**对 API 消费者而言这些
均不可用**——可用的杠杆只有布局与有界化。多副本部署下朴素负载均衡会破坏缓存亲和
（SGLang cache-aware router 实测多前缀组命中率 20% → 75% [SGLang v0.4]）。

### 2.2 长篇生成与上下文工程

长篇生成系统的主流构造全部收敛于"近程逐字 + 蒸馏状态 + 按需检索"三件套，上下文
对章节数 O(1)：RecurrentGPT 的滚动短长期记忆 [2305.13304]、DOC 的递归大纲+逐段
控制器（人评情节连贯 +22.5%）[2212.10077]、DOME 的时序知识图谱+冲突分析器
[NAACL 2025]、MemGPT 的分页记忆 [2310.08560]、RAPTOR 的层次摘要 [2401.18059]。
**没有任何一个成功系统采用整卷历史无限追加**。Anthropic 的 memory tool
（str_replace 增量更新 + context editing）在 100 轮 agent 实测中削减 84% 输入
token [Anthropic Advanced Tool Use]——是"状态增量 diff 化"的工业先例。可靠性方面，
aider 的基准长期表明弱模型生成不可靠 diff；因此增量方案必须配结构化解析 + 锚点
校验 + 失败回退。

## 3. 系统架构

### 3.1 流水线

千笔一文逐章流水线：卷纲/细纲 → 正文（思考高档）→ 字数闸门/扩写 → 本地 L0 确定性
预检 → 6 维审校（3 票 + 引证逐字验真 + CISC 置信聚合）→ 修复环 → 追踪台账（角色
状态/伏笔/时间线/上下文）→ 摘要链 → 设定清算（canon audit）。反哺机制把正文新设定
回写世界书。约 18 次 LLM 调用/章，DeepSeek V4 flash 档。

### 3.2 双层前缀与会话栈

- **L1 全书前缀（project_header）**：题材预设、核心设定、正则 must 契约——全书逐字节
  稳定；
- **L2 章级前缀（chapter_header）**：八节（细纲/全局摘要/角色状态/时间线/伏笔/上一章
  结尾与文风样本等）——每章一次。

`volume_session` 开启后：会话 system = L1（+S4 时附加冻结的写作指令库）；L2 与正文
作为开幕轮进入会话，此后各阶段作为追加 user 轮推进。请求序列满足"append-only 纯
追加"，理论上每个请求整体命中前缀缓存。

### 3.3 字节纪律

所有优化以**旗标缺省关闭**上线；关闭时请求体与改造前**逐字节一致**，由 `prefix_lint`
静态锁守护（模板占位符断言、两次生成逐字节一致、禁用动态值扫描）。这一纪律使
每个优化都可以独立 A/B、独立回滚，也是本战役所有对照实验成立的前提。

## 4. 命中率工程

### 4.1 从官方语义推出的四条构造纪律

由 §2.1 的单元语义（E2，官方文档）+ 我方 E1 实证：

1. **追加式是唯一免费午餐**：任何对历史中段的改写都会使其后全部单元作废；
2. **静态前置**：指令体、书级设定进 system 或冻结段，一次计价、全程命中；
3. **每章请求规模有界**：超长输入的单元按固定间隔粗粒度切分——栈越长，章界这一笔
   "首达深请求"的记账脆弱面越大（§5）；
4. **少即是多**：命中价再便宜也是钱；减少进入历史的每章余量（增量台账、引用行替代
   重述）同时改善成本与延迟。

### 4.2 卷级会话栈（S1）

同一卷各章共享 VolumeSession；跨章历史从"每章全价重读"变为"命中价复读"。20 章真机
对照（同种子书同目标字数）：混合命中率 **80.4% → 93.8%**（真分母口径，见 §5.4），
单章实付 ¥0.386 → ¥0.273（-29%），盲评 7.61 → 7.53（-0.08，闸门 ±0.5 内）。

### 4.3 静态指令冻结（S4 / review_in_system）

写作指令库（S4）与审校静态尾段（约 5.1k 字符：裁决优先级 + 六维 checklist + 输出
契约）各自一次性载入会话 system。逐章重发版会在历史里累积：第 k 章的每次调用都要
复读前 k-1 章的指令体。冻结后全书只计价一次。实测合计省 ~11-12k token/章（S4）+
~3.3k token/章（审校尾段，E1 归因）。

### 4.4 台账增量更新（tracking_delta）

追踪相位的旧设计让模型每章输出**整本台账**（"更新后的完整文件、不得删减已有小节"），
输出 2.2k → 7.9k token 随章数单调增长、第 17-19 章撞 8,192 max_tokens 截顶，且在
章内与章界各计价一次——是"每章 +40k 且增速上升"的主驱动（占 ~31k/章的永久留栈）。
增量模式只要求输出**有变化的条目**：角色状态按 `## 名` 小节锚点整节替换、伏笔表按
首列键替换、时间线整行去重追加；解析/合并失败自动回退全量重述（绝不把碎片当全文
写盘）；每 10 章强制全量对账防漂移。实测追踪输出 **1.3-2.9k token/章**（含世界书
反哺），每章上下文增量 +40k → **+2k**（冒烟 3 章 E1；20 章验证见 §6.3）。

### 4.5 章界抖动：把不可判的判掉（诊断方法论）

20 章长跑发现一个规律性异常：**12/19 个章节边界**，下一章正文请求的命中恰好等于
上一章正文请求的深度（`hit(N) = ⌊in(N-1)/256⌋×256`）——上一章正文之后约 32k 已
缓存内容在章界被重新按 miss 计价；但同章内后续相位几分钟内又能记到深命中；另有
孤立样本同一串字节先记 4.5%、一小时后重放 99.9%。我们用五步把候选原因压干：

| 步 | 实验 | 结论 |
|---|---|---|
| 1 | 跨渠道复测（百炼续写 4 章） | 章界浅命中**两渠道同构**——非某网关记账特性 |
| 2 | 可控阶梯深度探针（24.5k→73.5k，静置 150s + 大追加） | 最深节点静置后仍命中——**TTL/驱逐解释作废** |
| 3 | 界隔时长 vs 命中深度相关性检验 | 无相关——"等久一点再发车"判伪 |
| 4 | 逐消息 sha1 轨迹（134 条跨章界消息） | **逐哈希全等**——我方代码零改写，排除应用侧 |
| 5 | 同串字节 30 次重放（3 参数形状 ×10，隔 4h、顶着并发负载） | **全部 99.9-100%，零双峰**——朴素多副本路由假说证伪 |

净结论：请求侧字节已被证明干净；异常被定性为**"首达深度窗口"的服务商单元持久化
时滞（best-effort 语义）**，稳态深前缀持久可靠（≥4 小时 + 负载）。由此得出两条
工程纪律：**单章 hit% 不可作裁决判据**（用整卷均值 + 同串重放复核）；**章界损失
≈¥0.03-0.05/章（E2），不值得为其增加工程复杂度**。低成本重试/热身方案因"同串
哈希亲和变体下无效 + 稳态自愈"被主动放弃——**知道什么时候不优化，也是优化**。

### 4.6 计量纪律

- **真分母口径**：网关偶发缺失 `prompt_tokens_details` 时，涉及 token 按全 miss 计
  → 在册命中率与真分母差 2.1pp（T1：95.9% vs 93.8%）。对外报告一律用真分母。
- **OpenAI 式回退**：中转渠道只报 `prompt_tokens_details.cached_tokens` 时客户端
  自动换算命中/未命中（DS 双字段在时优先 DS），使命中率在任何渠道可测量。

## 5. 有界上下文与质量

### 5.1 衰减的实测与文献对齐

38 章质量盲评（18 份样本 × 双评委 × 引文逐字验真 × 同场锚点自校准）：
前 20 章 +0.0145 分/章（平），之后 **-0.042 分/章**（超 T3 判据 ≥-0.02 一倍），
掉分最大维为爽点/情绪闭环（D2 -1.17）与情节一致性（D4 -0.42）——评委点名的全是
"章内账本穿帮"（钟点认错、伤情漂移、道具无来源）。这与 §2 的文献曲线同构，且与
"多轮分片 -39% 且不可自恢复"（Laban 2025）共同否定了"继续在长栈里修"的路线。

### 5.2 压缩：质量装置，不是成本装置

20 章边界的压缩 A/B（两臂各 6 章，同 285k 热栈出发）：压缩把**读量**砍 71%，但
读量本是命中价的廉价部分；真正贵的 miss 反而 +5%（折叠等于扔掉热缓存，新栈每章
重新补写），LLM 耗时 +78%。**但盲评质量 +1.03 分**（7.17 vs 6.14）：不压缩臂草稿
退化到 1,067-1,573 字、触发字数预检跳过审校；压缩臂草稿饱满、审校链完整。
⇒ **压缩的收益口径是流水线完整性与质量，不是钱**——这与"压缩省钱"的朴素直觉相反，
也是本文最反直觉的实证发现。

### 5.3 L0 确定性预检（零 API 的质量补位）

盲评与埋雷召回共同暴露：LLM 审校对"钟点认错/伤情漂移/道具无来源/爽点推迟"四类
穿帮召回 0/2，而确定性清算相位能抓到同批缺陷——缺的是**确定性证据**不是智力
（与 CRITIC/Huang et al. 的结论一致：无外部反馈的内在自校正退化）。V5 在审校前
注入零 API 的账本对照：细纲爽点承诺 + 推迟语式词典、中文数字归一的钟点复现核对、
"禁止提前释放"关键词确定性命中、未愈伤情在场清单（证据供给而非自动裁决，全部
fail-open）。

## 6. 实证结果

### 6.1 主要结果表（E1，除注明外均为真机）

| 配置 | 章 | 命中率（真分母） | 单章实付 | 栈增量/章 | 盲评（同场锚点） |
|---|---|---|---|---|---|
| 0.19.0 基线（章级会话） | 6 | 80.4% | ¥0.386 | — | 7.61（在册） |
| + 卷会话（S1） | 6 | 93.3% | ¥0.291 | — | 7.53 |
| S1+台账增量+前置冻结（V 全栈冒烟） | 3 | 89.6%* | **¥0.168** | **+2k** | 待评 |
| V 全栈 20 章（V6） | 20 | 见 §6.3 | 见 §6.3 | 见 §6.3 | 见 §6.3 |
| 旧架构 53 章（对照，未优化） | 53 | 90.4%* | ¥0.423 | +33~40k | -1.04（后段） |

*3 章样本含首章冷启，20 章整卷数字以 §6.3 为准；53 章行含渠道切换段。

### 6.2 分项归因（E1/E2）

- 卷会话（S1）：80.4% → 93.3%（6 章同输入对照）；
- S4 静态冻结：省 ~11-12k token/章（新开幕轮从 3.4-10k 降到 ~8.3k 纯新料）；
- 台账增量（V2）：追踪输出 7.9k → ~1-2k/章；上下文增量 +40k → +2k；
- 审校前置 + 清算剥离：合计 ~8k 字符/章的重复计价消除；
- 章界抖动：定性为服务商 best-effort 语义，不计入可优化损失（§4.5）。

### 6.3 输出侧组合的对照验证（V7 vs V6，同书同渠道同跨度 11/13 章）

输出侧三鲸鱼的相位级对照（E1，`v7_long13` vs `v_full20` 的 usage 逐笔聚合）：

| 相位 | V6 输出 tok | V7 输出 tok | Δ | 机制 |
|---|---|---|---|---|
| 追踪台账 | 63,280（ch10 起撞 8192 截顶 ×3） | 36,309（10/11 章 ≤4.5k） | **-43%** | JSON 补丁（事件+键控 upsert），输出绑定本章出场实体数 |
| 全局摘要 | 18,827（13 章每章全量重述） | 6,032（每 2 章重算） | **-68%** | 降频 |
| 扩写 | 25,305（20 次整章重写） | 4,875（10 次补尾，单次 ≤674） | **-81%** | 只续缺口，输出∝缺口 |
| 合计输出 | 267,197 | 254,179 | -5% | 正文思考方差淹没相位收益（见 §6.4） |

每章 DS 口径总成本 ¥0.405 → **¥0.289（-29%）**；命中率 96.0% → 94.1%（同带，
波动来自章界记账抖动与内容差异）。11/11 章补齐至目标字数（V6 有 4 章 <1800 被字数
闸门跳过审校——补尾式的次级收益是审校链不再被跳过）。

### 6.4 新发现：正文思考长度的百倍方差

同配置（thinking high）逐章 prose 推理 token：**323 ~ 32,770（100 倍）**，与章节
难度/内容无可见相关。由于命中率已达 94-96%，输入侧边际成本已低于输出侧推理，
思考长度方差成为下一个主要成本杠杆（候选：effort 降档的质量 A/B、结构化思考约束
——须过盲评闸门）。同时实测栈斜率（+30k token 级/章）未因输出侧治理而下降——
轮次累积的大头（审校票往返、上一章正文）需要 V4 有界窗口，是路线图的下一站。

### 6.5 方法论教训：冒烟外推陷阱

3 章冒烟曾测得"每章上下文增量 +2k、¥0.168"——新书前三章的世界书/台账极小，一切
处于最小值；13 章实测斜率回归 +30k 级。**长篇系统的任何性能指标都必须在 ≥半个
叙事跨度上测量**，前 N 章外推系统性乐观。

## 7. 讨论

**7.1 反直觉之一：压缩不省钱。** 在热缓存下，压缩把命中价的读量变成 miss 价的
重补写；它的正确收益是质量（草稿饱满 → 审校链不断）。压缩的部署时机应由"质量
需要"而非"成本需要"决定——这与把压缩当作降本手段的普遍直觉相反。

**7.2 反直觉之二：命中率工程的终点不是 100%。** 命中率的敌人从"我们没做好追加式"
（已解决）收敛为"服务商 best-effort 语义下的记账抖动"（不可优化、可用口径纪律绕过）
与"卷界/窗口重置的结构性税"（≈4.4pp，应有界窗口 + 按章数定界的重置摊销）。99% 的
正确表述是"**整卷均值 ≥97% + 同串重放复核**"，而非单章数字。

**7.3 有界上下文是成本与质量的联合最优。** 文献（§2.2）、官方语义（§4.1）与本实测
（§5.1）三方独立指向同一架构：近程逐字 + 蒸馏状态 + 子集注入，上下文对章节数 O(1)。
无界栈的唯一优点是实现简单；其代价（二次增长成本 + 32-128K 整合衰减 + 多轮不可
自恢复）在长篇场景必然兑现。

**7.4 工程纪律的价值。** 旗标缺省关 + 逐字节锁 + 独立 A/B，使八项优化各自可归因、
可回滚；计量纪律（真分母、整卷均值、重放复核）使每个数字可对账。本战役全部结论
均可在仓库产物中复核（usage.jsonl / metrics.json / 盲评票据 / 诊断轨迹）。

---

## 8. 局限与未来工作

- 单题材单书（都市悬疑，2000 字目标/章）主测量；跨题材外推属 E2。
- 章界抖动的服务端机制（单元持久化时滞 vs 其他）不可从 API 侧分辨，本文仅完成排除法。
- 增量台账的长期漂移率（10 章对账窗口是否足够）需要 ≥100 章尺度的验证。
- 有界窗口（V4）尚未启用：V2 后栈斜率降至 +2k/章，60 章预计 ~50k 栈，窗口重置的
  必要性待长跑数据定夺。
- L0 预检的召回率目前只有构造性依据（推迟语式近确定性），需埋雷集持续校准。

---

## 9. 结论

在字节级前缀缓存的约束下，长篇生成的成本与质量可以被同一组架构决策同时改善：
**追加式会话栈 + 静态冻结 + 状态增量化 + 有界窗口 + 计量纪律**。本系统将该组合在
产品约束下落地，20 章命中率 80.4% → 93.8%、单章成本 -38~56%、上下文增量逼近常数，
且质量盲评全部通过 ±0.5 闸门。我们希望本文的语义模型、诊断流程与"不优化清单"对
同类系统可复用。
