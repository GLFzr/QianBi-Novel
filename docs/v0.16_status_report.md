## 3. 本轮修掉的「断链」——为什么这个项目值得这么较真

这一轮最有价值的不是新功能，而是挖出并堵掉的几条**平时完全看不见、出事那天才响**的断链：

1. **`updates.check_on_start` 是一个从未接线的死键**。配置默认 `True`、代码里判断了它，
   但没有任何调用点触发自动检查 → 设置里的开关是假的。修法是接线 + 改名为 `auto_check` +
   默认关：旧配置里那个 True 是出厂值而不是用户选择，原样搬到新键等于**升级后偷偷开机联网**，
   与 README 里「数据不出本机」的承诺冲突。
2. **网络失败被报成「已是最新版本」**。`update_check.check()` 把「拉不到清单」和「无新版」
   都吞成 `None`，调用方据此 toast「已是最新」——典型假绿。改成三态分开报。
3. **检查更新用裸 `threading.Thread` 直接 emit**：等于从别的线程调进正在求值的 QML 绑定。
   换成 `QThread` 工作器 + 排队信号。
4. **`config.json` 解析失败会吃掉用户设置**：直接回落默认值，而下一次保存就把连接档案与槽位
   绑定覆盖掉，且不留痕迹。改为先另存 `config.json.broken-<时间戳>`。
5. **覆盖安装会残留旧 `_internal`**：PyInstaller onedir 升级只做「新的盖旧的」，已删除/改名的
   模块会留下来和新版拼成一套谁也没测过的组合。加 `[InstallDelete]` 先清空程序树。
6. **日志目录不认 `QIANBI_CONFIG_DIR`**：配置能重定向而日志不能 → 探针隔离时日志仍写进真实家目录，
   且「关于」里显示的路径与实际打开的路径可能不是一份。改为与 config 同源。
7. **文档里的事实错误**：`PRIVACY.md` 与便携版说明都写「书稿在 `~/.qianbi_novel/projects|books`」，
   真实默认是 `~/Documents/千笔一文`。**照旧文案备份会丢掉全部书稿。**
8. **清单字段一直空转**：`latest.json` 里的 `sha256` 从没被读过 → 用户手动下载后无从校验。
   现在随新版提示显示。
9. **README 的数字在漂**：43→45 装配点、316→421 单测、35→41 探针、包名钉死 v0.15.0。
   已全部校准，并把下载表改成不写死版本号。

## 6. 已知边界

- **注入 ≠ 执行**。自然语言写的 must（「改命必须索回代价」）机器无从判定，仍靠 prompt 约束 +
  审校裁决，是概率性的。硬闸门只覆盖可确定的那一小部分——对判不准的东西亮红只会制造假阻断，
  最终把人逼成无脑点强锁。
- 优先级固定为：**作者显式指令 > 本书正则 must > 本书世界书 > 本章细纲 > 题材预设**。
  契约不凌驾于作者：强锁永远可选，但会署名留痕。
- 外部文档导入是「摘录 + 映射」，不是「读完整本书」：3 万字一段、最多 8 段，模型补写的一律判不通过。
- 检查更新只到「提示 + 直达下载」，不做静默自装。
- 仅 Windows 打包；提示词按 DeepSeek API 调校，换网关可能更抖。
- `[常驻]` 标记只在世界书**裁剪路径**上被剥掉；「整本装得进预算 → 逐字返回原文件」的快速路径不剥。
  诚实取舍：比起原作设定被静默裁掉，多一个标记的代价可以接受。

## 8. 一句立场

写作 Agent 的终局不是「更会写的模型」，而是**会拒绝的流水线**。所以它可能是未来最好用的那一个
——不是因为它现在写得更漂亮，而是因为这里攒下来的证据（哪条设定在第几章被丢弃、这句引证在原文
里不存在、这次锁定绕过了哪条 must）不会因为换模型而作废。
