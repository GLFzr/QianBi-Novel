## 第一部分 两档制改造设计（主代理方案 · 本轮主改）

### 1.1 现状盘点（全部实证）

**四个档位**（`app/config.py:92`）：`auto=全自动 / step=逐步确认 / border=边界确认 / cw=共写`。

| 消费点 | 位置 | 行为 |
|---|---|---|
| 门启用判定 | `app/core/orchestrator.py:110-118` | auto=全关 / step=全开 / border=按 gate_hard+gate_soft 清单 |

**结论**：四个档位在"门行为"维度上**本来就是同一套机制的不同清单内容**
（auto=空清单 / step=全清单 / border=部分清单），cw 是独立状态机与门无关。
删掉 step/border 两个档位、把清单开关升为全自动档的一等公民，**零机制损失**。

### 1.2 目标形态

- **顶层只有两档**：`全自动` / `共写`。UI 换成两段式分段控件（点哪进哪，不再循环胶囊）。
- **全自动档下，决策门变成管线上的常驻开关**：
  - 「门」按钮从"仅运行中可见"改为常驻（有项目即显示）；
  - gatesDialog 改造：9 门清单（隐藏未接线的 G1/G3，或标注"未接线"）+ 三颗预置按钮：
    - **全放行**（=原 auto）：清单清空，一路到底；
    - **边界推荐**（=原 border 出厂语义）：G2/G5L/G8/G9（大纲/开写/审校/定稿）；
    - **逐章全停**（=原 step）：G2/G4/G5L/G6/G7/G8/G9 全开。
  - 弹层说明文案删掉 border/step 词汇，改为「勾选哪些步骤生成后停下等你确认；不勾=自动过」。
- **cw 完全不动**：六阶段状态机、粘性、受控切换全部保持现状。

## 第二部分 UI 视觉高级化（子代理 A 报告精编）

### 2.1 现状底子

- 已有资产比预想厚：Theme.qml 三主题 24 色/6 字号/6 圆角/6 间距令牌；App* 组件 30+ **无一处裸原生控件**；

### 2.2 病灶清单（11 条，全部带证据，摘要）

1. 缺中性色阶与浮起体系：所有卡片同明度 bgCard+1px 边，无一层投影/渐变（AppCard.qml:8-11 等）；docs/ui_demo/UI优化演示.html 已试出 --bg-raise/--shadow 令牌但未回灌 QML。
2. 语义色有"点"无"面"：36 处手写 `Qt.rgba(Theme.xxx.r,...)`（算上裸字面量 rgba 全库 57 处），alpha 离散出 **15 种**（0.05~0.55），缺 successSoft/warnSoft/dangerSoft 令牌；**实锤：Theme.qml:145 专门定义了 accentSoft(0.14)，全库 0 处使用**。
3. 字重两档走天下：82 处 `font.bold` vs **0 处 `font.weight`**；serifFont/monoFont 未随包分发，干净机器静默回落（Theme.qml:164-166）；ContractPanel 标题误用 fsBig=20 与其他面板 fsTitle=15 不一致（ContractPanel.qml:105）。
4. 间距节奏混乱：三种 inset 机制并存；**BookshelfPanel.qml:65-70 / ChapterPanel.qml:85-88 在 Layout 子项上写 anchors.margins（无效属性）**，靠 delegate `width-20` 制造单边空隙，左贴边右 20px。
5. 圆角不成节奏：令牌 4/5/8/12/99 之外，字面量 6/7/8/10/11 散落（Main.qml:586、LogView.qml:9 等）。
6. 图标语言割裂：AppIcon 30 个线性图标 vs 裸奔字符"▤ ⏸ ✓ ● ＋ －"混排（BookshelfPanel:147、StepGateBar:60、AppSpinBox:41/55 等）——**多数图标 case 已存在，纯替换即可**。
7. 原生对话框割裂：FolderDialog/FileDialog **8 处**弹 Windows 原生窗；Menu 仅调 palette。
8. 空态/加载态三处野实现（书架"▤"、章节两行裸 Text、契约一句话），AppEmptyState 组件反而不被用。
9. 编辑器顶栏 10+ 控件无分组无分隔，主操作"保存"淹没（Main.qml:514-647）。
10. 动效只有"变色"没有"位移/层级"（详见第三部分）。
11. 门面件无记忆点：书架首字方块纯色、AppStatTile 数字 15px 太小气、Logo 28px 文字方标。

## 第三部分 动效体系（子代理 B 报告精编）

### 3.1 现状一句话

现有动效词汇只有两种：**色值过渡**（25 处 Behavior，100-120ms）+ **opacity 呼吸**（8 处循环定义，600-850ms）；
缺**位移、缩放、推进、一次性仪式**四类词汇。全库 44 处动画时长全是字面量（核实精确计数），无令牌。

### 3.2 最痛三处

1. **面板切换纯瞬切**（Main.qml:400 StackLayout）——感知最强的"生硬"第一来源；
2. **22 个 Dialog 全部无出入场**（全库唯一带 enter 的是 ReaderView 的 notePopup，且它是 Popup 不是 Dialog、无 exit），遮罩瞬时变色；
3. **长任务"死进度条"**：ThinProgress 只在章完成瞬间跳一格（bridge.py:2604 进度=完成章数/总章数），
   单章跑几十分钟无法区分"在跑"和"卡死"。

其余重点：StepGateBar 出现时"啪"地顶开布局（决策门恰是共写核心节奏点）；主控四按钮 visible 硬切；
流式正文 `positionViewAtEnd()` 硬跳（读不了刚生成的上句，CwDialogueDock.qml:469 已有正确的"贴底才跟随"范式但编辑器没抄）；
QueueRow 状态跳变+model reset 整列闪重建；章完成/完本无仪式感。

### 3.3 动效令牌（落点 Theme.qml，纯追加）

```qml
readonly property int durFast: 120    // hover/press/focus/色值微反馈
readonly property int durNormal: 200  // 面板切换、抽屉、GateBar、日志渐入
readonly property int durSlow: 320    // Dialog 出入场、全屏过渡
readonly property int durLoop: 1400   // 呼吸/循环（把焦躁的 600-850 放慢）
readonly property int durIndet: 1600  // 不确定态扫过周期
readonly property var easeOut: Easing.OutCubic
readonly property var easeStd: Easing.InOutQuad
property bool motionOK: true          // 减少动态总闸
```

### 3.4 方案分层

| 层 | 内容 |
|---|---|
| **P0 面包黄油** | 面板切换 fade+slide（新面板入场 opacity 0→1 + x 24→0，不动 StackLayout 结构）；Dialog 通用出入场（opacity+scale 0.96→1）；StageStepper 相位推进叙事（圆点弹跳+连接线"电流点亮"）；QueueRow/书架 hover 补 Behavior；StepGateBar height+opacity 滑入；主控按钮交叉淡化 |

### 3.5 性能红线（写进实现约定）

- 可动画：opacity/x/y/scale/rotation/color/独立小元素 width；**禁**：任何触发 relayout 的属性、text 内容逐帧动画、大文本容器循环动画。
- 打字机 33ms tick 已到上限，**不提速**；改善方向是"只平滑滚动、不动画文本"。
- **重点隐患顺手修**：ReaderView.qml:350-364 流式期间每 chunk `toHtml()` 全章重渲染——加 250ms 合并 Timer（这同时是性能修复）。
- 9 个循环动画改 render 线程驱动的 `OpacityAnimator/RotationAnimator`（Python 高频 emit 挤占 GUI 线程时动画仍顺滑）+ 全部挂 `&& Theme.motionOK`。
- ListView 只用 add/displaced 一次性过渡，禁 populate 大列表动画。

### 3.6 减少动态

设置页加「减少动态」开关（走 editorPrefs JSON 通道）→ Theme.motionOK 总闸 → 9 个循环动画 running 挂闸；

## 第七部分 用户裁决落定（v1.2，2026-09-13）· 实施规格

> 三个决策点已裁决，本节为唯一实施依据，与第一部分冲突处以本节为准。

### 7.1 决策一：门交互重设计（取代 1.2 节的「门按钮+弹层」方案）

- **取消「门」按钮与 gatesDialog 弹窗入口**。
- **仅在流水线面板（全自动档）下方空白处**放两个开关按钮：**「逐步确认」**与**「边界确认」**：
  - 互斥：**可以同时关，不可以同时开**；
  - 「逐步确认」开 → 全部接线门停靠（原 step 档语义）；
  - 「边界确认」开 → **下方拉出内联清单**逐门勾选（原 border 档语义，勾选即时生效）；
  - 两个都关 → 全门自动放行（原 auto 档语义）；
  - **共写档下整块不显示**（含清单）。
- 配置表达：`writing.gate_preset: "off"|"border"|"step"` + `writing.gate_list: [门key]`
  （preset=border 时消费 gate_list；step 时消费全部接线门；off 时空转）。
- 迁移：旧 `run_mode=step → preset=step`；`border → preset=border, list=hard+soft 并集`；
  `auto → preset=off, list=hard+soft 并集`（保留勾选记忆但关闭）；
  `step_confirm=true → preset=border, list=[G9]`；`run_mode=cw → auto`（cw 只存项目粘性）。
