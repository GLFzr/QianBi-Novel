## 一、prefix 经济学：90% 目标的达成算术（v2 关键修正）

命中率 = ΣH / (ΣH + ΣT)，H=项目头（跨调用逐字节一致），T=各调用动态尾。

现状：H≈2k tokens（core_setting 1500 字符+genre），T 平均 5-7k → 命中率 ≈ 25%（与实测 16% 吻合，其余损耗来自无项目头的调用）。

**90% 的达成条件：H ≥ 9 × ΣT/调用数。** 两条路径同时做：

1. **H 扩容到 10-14k tokens**（反直觉但正确：命中部分只收 1/10 价，头部做大是
   "把贵的数据搬到便宜的地方"）：
   - 写作纪律全文（14+2 条）≈ 1.5k
   - must 规则全文（228 条，~12k 字符）≈ **8-9k**（v1 只说"全文"未算账，v2 明确：这是 H 的主力）
   - 核心设定节选 + 授权清单 + 题材预设 ≈ 2k
   - 世界书常驻条目（30 条）≈ 1.5k
2. **T 瘦身（A1-b）**：非草稿调用的尾段压到 ≤1.5k tokens——
   - 近章摘要 n=3 → n=2；时间线 1500→800；角色状态 3000→1500（摘要/追踪类调用）
   - 审校票的 prose 是载荷不可移——该调用族命中上限 = H/(H+prose尾)≈8/(8+4)≈67%，
     靠 H 扩容把全员加权命中率拉过 90%

验收口径随之修正：G1 = **全调用加权命中率** ≥90%（usage 聚合），不是单调用口径。

## 二、B1' 内置机械相位表（配置工程，零 client 改动）

**位置**：`app/core/stages.py::preset_param_layers` 返回的 `stage_params` 上合并一张
模块级内置表（genre 预设显式配置同相位时压过内置——尊重预设作者）。

```python
# app/core/stages.py（模块级）
BUILTIN_PHASE_PARAMS = {
    # 机械相位：关思考 + 收 max_tokens（quality 无损、墙钟与成本双降）
    "tracking":       {"thinking": "disabled", "max_tokens": 8192},
    "chapter_summary": {"thinking": "disabled", "max_tokens": 2048},
    "global_summary": {"thinking": "disabled", "max_tokens": 2048},
    "deslop":         {"thinking": "disabled", "max_tokens": 16384},
    "enrich":         {"thinking": "disabled", "max_tokens": 16384},
    "canon_audit":    {"thinking": "enabled", "reasoning_effort": "high", "max_tokens": 8192},
    # 创作相位不内置：留给 genre 预设/连接配置（prose/outline/review 维持现状 max）
}
def preset_param_layers(proj):
    pid = _preset_id(proj)
    sp = genre_presets.stage_params(pid)
    for ph, kv in BUILTIN_PHASE_PARAMS.items():
        sp.setdefault(ph, {}).update(kv)   # genre 显式配置优先
    return {"stage_params": sp, "payload_defaults": genre_presets.sampling(pid)}
```

**风险与护栏**：`_overrides` 对显式实参让路（调用点显式传参不受影响）；`TEMP_LOCKED_PHASES`
机制不动；genre 若已配置同名相位则内置表让位（setdefault 语义）。**验收**：单测断言
机械相位的 payload 不含 `thinking` 字段、max_tokens 生效；A/B 一章对比去味/追踪质量。

## 四、其余各项实施规格（v1 未细化处）

### A2' `wb.constant_entries(proj) -> str`
独立函数：`parse(doc)` 后过滤 `meta["constant"]` 条目按 name 排序渲染。**不动 assemble
本体与其快速路径不变式**；`worldbook_text` 签名与行为零变化。

### C1' usage 字段（三处小改）
1. `client._record_usage`：增读 `usage.get("prompt_cache_hit_tokens")/("prompt_cache_miss_tokens")`
2. `usage.record` 签名扩参 `hit=0, miss=0, phase=""`；jsonl 增三列
3. 流式路径 `stream_usage` 已在手，同一 `_record_usage` 入口

### C3' 报表 `tests/report_cache.py`
读 usage.jsonl → 按天/phase 聚合：命中率、输出量、估算费用（价目表常量）；
`--last N` 输出最近 N 章窗。G1/G4 的验收工具。

### D1' 日历自动回写
`audit_chapter` 后：正则抽正文历法表述（`\u4e09\u65e5|\u4e03\u65e5|\u521d[\u4e94\u516d\u4e03\u516b\u4e5d\u5341]`等）→
与 案发日历.md 表项比对 → 不一致即写 `追踪/日历偏差提案.json` + toast（人工一键采纳）。
**不做静默改写**（时间中枢是契约文件）。
