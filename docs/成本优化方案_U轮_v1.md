## 2. 三条待裁决 → 本方案推荐（U0/U1 不依赖裁决，先行）

### 裁决 1（🔴 去Pro vs D4）：推荐「先②后①，拒绝③」
- **②先行**（零 Pro 修 D4，≈¥3 验证）：U2 修复包——D4 穿帮全是**章内账本**问题，
  而台账材料本来就在会话栈里（T 报告 §4.2 评委点名的三类穿帮，清算相位全部抓得到
  ⇒ 材料够、是审校没用上）。修复包见 §5。
- **①兜底**（仅审校/清算挂 `--pro-conn`）：U2 后 D4 仍 <锚点-0.5 才上；按 T1 实测
  清算相位用量（14.1k tok/章 pro 复核 3.7k），成本增量 ≈¥0.05-0.10/章，可承受。
- **③拒绝**（改尺子迁就结果）。

### 裁决 2（99% 验收渠道）：推荐**钉 TR + 整卷均值**
T1c 已证两渠道章界行为同构（差异只剩记账抖动 ±2.1pp），且用户钦定 TR 主测。
⇒ 99% 的验收表述改为：**「tr-dsv4f 渠道、整卷均值 hit%、同字节重放复核」**。

### 裁决 3（单章判据修订）：推荐**采纳，即刻生效**
- `miss ≤15k/章` → 改为「**构造性新料 ≤15k/章**（＝开幕轮+新 user 轮，E1 实测 9.6k 已达标）
  ＋ 整卷 miss/输入均值作为报告项」。单章 miss 不再作裁决（T 报告 §5.2：无法从回执
  分辨真重新计价）。
- `卷末 hit%` → **整卷均值 hit%**（验收）＋ 同形请求重放中位数（争议复核）。
- 单章 hit% 降级为观测曲线，不作判据。

## 3. U0 · 章界 32k 判决实验（✅ 已出数，2026-09-08 00:55）

### 3.1 ×10 重放判决（E1）：朴素多副本路由假说**证伪**
`replay_request_probe.py --reps 10`：同一 319,686 tok 串 ×30（3 参数形状 ×10），
**全部 hit=319,488（99.9-100%），零双峰**。且与首测（昨 20:37）相隔 **4 小时**、
期间 T3 长跑并发挤占——深前缀依然纹丝不动地热着。
- **排除**：冷热副本轮转（若有，30 发必现低命中）；TTL/驱逐（4h+负载仍活着，二度确认）；
  参数进键（三形状无差别，二度确认）。
- **仍然解释不了的（诚实保留）**：实跑 prose(22) 在 40-65s 窗口记 4.5%、
  enrich(22) 一分钟后记 95.8%。剩余候选（精确串哈希亲和、首达深度的提交窗口）
  在我们侧不可分辨，**停止追挖**——见 3.3 的经济性判断。

### 3.2 定案（E1）：不稳定性只存在于「首达深度的窗口」；稳态深前缀持久可靠
⇒ 章界那一笔的低命中**大部分是记账抖动而非持久损失**（同章内后续相位几分钟内
就记到深命中）。这直接支撑裁决 3：**单章 hit% 不可作判据，整卷均值 + 重放复核**。

### 3.3 缓解降级：低命中重发不做了（省钱省事）
- 重发若遇「精确串哈希亲和」变体则**无效**（同串→同副本→同样冷）；
- 稳态自愈（enrich 几分钟后即 95.8%），重发买不回多少真损失；
- 经济性（E2）：T1 口径章界真实损失 ≈¥0.03-0.05/章（12-18% 成本），
  工程价值低于 U1/U3，**搁置**（热身请求方案一并上架待用）。

### 3.4 对 99% 主攻的改写
章界抖动从"优化前线"降级为"计量注记"。**99% 的真缺口只剩一个结构性敌人：卷界税
（4.4pp）**——U3 升格为唯一主攻，U1-e/f（砍栈体积）承担成本与延迟。
## 4. U1 · 正确性与仪器修复（**不碰请求字节的立即可做**；碰字节的等 T3 收车）

**执行约束（重要）**：T3 正在跑，driver 每段新起 cost_bench 进程 ⇒ 磁盘上的新代码
会被后续段吃到。分两类：
- **A 类（T3 期间可落）**：压缩路径缺陷 A/B（T3 压缩关，零影响）、span 回退计数 E
  （T3 不用 span）、bench_queue 瞬时 5xx 退避续跑（昨晚 503 整夜教训）。
- **B 类（T3 收车后落）**：C① 台账增量写回、F 清算前缀剥离——两者都改请求字节，
  落了会让 T3 后段变成混合代码，读数分段污染。

| # | 项 | 对应缺陷 | 内容 | 判据 |
|---|---|---|---|---|
| U1-a | 压缩卷号错位 | T 报告 §9-A | 写侧 `volume=cur`；读侧先查本卷；幂等守卫改按"块覆盖到第几章"；回归：卷内只点火一次、陈旧块不复用 | T2 污染段（ch25-26）在修复后重跑中消失 |

## 5. U2 · D4 修复包（裁决 1 的路线②实质）

**设计原则**：D4 穿帮=章内账本问题；材料已在栈里（追踪相位输出逐章在会话历史），
缺的是**把材料递到判它的人面前**＋**确定性地查一遍**。

| # | 修法 | 层 | 说明 |
|---|---|---|---|
| U2-a | **审校 B 维注入"细纲承诺清单"** | prompt | 本章细纲承诺的爽点/伏笔逐条列出，要求逐条给 verdict，未结算即 fail（T4a 的 rule_ref 金标本来就这么写，是审校没拿到清单） |
| U2-b | **确定性账本预检（L0，零 LLM）** | 本地 | 从细纲+台账抽钟点/伤情/道具关键值，正文本地 grep 级一致性检查，违例合成阻塞项（D_PLOT）——与字数预检同型 |
| U2-c | **追踪引用历史**（S2 模式搬到 tracking） | prompt | 台账最新版已在栈里 ⇒ 审校/清算引用「最近一条台账消息」，user 轮不再重塞快照——**同时服务 U1-e**（省 opening snapshot 体积而不丢 D4 材料） |

**验证（U2-V，≈¥3）**：6 章 A/B（修复包 on/off）＋ 双评委盲评。
判据：**D4 ≥ 锚点(8.08)-0.5**；总分 Δ 回到 ≥-0.5 线内。
**若不达标** → 触发裁决 1 路线①（审校/清算挂 pro，T1 实测增量 ≈¥0.05-0.10/章）。

## 6. U3 · 卷界税消除（99% 的结构性主攻，U1-e/f 落地后）

**方案**：`volume_session.continuous` 旗标（缺省 OFF）——卷界**不再换栈**：
- 卷头信息（新卷纲/卷摘要）作为**追加 user 轮**进入会话（字节追加，前缀保持）；
- 会话文件跨卷续写（`卷N_messages.jsonl` → 单一连续栈或按代切文件，栈内容不断）；
- 压缩点不再绑卷界，改由 `input_threshold` 在**我们选的边界**触发（U1-a 修好幂等后）。

**A/B（U3-V，≈¥7）**：26 章跨双卷界（13+13）对照：
- 对照：现行为（卷界换栈，两次 75.4% 悬崖）
- 实验：continuous——**判据：卷界章 hit% 不低于前后章均值 -5pp；整卷均值 ≥97%**
- 附带收获：把 T 报告 §3.3 的公式改写为无卷界税纯 N 曲线，验证 hit% ≈ 1 − 0.37/N 是否恢复预测力

**为什么放在 U1-e 后**：连续栈让栈体积单调涨（无卷界重置），必须先有增量台账
（U1-e，砍掉 +40k 的主驱动）和可选压缩（U1-a 修好），否则 60 章后段读量失控。
