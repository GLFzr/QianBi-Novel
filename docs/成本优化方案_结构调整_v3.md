# 成本优化方案 v3：结构调整（目标：缓存命中 ≥93%）

> 定位：下一版优化方案。上一轮（v2 报告的 O1-O12）是**机制层**优化（span/预算/级联/外迁——已全部实现待测）；
> 本方案是**结构层**调整（用户已授权："在保证项目输出成果的情况下进行应用结构上的调整"）。
> 硬目标：**缓存命中 tokens ≥ 全部输入 tokens 的 93%**（hit/(hit+miss) 口径，与成本台账一致）。
> 数据位：本文的数字模型基于 0.18.4 逐笔还原 + 0.19 机制推算，**E0.1 六章基线跑完后用实测逐相位数据回填校准（§7），再定稿执行**。

---

## 1. 为什么 93% 需要动结构（数学，不是意志）

### 1.1 章会话栈（0.19 现状）的命中天花板

0.19 每章一个会话，每章结构：system = project_header(~13.4k tok) + chapter_header(~5-8k)，正文为首轮，其后 8-10 个相位为追加轮。**每章的 miss 构成**：

| miss 源 | 估算 tok/章 | 说明 |
|---|---|---|
| 轮 1（正文）：chapter_header + 写作指令动态尾 | 8-12k | project_header 跨章命中，章头必 miss |
| 轮 2-10：各相位指令 + 动态值（findings/数字/细纲引用） | 2-4k × 8 ≈ 16-32k | 每轮的增量尾巴 |
| **canon_audit 预扫（会话外单发）** | 5-18k | 审计 prompt 独立于章会话；只有 project_header 部分命中 |
| 异步注册窗口（长调用后秒发的快调用） | 0-5k | enrich 类 |

稳态估算：hit ≈ 9 轮 × 30k 均值 ≈ 250k，miss ≈ 35k → **混合命中 ~88%**。这与 v2 指南预估的 82-88% 一致——**章会话栈的设计天花板就是 ~88-90%，93% 靠它达不到**。这不是调参问题：每章一次 chapter_header 换血 + 每轮 2-4k 尾巴 + 审计单发，三座山都是结构性的。

### 1.2 93% 的代数

命中 93% ⇔ miss ≤ 总输入 × 7%。按上表总输入 ~285k/章，**miss 预算 ≤ 20k/章**——必须砍掉约一半的 miss，且在章数增多时 miss 增长要慢于 hit 增长。唯一同时满足两条的路：**让"每章重来的部分"变成"逐卷累积的部分"**。

## 2. 核心结构：卷级会话栈（S1，最大杠杆）

### 2.1 设计

把"一章一个会话"改为"**一卷一个会话**"，三个字节级纪律不变（harness 四件套）：

```
system（全书冻结）: project_header + 阶段指令库（见 S4）——逐字节永不变
user(第1章开幕轮):  chapter_header@ch1 + 本章细纲 + 「开始写第1章」
assistant:          第1章正文
user(追加轮):       审校指令+动态值 → assistant: 审校报告
user(追加轮):       清算/追踪摘要/修复 …
user(第2章开幕轮):  chapter_header@ch2 + 细纲 + 「开始写第2章」   ← 此前全部历史命中
...
```

关键字节级改动：**chapter_header 从 system 挪到每章开幕轮**。system 里放任何逐章变化的内容 = 每章全灭缓存（inferloop 实验的第一课）；挪到追加轮后，章头只 miss 一次、此后永久命中。

### 2.2 收益机制（三层）

1. **章头 miss 从"每章一次"不变，但 hit 基数逐章滚雪球**：第 N 章的每个相位都能命中前 N-1 章的正文/审校/摘要全文。第 4 章起单轮 hit 基数 80k+，混合命中进入 93-95% 区间；
2. **canon_audit 入会话（S2）**：审计的三分类对账本来就要读前情——预扫变为追加轮，输入从"单发 18k"变为"命中全部历史 + miss 增量 4-6k"。跨章硬伤检测的原料反而变厚（pro 全量复核仍独立保留为质量上限）；
3. **跨章一致性原料升格**：audit/审校从"读摘要"升级为"读真实历史"——这是质量侧的正外部性（v2 报告 §2.3 Claude Code 部分"前轮结论泄漏"风险由既有 SCOPE_LINE 机制兜住）。

### 2.3 成本侧账（为什么输入膨胀是赚的）

卷级会话让单轮输入随章数增长（第 20 章 ~300-500k tok/轮），但增长部分**全部是 hit 价**（$0.007/M off-peak）：400k hit = $0.0028/次，而省掉的 miss 重发是 $0.22/M 的 31 倍价。**输入膨胀的边际成本约为边际收益的 1/30**。真约束只有 TTFT（SWA 缓存读快，E0.1 数据里 latency 列可验证）与 1M 窗口（每卷 30-50 章才需要处理，见 S7 分卷重置）。

### 2.4 持久化与断点（工程关键）

- 会话消息栈**逐章追加落盘**：`项目/会话/卷N_messages.jsonl`（append-only，一行一消息）——崩溃恢复 = 重新加载文件，**字节不变则服务端缓存仍有效**（不需要重放，也不重新 miss）；
- `ChapterSession` 扩展为 `VolumeSession`：新增 `append_chapter_opening()`、`load(path)`/`save()`、章边界 checkpoint；既有 `rollback_to`/`snapshot`/`commit_turn` 语义不变；
- 写作/审校/辅助三槽跨厂商路由由 `_use_session` 守卫继续兜底（外迁相位保持无栈单发）。

## 3. 相位合并与尾巴极简（S3+S4，砍每轮 miss）

### S3 摘要链三合一
tracking + chapter_summary + global_summary 三相位读同一份正文、写同一族状态文件，合并为**一次调用一个 JSON**（人物/时间线/伏笔/章节摘要/全局摘要增量五个字段）。每章 3 轮 → 1 轮：省 2 轮尾巴（~5k miss）+ 2 次延迟；输出也从 3 份结构头压缩为 1 份。风险低（三相位均已关思考、机械任务），埋雷断言用 W4.2 的 summary_assert 直接可测。

### S4 指令库前置（harness 工具表模式的同构物）
各相位的**静态指令**（审校六维规则、去味红线、清算 schema 说明——合计 ~6-10k）目前随每轮动态尾巴重复出现。改为：system 尾部追加一次「阶段指令库」（全部相位的静态说明，逐字节冻结），**每轮 user 只携带动态值 + 一行相位指针**（"执行【指令库·审校】"，~200-400 tok）。每轮尾巴 2-4k → ≤1k。**纪律**：指令库变更 = 缓存全灭一次，只能随版本发布（写入 prefix lint 的 fingerprint，版本号变更在晨报可见）。

### S5 顺序微调（规避异步注册窗口）
长调用（正文 ~265s、审校 ~170s）之后的秒发快调用必然白 miss。合并后残余的快调用（修复、扩写）排在长调用后至少一个注册窗口（60s）或直接跟在另一个长调用后。收益小（~$0.005/章）但零成本。

## 5. 执行结构（S1-S7，每步独立 A/B 可回退）

| 步 | 内容 | 前置 | 预期命中贡献 | 风险与回退 |
|---|---|---|---|---|
| **S1** | 卷级会话栈（chapter_header 入开幕轮 + 消息栈持久化） | E0.1 基线 | 88% → 90-93%（第 3 章起） | 中：断点/回退语义——feature flag `writing.volume_session`，跌破质量地板即回退章会话 |
| **S2** | canon_audit 预扫入会话（追加轮） | S1 | +1-2%（省单发 miss） | 中：审计独立性——预扫 tag 隔离 SCOPE，质量对照必须含跨章硬伤埋雷 |
| **S3** | 摘要链三合一 | 无（可与 S1 并行） | +1%（省 2 轮尾巴） | 低：summary_assert 断言兜底 |
| **S4** | 指令库前置 + 轮尾 ≤1k | S1 稳定后 | +2-3%（大头在多轮尾巴消失） | 中：指令库版本纪律（lint fingerprint） |
| **S5** | 调用顺序微调 | 无 | +0.5-1% | 极低 |
| **S6** | 命中率预算门进 CI：prefix_lint + 相位 hit% 预算表（每相位 miss 上限）+ per_tier 台账对账 | 已具备 | 防回归 | — |
| **S7** | 分卷重置与长期压缩（ACE delta，O8 的接入点）：卷末把历史折叠为"卷终状态块"，新卷开新会话 | 单卷 >40 章才启动 | 防窗口/TTFT 失控 | 远期 |

**验证协议（继承 P1-P8）**：每步同源 6 章配对（S1 起才有跨章效应，3 章看不出 S1 的真实收益）；质量闸门 = 既有六维+清算+埋雷 v2 全套不降；命中验收 = 混合 hit% ≥ 该步预期下限；**93% 总验收 = 第 6 章单章 hit% ≥93% 且全卷均值 ≥91%**（第 1-2 章的冷启动摊销不计入单章达标线，但计入总账）。

## 6. 与 v2 机制层的关系

不冲突、正交且互相放大：span（O1）砍输出、预算（O2）砍思考——它们减小的输出恰恰是 S1 结构里下一轮的 hit 输入，输出越小 → 轮越轻 → hit% 越高；外迁（O3）被 `_use_session` 守卫隔离在卷会话之外，不破坏前缀域；级联（E9）的 pro 复核保持独立（它读的是 flagged 片段，本来就该小）。**执行顺序：先放 v2 机制实验（E1.1-E1.3 用固定草稿法不依赖 S1），S1 结构改造在其 A/B 框架内并行推进，两线在 G2 gate 汇合。**

### 对 §1.1 天花板模型的修正

实测 80.4% 低于模型推算的 88%——差距在**每轮增量比模型假设大**（实测均值 4.5k miss/笔 vs 模型 2.5k）：tracking/review_fix 的动态值冗余、deslop/enrich 的注册窗口白 miss、字数矫正链的额外轮次，三者合计约占 miss 的 30%。**修正后 v3 目标：S1-S5 全量落地 + 触发率治理，稳态章（卷内第 4 章起）hit% 93-95%，全卷均值 ≥93% 需要 ≥10 章/卷摊销冷启动**——6 章口径下 S1 全量落地预期 89-91%，这正是 S7（分卷摊销）与"卷均值 ≥91% / 单章 ≥93%"双指标验收线（§5）的依据。

### 输出侧结论（与 93% 目标正交，但直接砍账单）

思考 tok 占输出 69%（184.5k/267k）：prose 60.7k（预期内）、**canon_audit 系 65.7k**（预扫 low 档 + pro 复核 high）、**trim 45.2k**（high 档失控）。R1 批次（已发车）的 span 三变体 + trim-low 直接作用于输出侧，预期 trim 输出 -60~70%、deslop/fix 输出 -50%+，合计账单预期 -15~20%（¥0.386 → ~¥0.31/章）。
