## 1. 使命与验收标准

**项目**：qianbi-novel（千笔一文）——PySide6/QML 中文网文生成流水线，DeepSeek V4
flash/pro 双档 API。当前在做**成本优化战役**：在不降低写作能力的前提下把缓存命中率
推到极限。

**总目标（用户原话口径）**：缓存命中率 **99%**，能力**不下降**，**全线去 Pro**，
全程 autonomous（可回滚前提下持续调整，无需用户逐步审核）。

**验收硬指标**：

| 指标 | 验收线 | 现状（S 轮 6 章实测） |
|---|---|---|
| 卷级缓存命中率 | 长卷（≥20 章）**≥97-99%** | s1 变体 93.3%（6 章体量） |
| 单章成本 | ≤¥0.30/章（DS 口径） | s3 变体 ¥0.211 |
| 盲评加权分 | 相对 baseline(7.61) 漂移 ≥ -0.5 | s1 7.53 ✅ / s3 7.22 ✅ |
| Pro 依赖 | 0（全 flash + 级联预扫） | ✅ 已达成 |
| 一致性 D4 观察项 | 长卷不低于基线 -0.5 | s3 曾 -0.9，待 20 章复验 |

**为什么 99% 需要 20 章**：命中率是体量效应——hit% ≈ 1 − 0.37/N（N=章数，S 轮校准）。
6 章 → 93.9% 封顶；N≥20 且单章 miss ≤15k tok 才进 97-99% 区。**T1 就是来证明这个的。**

## 3. 协同协议（与台前主代理共享工作，必读）

**共享入口**：`docs/测试共享状态.md`。它有四块：当前坐标、测试矩阵进度、
**数据产物自动落点表**、协同日志。

规则（三条，都是硬性的）：

1. **开工前先读**看板 §1 当前坐标与 §2 矩阵进度——你不需要问任何人在哪、做到哪了；
2. **每个里程碑立即回写**看板：跑完一个变体（把 hit%/¥/章/盲评分三数写进 §5 日志，
   newest 在上）、做了决策、换了渠道、遇到阻塞。带时间戳和你的身份标注
   （`(接手代理)`）；
3. **不删别人的记录**，追加式协作；结论冲突时在看板 §6 挂起等用户裁决。

**分工边界**：台前主代理负责方案设计与代码实现；接手代理（你）负责测试执行、
计量、盲评组织、报告回写。你发现代码问题时**修测试/回滚配置**可以直接做，
**改主流水线代码**先在看板挂起（那台代理有文件所有权约定）。

## 4. 渠道与供数规则（用户裁决 2026-09-07）

**优先级链（已写进代码 `cost_bench.TEST_CONN_PRIORITY`，不是口头约定）**：

```
tr-dsv4f（TokenRhythm dsv4f）→ bailian-flash（百炼）→ ocgo-omen（opencodego）
```

- 缺省自动取链上第一条带 Key 的连接并打印进日志；`--flash-conn <id>` 可钉死；
- **缺省无 Pro**（全线去 Pro）；确需严格档显式 `--pro-conn <id>`；
- 三条连接的 Key 都在凭据管理器，`app.secrets.hydrate` 自动回填；
- **渠道 = 缓存域**：中途换渠道 hit% 曲线断裂。只许整卷边界切换，切了必须写看板 §5。

**渠道能力差异（选渠道前必读，详细表在共享状态 §4）**：
- **tr-dsv4f 有两个坑**：① `thinking:disabled`/`reasoning_effort` 被网关静默剥参
  ——**effort 敏感的 A/B（S3 节拍、think_budget 档位）不许在它上面跑**，那些实验
  用 `--flash-conn bailian-flash`；② 无 reasoning_tokens 明细（推理量并进输出）。
  命中率可测（客户端已打 `cached_tokens` 回退补丁），缓存读价 ¥0.20/M（读税
  ≈¥0.0155·N/章，仍远低于 miss 价）。**适合当 T1/T2/T3 长测主力**（用户钦定首选）。
- **bailian-flash 能力最全**（effort 完整、DS 原生 hit/miss 字段、最便宜缓存
  $0.007/M）：99% 数字的**精校与 effort 类实验**跑它。
- **ocgo-omen** 只作两家都断供时的续航（读税 $0.04/M，5.7×，cheap 区间收窄到 N≲10）。

**断供处置**：4xx insufficient balance / 限流 → 队列器自动跳过/停跑（§5.2）；
你换链上下一条渠道重发，在看板记切换点。渠道连通性存疑时先跑探针：
`python scripts/provider_probe.py --base-url <url> --api-key <key> --model <model>`
（四步：模型清单/推理不禁/关思考/缓存复打，约 ¥0.01）。

**时段**：DS 官方价 peak=北京工作日 9-12/14-18；百炼/TokenRhythm 全天一口价。
夜跑走 bench_queue 自带 off-peak 门（`--force` 可强发）。

## 5. 测试矩阵（作战卡：目的/命令/判据/处置）

> 每张卡五要素：**要证明什么 → 前置 → 命令 → 判据（数字）→ 失败处置**。
> 跑完把结果三数（hit% / ¥每章 / 盲评分）回写共享看板。

### T1 二十章长卷主测量 ⬜（**你的第一仗**，preset/队列已预制）

- **要证明**：① 99% 路线图成立——hit% 随章数爬升，第 10 章起 ≥95%，卷末 ≥97-99%；
  ② 单章 miss ≤15k tok（S4 静态冻结的效用）；③ 单章成本 ≤¥0.30 且无质量塌方
  （D4 一致性漂移是否复现）；④ TokenRhythm 渠道承载 20 章连续长测的稳定性
  （断流/限流/缓存域粘性）。
- **前置**：`tests_output/bench/bench_base/` 存在（已存在）；TokenRhythm 余额未知
  ——先跑 1 次探针确认活着。
- **命令**（二选一；推荐夜跑队列）：
  ```bash
  # 夜跑（off-peak 门自动拦 peak 发车）：
  .venv/Scripts/python.exe scripts/bench_queue.py --queue tests/bench_variants/queue_t1.json
  # 白天手动：
  .venv/Scripts/python.exe scripts/cost_bench.py --variant t1_long20 --chapters 20 \
      --preset-params tests/bench_variants/t1_long20.json --user-id qianbi-bench-t1 \
      --flash-conn tr-dsv4f --no-pro
  ```
- **判据**：见 §1 验收表 + `night_report_t1_long20_20260907.md` 预算线 ¥7.0
  （×1.5=¥10.5 全停）。**逐章 hit% 曲线**是核心产出：从 usage.jsonl 按 phase+章聚合
  （cost_bench --compare --phase 出相位表）。
- **处置**：中途断供 → 换 bailian-flash 重跑（记录切换点，hit% 曲线分段解读）；
  hit% 第 10 章仍 <90% → 先查 prefix_lint（前缀被动态值污染）再谈方案；
  D4 漂移 ≥-0.5 → 按长程文档 §6 预案：恢复被标记项的 pro 升级或强化 prescan。
- **预算**：¥4.2-5.8（S1 画像外推）。
- **跑完必做**：盲评（T5 对 t1_long20 的 24→20 章版）+ 更新台账 + 看板回写。

### T2 压缩 A/B @ 20 章边界 ⬜（等 T1 的卷状态做种子）

- **要证明**：长程压缩设计（长程压缩文档 §4）在真实续写中成立——20 章后接续写
  21-26 章，压缩组 vs 不压缩组的 hit 恢复速度、质量保持、成本差。
- **要点**：按 §4.3/§4.3.1 的 5 条保险丝（49/50 章近因保留、伏笔账本不压缩、
  压缩点选卷边界、压缩后首章 miss 预算、canon 引用不回退）。压缩实现
  （`app/core/history_compaction.py`，装配式零 LLM 费用）**可能还没落地**——
  先查 `app/core/` 是否已存在；没有则看板挂起给台前代理，或按文档 §6 自己实现
  （测试侧先行可用脚本级装配模拟）。
- **命令**：T1 结束态为种子，复制 fake home 后 A/B 两分支各续 6 章
  （对照组原栈续写、实验组压缩后续写）。
- **判据**：压缩组续写首章 hit% 恢复到 ≥85%（允许一次性压缩 miss），第 2 章起
  ≥对照组 -5pp 内；盲评两组差 ≤0.5；压缩组 6 章总成本低于对照组（上下文变短
  →miss 减少 >压缩一次性成本）。
- **预算**：≤¥3（12 章续写）。

### T3 60-100 章压力终验 ⬜（等 T2 通过）

- **要证明**：cheap 区间与质量衰减的双曲线——per-chapter 成本/延迟曲线平缓、
  盲评衰减斜率 ≥ -0.02/章、压缩循环（每 20 章一次）可持续。
- **命令**：同 T1 队列改 `--chapters 60`（MAX_CHAPTERS=40 上限，先改常量或分两卷
  拼接，**卷边界=压缩点**）；预算 ¥15-20；分 3-4 夜跑（bench_queue 串行）。
- **判据**：卷末 hit% ≥97% 不衰减；无内存/句柄泄漏（观察 latency 曲线）；质量斜率达标。

### T4 遗留回旋项 ⬜（可与 T1 并行的间隙活）

- **T4a trim_low D2 复核**：TRIM_PROMPT 已加"保爽点闭环"规则 5，需用
  `tests/planted_defects/` 雷章重验召回（命令模板：cost_bench --variant e13_trim_low
  --preset-params tests/bench_variants/e13_trim_low.json + 雷集对照）。
- **T4b span_reviewfix 复测**：⟦Pnn⟧ 修复轮用埋雷章验证修复命中率与 span 回退率。
- 两项都要在 effort 可控渠道跑（**bailian**）。

### T5 质量盲评（随 T1/T2/T3 每轮必做）

- **要证明**：成本优化的每一轮都没有能力下降（用户红线）。
- **机制**：评委是**子代理**（不是 API 脚本、不是产品功能），双评委+分歧补投；
  章节匿名（blind_map 只有主代理持有）；rubric 六维加权，
  `scripts/quality_score.py` 做引文验真（引文不实计 1 分）+程序重算总分
  （不信模型自报）；评委通道**不许污染用户 DS 控制台**——评委连接用
  `client.user_id="qianbi-eval"` 标注 + 优先百炼/TR 渠道。
- **命令**：`.venv/Scripts/python.exe scripts/quality_score.py --targets <变体1>,<变体2>`
  （票落 `tests_output/bench/quality_votes/`）；子代理评委按
  《小说质量评测标准_v2.md》逐维给分+逐字引文。
- **判据**：加权总分漂移 ≥-0.5 vs baseline；D4（情节一致性）单维 -0.9 即触发
  §6.6 预案（这是 s3 的遗留观察项）。

### T6 压缩内置化验收 ⬜（组件落地后）

`app/core/history_compaction.py`（装配式 handoff 块，¥0 LLM 费用）落地后：
单测（装配正确性/保险丝触发/flag 关闭时字节不变）→ T2 场景真机验收 →
`writing.compaction` flag 默认 OFF 收录。**flag 纪律**：所有 S 系旗标缺省 OFF 时
请求体必须与改造前逐字节一致（prefix_lint 守着）——新组件同样适用。

## 6. 计量与证据纪律

- **一切结论分级**：E1 实测（有 usage/产物证据）/ E2 模型推算（注明公式与输入）/
  E3 假设（不许驱动决策）。文档里没标级的结论视同 E3。
- **逐相位计量**：usage.jsonl 每行带 phase/slot/hit/miss/reasoning——相位对比用
  `cost_bench --compare --phase <名>`，不许拍脑袋。
- **台账**：每轮跑完 `python scripts/cost_ledger.py` 重生成 `docs/成本台账.md`
  （新变体要在 `BENCH_LABELS` 里加一行说明，否则不进表）。
- **TokenRhythm 口径**：无 reasoning 明细 → 该渠道的 reasoning 列恒 0（并进 out），
  台账注记；命中率用回退字段，可信。
- **防污染**：测试一律 fake home（cost_bench 已处理）；探针用量已隔离到
  `tests_output/probe_tr/`；用户的 DS 官方控制台数据只许减不许增。

## 8. 质量闸门与回滚

- **回滚安全网**：全部 S 系旗标缺省 OFF（volume_session/s4_static_freeze/
  session_pace_seconds/canon_audit.in_session/early_stop/review_confidence_vote/
  span 输出模式…）——关掉即回到改造前行为，prefix_lint 静态锁逐字节一致。
- **代码回滚**：仓库是 git（bench_queue 会自动 commit 产物）；主流水线改动
  出问题先 `git checkout app/` 再定位。
- **质量闸门**：盲评漂移 ≥-0.5 即该变体否决（S 轮 s3 的 D4 是唯一在册观察项）；
  埋雷召回（planted_defects 14 雷）用于评委灵敏度自检，不许全绿的评委直接采信。

## 9. 红线（不许做的事）

1. **不许污染用户 DS 官方控制台数据**（长测/盲评走百炼/TR/ocgo 链）；
2. **盲评不是产品功能**——它是优化工作的测试手段，不许塞进 app；
3. **E3 假设不许驱动决策**；单点复测不许外推成规律；
4. **不许在 tr-dsv4f 上跑 effort 敏感实验**（剥参，口径失真）；
5. **不许中途（卷中间）换渠道**；不许静默换渠道（看板必须留痕）；
6. **不许改主流水线代码绕过测试失败**——失败是数据，不是障碍；
7. **不许把 `tests/test_5ch_e2e.py` 加回全量跑**——真机件（46-61 笔真实调用），
   已加 `QIANBI_E2E_REAL=1` 环境变量闸（2026-09-07 事故：全量误触发真机跑 21 笔）；
   想跑真机 e2e 只许显式单独执行。全量基线：**825 passed / 1 skipped / 0 failed**
   （2026-09-07，`pytest tests/ --ignore=tests/legacy`）。
