## Wave B · 共写档成为主推（本轮的产品方向）

### B-1 默认档改共写
现状：`config.py:101 run_mode: "auto"`、`:107 gate_preset: "off"`；共写是**项目级粘性**（`state.cw.mode`，`co_writing.py:71 migrate_mode` 自述"与自动档完全隔离：只写 `state['cw']`，绝不碰 `state['stage']`"）。要做：
1. 出厂默认 `run_mode` 改 `"cw"`，**只作用于新装/新项目**（R17）；两档控件的默认选中、`SettingsPanel` 的启动档枚举、`CoachOverlay`/`demo_director` 新手第一屏、README 头条与截图**必须同步换**——否则界面说一套、首屏演一套（这是本指南从头到尾在抓的那类病）。
2. **自动档不删、不藏死**：它仍是批量补章/熟手路径。给出显式回退入口，且回退文案说清代价（少人工介入、门全放行时零确认）。
3. 共写成为默认后，**共写档的缺陷就是首发缺陷**：Wave A 的 A-6/A-7/A-9 优先级因此从"重要"升为"发布阻塞"。另加 H-5：`gate_preset=off`（出厂默认）+ 人工审校 ⇒ G8 返回空 ⇒ 落一条**伪「作者已放行」**、六维审校零执行——默认档换了，这个组合洞的踩中概率反而升高，本轮封死（组合非法就明确拒绝并指路，不要静默造凭据）。
4. Agent 能力面对齐：`UI_TOOLS` 现在覆盖共写 dock（去味/审校/落稿/回退阶段），自动档侧只有 `/` 指令与自然语言兜底——主推档必须拿到**完整的 Agent 行动半径**，包括 v3 里仍缓办的 4 支 Slot（`runCanonAudit`/`readFileText`/`validateCwOutlines`/`saveCwIdeaInfo`/`exportPreset` 中属于共写的）。
5. **H-12 优先修**：自然语言兜底链现在**双死**——`bridge.py:3810` 取永不存在的 `self.router`，`_ui_tool_dispatch:3824` 用未导入的全局 `agent_tools`（运行期证明名字不在模块命名空间）；兜底一旦复活就是 NameError → 叠加 C-1 = 进程消失。**共写主推会把用户推向这条链**，所以 B-1 之前或同批必须修。

### B-2 双向切换流畅性（用户点名要测）
1. **先审计再改**：把两种方向各自的"保留 / 丢失 / 被静默改写"列成表——`cw → 自动`：六阶段产物（立项/核心设定/总纲/世界书与正则/单元细纲/正文）能否被自动档 A1-A4 识别、断点在哪、`stage` 从哪续；`自动 → cw`：已生成的设定/细纲是否被共写档当作已完成阶段接管、会不会重问用户已有信息、已定稿章在共写档的可见性与可改性。这张表**交用户过目后再动手改**。
2. 切换必须有**确认感**（本轮主线）：切之前告诉你会发生什么、切之后有回执且留得回（归档/可撤销），失败不许静默改一半（对照 L2-04/L2-06 的处理法）。
3. `_cw_view`（回看历史阶段）与真实机器阶段的分离要保住：`bridge.py:1050/1290/3454` 这条线一旦在切换时错位，用户看到的对话就不是当前阶段的内容。
4. **离线夹具先行**：切换矩阵用夹具测（零钱、可重跑），覆盖 ≥8 个状态点（六阶段每一阶段 + 中途有定稿章 + 空项目）；**真实走查放 Wave C**（用 union-alpha）。
