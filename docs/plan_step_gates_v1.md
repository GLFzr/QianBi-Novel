# 改版计划 v1：步骤级确认门（Step Gates）— 人 AI 共写指挥台

> 目标版本：V1.0 前最后一个大改版。把「AI 自动跑 + 人事后审」升级为
> 「每一步都是决策点：人可看着产物、提想法、继续或回退重做」。
> 配套「中间共写窗口（Agent Console）」为远期目标，决策条输入框即其对话通道雏形。

---

## 1. 核心交互模型：每步一个"决策门"

流水线每一步完成（或每个决策点到达）后，暂停，弹出**步骤决策条**：

```
┌─ 决策门 G5 · 草稿完成（第 7 章）────────────────────────────┐
│ 产物摘要：3,214 字 · 开头：雨夜，陈默在便利店捡到那支钢笔…    │
│                                                                │
│ [想法输入]  ──────────────────────────────────────────────── │
│     （可选）对这一步的想法 / 修改意见 / 回退到某步的指令…       │
│                                                                │
│      [空]  + [继续下一步]   → 直接继续                         │
│      [有]  + [继续下一步]   → 带想法继续（想法注入下一步执行）  │
│      [有]  + [回退重做]     → 带想法回退（回到目标步重跑）      │
│                                                                │
│   回车=继续 ·  Ctrl+Enter=带想法继续 ·  R=回退（默认上一步）    │
└────────────────────────────────────────────────────────────┘
```

**三种决策语义**：
- **继续**：无想法 → 按原计划执行下一步。
- **带想法继续**：想法进入"执行指令队列"，注入**下一步**的执行上下文（如草稿前说"多用冷清氛围" → 注入草稿 prompt 的指令区）。
- **带想法回退**：回退到**上一步**（想法里可明确指定回退目标，如"回退到细纲，把第3章的坠落改成天台戏"→ 直接回到细纲步重跑）。

**配套规则**：
- 想法与正文产物分离：想法只进指令区，不污染正文输出。
- 想法可一键「存为正式想法」（沉淀到创作笔记/注入范围），也可即用即弃。
- 每个确认点可单独开关；关闭后该点自动通过（只记日志）。

## 3. 想法的流动规则

```
用户在门 G 输入想法 T
  ├─ 继续      → T 添加到 step_instructions[] → 下一步执行时注入
  ├─ 带想法继续 → 同上（与"继续说"的差别仅在 UI 语义，实际都注入）
  └─ 带想法回退 → T 作为重跑步骤的新增指令，回退目标优先取想法中的
                  "回退到 X" 声明，否则默认上一步
```

注入位置（现状代码对应）：
- 草稿生成：`stages.chapter_microcycle` 的 `prompts.PROSE_WRITING_PROMPT` → `user_ideas` 区（现已有 ideas 参数）。
- 细纲/大纲/设定：对应 prompt 的指导区（现已有 `指导` 通道，参考 `pending_guidance`）。
- 审校/去味：作为"人工裁决指令"（如"第3段不要改，我自己改"）。

**持久化**：`pipeline_state.json` 新增字段：
```
"step_gates": {"enabled": true, "hard": ["G2","G3","G5","G8","G9"], "soft": ["G1","G4","G6","G7"]},
"gate_status": {"gate": "G5", "chapter": 7, "pending": true},
"step_instructions": [...]   # 待注入指令队列（即用即清；可一键存为正式想法）
```

## 4. 回退语义表（含数据安全）

| 回退到 | 动作 | 数据安全 |
|---|---|---|
| A2 设定 | 重生成 设定/题材定位.md | 旧设定先归档 `设定/.bak/题材定位.md` |
| A3 大纲 | 重生成 大纲/大纲.md | 旧大纲归档 `.bak/`；**连带清空细纲**（提示确认） |
| B1 细纲 | 删除该批 细纲/N章.md → 重生成 | 被删细纲先归档 `pipeline_debug/rollback/` |
| C1 组装 | 重新读材料（含新想法）组装 | 无产出可损 |
| C2 草稿 | 重新流式生成草稿 | 旧草稿本未落库；若用户已手动保存则为**工作副本**，不覆盖 |
| C5 去味 | 还原为去味前版本重做 | 当前版保留在 `pipeline_debug/rollback/` |
| C6 审校 | 还原审校前正文 → 带指令重审/手动改 | 修改稿保留在 rollback |
| C7 定稿 | 回到 C6 状态，正文转工作副本（不产生新版本） | 版本历史不受影响，可继续回退 |

**通用规则**：回退重跑前一律对将被覆盖的产物做一次快照归档，路径
`pipeline_debug/rollback/<gate>_<chapter>_<时间戳>/`，回退链无限。
正文类已有 `.versions` 体系加持，双保险。

## 8. 阶段 3 设计稿：跨章想法沉淀（T4.2 实施依据，2026-08-28 补）

### 8.1 现状与缺口

想法管道已有：`state['pending_ideas']`（结构化条目 id/text/status/scope/ts）+ 面板管理
（NotesPanel：列表/编辑/删除/标记已应用 ↔ bridge ideasList/updateIdea/removeIdea/markIdeaApplied）
+ 注入通道（章循环 take_ideas → 草稿 prompt user_ideas）。缺口：**「通用」想法是一次性消费**
（take_ideas 注入后即标 applied），跨章灵感无处沉淀。

### 8.2 注入策略（本稿核心）

| scope | 注入行为 | 消费方式 |
|---|---|---|
| `next`（默认） | 下一章草稿注入一次 | 自动标记 applied（现状不变） |
| `通用` | **每章草稿持续注入**，不自动消费 | 面板「✓ 标记已应用」或「× 删除」手动收口 |
| `N`（数字） | 第 N 章草稿注入一次 | 自动标记 applied（现状不变） |

- 「通用」语义升级（v0.13）：由「一次性」改为「持续注入」。旧项目升级后原「通用」想法
  从一次性变为持续，属想法沉淀特性的预期行为；停止注入 = 面板手动收口。
- 门想法（G4/G6/G7/G8/G5L/G2/G9 的即用即弃想法）不进本库，仍走门通道（见 §3）。

### 8.3 实施清单

1. `state.py take_ideas`：`通用` 分支只注入不改状态；`next`/`N` 保持一次性（GUI/TUI 双端同步）。
2. 面板：NotesPanel 徽章文案「待应用·通用」→「持续注入·通用」，明示新语义（管理按钮复用现有 ✓/×）。
3. 单测：通用想法跨两次 take 持续注入；「标记已应用」后停止注入。
4. 决策记录：想法在章间的应用照旧由日志承载（不新增文件格式，守红线 #3）。

### 8.4 验收

- 通用想法连续 ≥2 章注入后仍 pending；面板 ✓ 后下一章不再注入。
- `next`/`N` 一次性语义无回归（原用例全绿）。

## 7. 风险与边界

- 回退重跑 = 额外 token/时间 → 回退前弹确认并显示预期成本提示（"重跑细纲约 160s / 约 X token"）。
- 逐步模式拖慢长跑 → 提供「本批次忽略后续门」（当前章剩余门全跳过）/「全书忽略」按钮。
- 卡死在门上的兜底：Esc 可放弃当前门（按"继续"处理）并记日志；异常时门自动放行（不阻断流水线，仅告警）。
- API 无流中注入 → "带想法继续"对**已在执行中**的步骤不生效，只对**即将开始**的步骤生效（这是"逐步确认"模式天然规避打断的收益）。
