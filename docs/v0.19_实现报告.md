## 一、实现清单（三包全量）

### 第一包：缓存 bug 修复
1. **`{chapter_header}` 占位符落地**（此前 7 处传参、0 个模板使用，第二层前缀从未上线）：
   PROSE / ENRICH / TRIM / DESLOP / TRACKING / CH_SUMMARY / G_SUMMARY / FINAL_REVIEW / REVIEW_FIX
   全部改为 `[project_header][chapter_header][阶段体]` 三段式，散装的细纲/状态/摘要/上一章锚点段
   收敛进章头（八节：细纲/全局摘要/近章摘要/角色状态/时间线/待回收伏笔/上一章结尾/上一章开头），
   截断取各消费方上限最大值，信息只增不减。追踪阶段的**全量伏笔表**保留（数据完整性红线）。
2. **outline 系接前缀**：CHAPTER_OUTLINE 重构为「静态方法论文+动态尾」，
   逐批变化的记忆锚/承接现场/世界书激活条目全部后置；VOLUME_OUTLINE / CORE_SETTING 接项目头。
3. **审校投票重排**：首票单发（写缓存/会话固化）→ 其余票并行重采样（副本票以首票请求
   快照下发，不进会话正史）；早停移除（v4 thinking 忽略 temperature，票间必不同构）。
4. **review_fix 接双层前缀**（单轮路径），bridge 定向修复同款对齐。
5. 顺手修复：设定清算日志的 `r.get` 潜伏 NameError（变量早已改名 audit）。

### 第二包：章会话消息栈
- `app/core/chapter_session.py`（新）：一章一个会话，system=双层稳定前缀；
  ask/commit_turn/snapshot/rollback_to/restart_with_prose；
  `client=` 覆盖保留各阶段槽位路由，`postprocess=` 保证历史正文与 clean 后一致。
- `LLMClient.chat_turn`（新）+ `_stream_messages` 抽取（chat_stream 行为逐字节不变）；
  阶段接线：prose→(enrich|trim)→deslop→审校票→review_fix→复检→tracking→摘要链，
  追加轮自动剥两层前缀、`{prose}` 换历史引用、带作用域声明行；
  G6/G7/G8 回退与「修复稿否决」场景同步 `rollback_to` 截断历史，保证
  「最近一条章正文消息」永远指向实际正文。
- canon_audit 与 outline 保持单轮（设计内）。配置键 `writing.chapter_session`（默认开，可关回退）。

## 四、已知现象（非缺陷，已定位）
1. **缓存注册延迟税**：上一响应落盘后 ~30-60s 内发出的快速小调用（enrich/deslop 紧跟 prose）
   可能整笔 miss（v4 异步落盘，实测 enrich 34.5%、部分 deslop 首轮偏低）。
   可选缓解：微循环排序把长调用插在中间；当前量级（每章 1-2 笔、每笔 ~$0.005）不值得动语义。
2. **canon_audit 每章重试 3 次取首个可解析响应**（前缀缓存下重试近乎免费；留档观察）。
3. **会话内 prose 首调 hit≈14%**：章级八节段逐章必然不同，属结构性冷调；其字节由该章
   后续全部调用复用（trim/deslop/审校票 86-100% 命中即证据）。
4. run_mode=cw 下章会话与共写互不影响；会话跨槽位路由语义成立，仅缓存收益限同模型。
