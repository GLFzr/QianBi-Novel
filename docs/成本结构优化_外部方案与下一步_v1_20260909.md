## 0. 先换尺子：三条从我们自己价表推出的定律

1. **命中价不是免费价。** 命中/未命中 = 0.0504/1.584 = **1 : 31.4**。
   第 53 章我们读 4.29M tok、hit 96.2% ⇒ 拆账 **hit 部分 ¥0.21（44%）+ miss 部分 ¥0.26（56%）= ¥0.466/章**。
   ⇒ "命中"只把每百万 token 从 ¥1.584 压到 ¥0.0504，**体量本身仍然是钱**；敌人是"被重读的历史体量"。
2. **入栈一次优于每章现贴**，只要这段文本将来被读 **≥1.04 次**（31.4 分之一）。
   ⇒ **去重只能发生在"追加那一刻"**；任何"回头删栈/改历史"都要把其后缀按 miss 重付
   （外部给的盈亏式：删 E tok 换 N 次复利，需 `E×N > 30.4×T` 才划算，栈中段永远亏）。
3. **命中率是一阶变量**：hit 96%→99% ⇒ 整章读账 **¥0.466→¥0.282（−39%）**，
   同样 3 个百分点，比砍掉一半思考预算更值钱。⇒ 明天先修"命中率的可解释性"，再砍量。

## 1. 战略分叉：长栈累积 vs 每章重建 —— 由一个尚未测的量决定

| 方案 | 第 53 章读账（hit 96%） | 备注 |
|---|---|---|
| **A 现状**：卷栈单调增长（416k 深） | 4.29M tok ⇒ **¥0.466/章** | 复利来源；命中率越高越便宜，但体量线性膨胀 |
| **B 每章重建** 60k 稳定头 + 章内 12 相位累积 | 12×60k 命中 ¥0.036 ＋ 本章新增 ~35k 首贴按 miss ¥0.055 ⇒ **≈¥0.09/章** | 省 ~5 倍；栈不再增长 ⇒ 无复利 |
| | 若 60k 头**只能命中 32k**（单元粒度=32k） ⇒ 12×28k×1.584 ≈ **¥0.53/章** | **比现状更贵** |

⇒ **B 成不成立，全看服务端缓存单元的落盘粒度**。这恰好也是我们解释不了的那个量的同一件事：
**每章章界固定 ~32k tok 被按未命中重计价**（哈希证明我们发的前缀字节没变）。

### 决定性实验 E0：单元粒度探针（零改代码，¥2-4，明早第一件事）
拿第 53 章那 416k 字节，**同一会话内**按前缀长度 8k/16k/24k/32k/48k/64k/128k/256k 各发一次
（问题尾巴固定，只截前缀），记每发的 `prompt_cache_hit_tokens` 与 miss。工具现成：
`scripts/replay_request_probe.py` / `scripts/cache_depth_probe.py`。
- 判据：若 miss 台阶**只出现在 32k 的整数倍** ⇒ 单元粒度=32k ⇒ 路线 B 作废，主攻方向改成
  "让每章新增落在 32k 边界内 + 减少重读体量"；
- 若 miss 与"我们截断的长度"无关、只与"上次请求末端"有关 ⇒ 支持**今晚 W-8 假设**
  （见 §2.1），路线 B 直接可做，预期 ¥0.46→¥0.10 量级。

## 2. 输入侧（命中/未命中/复利）清单

### 2.1 🔬 W-8 已装仪器：我们存进栈的可能不是模型原始字节（今晚已落代码）
一手依据：DeepSeek kv_cache 文档——单元在「**模型输出末端**」落盘，且命中要求
**逐字节完整匹配**某个已落盘单元（官方明写"尽力而为，不保证 100%"）。
我们的 `VolumeSession.ask` 固化的是 `postprocess=clean_llm_output` **之后**的文本
（无条件 `.strip()` + 剥代码围栏）⇒ 与服务商缓存的原始字节可能差一个换行/围栏。
一个换行的差异就足以让**该单元之后全部不吃缓存**，同时"原样重放同一串字节"仍然 99.9%——
**这是目前唯一能同时解释这两个现象的假设**。
- 仪器：`session_events.jsonl` 事件 `turn_cleaned{vol,gen,chapter,phase,delta,raw_sha,kept_sha}`；
- 明天看 `metrics["session_events"]`：`turn_cleaned.n > 0` ⇒ 假设成立，
  改法＝**固化原始字节，清洗只用于下游工作副本**（一处改动，`volume_session.ask`）；
  `n = 0` ⇒ 假设否证，回到 §1 的粒度解释。**别在数出来之前动手。**

### 2.2 相位指令只在当轮有效，不要落栈（业界叫 turn-scoped instruction / clear_at）
出处：[Claude mid-conversation system messages](https://platform.claude.com/docs/en/build-with-claude/mid-conversation-system-messages)
——指令写成 system + `clear_at:"next_user_message"`，下轮起**不渲染、不计 input token，但消息留在原位
因而前缀缓存继续命中**（官方明确：真删会让后续失效）。OpenAI 侧同原语：Agents SDK 的
`session_input_callback`（注入但不持久）。
- 我们的等价做法（渠道没有这个参数也能做）：**同相位指令体只在首次落栈，后续章落一行"（指令同上）"**。
  量具已给出靶子：清算审计轮 6,269 字/章（91.8% 重复）、tracking 请求 4,065（95.1%）、
  去味 953（75.3%）——这些重复的**主体就是重复的指令与台账，不是数据**。
- 预期：−9～10k han 字/章 ≈ 6k tok/章入栈量 ⇒ 栈增速 −21%，按 ×95 复利这是第二大单项。
- 风险：模型后续章看不到"当初怎么问的"→ 引用行必须写明"指令见第 N 章同一相位"，并配一次真机盲评。

### 2.3 章头分节去重（②-d，今晚已定性为"必须 A/B"）
两跑次同形实测：全局摘要 1,292～1,692 字/章（重复率 **94.6%～100%**）、伏笔 619～855、
时间线 404～519、角色状态 573～999；而**本章细纲 3.2k～3.9k 字/章重复率仅 1.7%～6%（真新内容）**。
关键反证：**这五节是 S4-b 当年刻意保留做 recitation 的**（防长历史后注意力衰减），
且 Manus 同款做法（`todo.md` 复述抗塌陷）明确说这类复述**该留**（约 0.5～1k 字/章是锚，不该砍）。
⇒ 只做**"整节逐字节未变才换引用行"**（t1_long20 的全局摘要是 100% 未变的典型），
旗标 `writing.s4_header_dedupe` 默认关；判据＝盲评 D3/D4/D5 与伏笔回收不掉。

### 2.4 别碰的两件事
- **system 任何字节变化 = 从该处起全栈失效**：社区一手案例——工具数 26→25，命中率 97%→11%
  （[deepseek-harness#935](https://github.com/deepseek-ai/deepseek-harness/discussions/935)）。
  我们已把"逐章会动的东西"移出 system，**任何新功能想进 system 前先问它是否全书恒定**。
- **设定要改别改 message 0**：DeepSeek 接受 messages 任意位置的 system 且**以最后一条生效** ⇒
  可把更新 append 到栈尾而不破前缀（需在我们渠道上自验一次才可用）。

## 3. 输出侧（真金白银最集中的一节）

### 3.1 重写/修复相位改「SEARCH/REPLACE 整段块」——同时砍输出桶和入栈桶
一手量化：[Output Format × Model Identity](https://arxiv.org/abs/2607.21674)（3 模型×3 格式×4013 次实跑）
**DeepSeek V4：unified/search-replace 66% vs full-file 35%**（n=120，p<0.001）；
[aider 排行榜](https://aider.chat/docs/leaderboards/) polyglot 上 DeepSeek 该格式合规率 **97.3–99.6%**；
[AdaEdit](https://arxiv.org/abs/2604.27296) 长例子集输出 648→547 tok 且**准确率反升**。
⇒ 我们那个"每章正文在栈里 3.9 份"（实测 94 条章稿轮/24 章）只有一次换格式的解法：
**不重生成整章**（§2.2 的定律 2 已排除"事后删旧稿"）。
- 落地：**程序侧四级匹配**（exact→去空白→保缩进→difflib 模糊）＋**失败只重发失败块**；
- ⚠️ **格式决策权不能交给模型**：AdaEdit Table 10 实测 DeepSeek-V3.2 自选格式**选对率 25.34%、
  57.85% 干脆不产生任何改动**；
- ⚠️ **分通道**：同一研究显示 Qwen 3.7 Max 是 full-file 50% > diff 36% ⇒
  **百炼 flash 通道保留整章输出可能才对**，必须按渠道分别测，不能一处改全局；
- ⚠️ 章很短（2-3k 字）时 diff 的锚点开销会反超整章输出 ⇒ **必须加门限**：
  改动段数/总段数 > ~0.4 就走全文重写。这也说明 span 的**回退率**是这条路的第一判据
  （至今 `span_stats.jsonl` 盘上一个都没有）。

### 3.2 审校引证改「引用块」而不是抄原文
出处：[Anthropic Citations](https://platform.claude.com/docs/en/build-with-claude/citations)——
把正文切成 content block，模型只输出 block/区间，**cited_text 不计输出费**，且切片必为真
⇒ **构造性地消灭假引文**，我们现有的逐字验真退化成越界检查。
我们已有 ⟦Pnn⟧ 段号，**但段号属最弱的 number-indexed 类**（AdaEdit：14～38% vs
内容寻址 46～54%）——**用在"写"上是坑，用在"指"上是够的**（引用只需读地址）。
⇒ 票面格式改成「维度 + verdict + 段号区间 + ≤30 字理由」，引文由程序按段号回填。
预期：票输出 1,511→~700 tok/票（P0 已实现一半），且**票内复述彻底归零**（票整章回声那 7.5k 字/章）。

### 3.3 台账用 JSON Patch，正文永远别用 JSON 包
[PatchBoard](https://arxiv.org/abs/2605.29313)：schema 约束的 JSON Patch 替掉 agent 对话，
**84.6% vs 30.8%，token/成功任务 368.3k→45.5k（8.1×）**。
但正文侧 [aider 实测四个前沿模型 JSON 包代码全掉分、strict 无救](https://aider.chat/2024-08-14/code-in-json.html)。
⇒ 我们挂起的 `TRACKING_PATCH.context` 全文字段（633 han 字/章，不值钱）真正的解法是
**台账按 schema 打补丁**，而不是砍这个字段；正文侧走 §3.1。
约束解码现状（已核）：DeepSeek 只有 `json_object` 且**自陈偶发返回空 content**（我们踩过的坑）；
百炼有 `json_schema strict` 但仅部分模型；`predicted_outputs` 两家都没有。
DeepSeek 唯一可用杠杆：**chat prefix completion（beta，`prefix:true`）预填协议壳、掐尾部回声**。

### 3.4 思考预算：软指令不算控制，且"该不该想">"想短点"
- 各家 effort/`budget_tokens` 官方口径全是**软目标**（OpenAI/Anthropic/Gemini 文档原话），
  与我们实测"low/high 思考量只差 1.06×"自洽；**唯一硬帽是 DashScope 的 `thinking_budget`**
  （覆盖 Qwen3.5-3.8 系与阿里直供 GLM/Kimi，且与 effort 互斥、有档位映射表）。
  ⇒ 我们的 `prose.think_budget=6000` 是软提示，**服从度必须报数**（实测中位 >0.8×预算即撤）；
  真硬帽只在百炼的 Qwen 通道上有，那是"换模型"，另案。
- 预算服从曲线：0-256 高效、>512 才谈高精度（[2508.12140](https://arxiv.org/abs/2508.12140)）；
  "值不值想"由**任务结构**而非名义难度决定（[The Reasoning Tax](https://arxiv.org/abs/2608.26235)）。
- Chain-of-Draft/CCoT 这类"写短点"**只省可见输出，对隐藏 reasoning 无杠杆**，且证据全在数学/编码
  短答案 ⇒ **不要用在审校/清算这类闸门相位**（我们自己的 E9' 已有同类反例：关推理→59% 引文不实）。
- **`reasoning_content` 回传会被忽略、不进上下文** ⇒ 卷栈与跨相位**绝不要把思考稿写进栈**。

## 4. 投票与级联（降票的判据终于有了）

- SC 原论文增益在 5-10 票吃满，**k=3 落在低收益段**（[2203.11171](https://arxiv.org/abs/2203.11171)）；
  [Adaptive-Consistency](https://arxiv.org/abs/2305.11860)：熵+95%CI 早停，**省 7.9× 样本、精度损失 <0.1%**，
  纯 API 可实现；[DSC](https://arxiv.org/abs/2408.13457) 先 4 题定难度，易题 1 票，**成本 −65%**；
  [TrACE](https://arxiv.org/abs/2604.08369)：拿"rollout 间一致率"当**免费**算力信号。
  ⇒ 今晚的 `metrics["vote_iso"]` 就是这条路的第一块数据。
- **明天该看的三个数与建议阈值**（外部阈值 × 我们的埋雷硬闸）：
  1. `iso_pct`（等级向量同票率）：**<10% 维持 k=3；10-30% 只在预筛命中章 k=3、其余 k=1；>30% → k=1**
     并改做票间差异化（rubric 顺序/persona/取证窗口——**别提温度**，温度在思考模式下被静默忽略）；
  2. **第 2/3 票的独家埋雷命中数**（只在 disagree 章统计）：<1 雷/20 章 ⇒ 降 k=2 + **5% 无条件全量抽检**；
     两票都 <1/20 ⇒ k=1 + 抽检。**召回硬闸（B01/B02 ≥1/2）优先于省钱结论**；
  3. **终审 low↔high 的裁决翻转率**：≤5% 且零新增漏判 ⇒ 降档（97.3% 的思考 token 挂在这一个开关上）；
     >15% ⇒ 保 high，但改成"命中可疑才送 pro"。
- **级联的结构性反例（必须记住）**：上游漏检会被下游放大且无从复核
  （[MAS 失败模式 1600 trace](https://arxiv.org/abs/2503.13657)；[RLM-Cascade](https://arxiv.org/abs/2606.22840)
  的收益**只在可自动验证的编码/数学上成立**）。⇒ 预扫必须有 **5-10% 无条件全量抽检**给 recall 设下界，
  否则"降票/降档"的所有账面数字都建立在漏检不可见之上。
- 关于"并行副本会不会各付一次全价"——**调研给的这个担心已被我们自己的数据否证**：
  8 个在册变体按同请求体成组，**副本票 miss 138～425 tok，首票 3.1k～7.6k**（后发更便宜）
  ⇒ 现行"首票单发写缓存 + 副本并行"是对的，不要串行化。

## 5. 渠道：有一笔钱不在代码里

- **峰时价 ×2**（工作日 9-12、14-18 北京时间，三桶同时翻倍，[定价](https://api-docs.deepseek.com/zh-cn/pricing)）。
  **明天是周四**：若 V7+think_budget 排在上午 9 点后，¥41-50 直接变 **¥82-100**。
  可用离峰窗口：00:00-09:00、12:00-14:00、18:00-24:00。
- **命中率 90.2% 是与"一口价渠道"的盈亏平衡点**：读价 = h×0.0504+(1−h)×1.584 = 0.20 ⇒ h≈90.2%。
  我们整跑均值 94-98% ⇒ 官方 DS 仍打得过 TokenRhythm 一口价；**但低命中章/低命中的 omen 段反之**
  ⇒ 可做"低命中相位导给一口价渠道"，前提是先有分渠道命中率报表（W-5 已给口径）。
- **盲区（没回 `prompt_tokens_details`）多半是"换了上游"而不是"吞了字段"**：
  opencode 源码级案例——`stickyId` 只在 catalog 配了 `stickyProvider` 时生效，否则
  `hash(stickyId) mod 当前权重池`，**池长随 TPM/预算实时变** ⇒ 同一字节打到不同实例
  （[anomalyco/opencode#48116](https://github.com/anomalyco/opencode/issues/48116)、
  [#35402](https://github.com/anomalyco/opencode/issues/35402) 同字节 10 次命中 0/19328/0/10…）。
  ⚠️ 同一族还有 **`adjustCacheUsage` 的 90% 估算兜底 ⇒ 有些渠道报的 cached_tokens 是合成的假数**，
  不能当决策输入。**结论：官方渠道原生 `prompt_cache_hit/miss` 作真值，中转渠道数字只做对账。**
- **百炼显式缓存（`cache_control:ephemeral`）对我们有害**：要求整条请求逐字节相同（连问题也算）、
  创建 125%、TTL 5min 不续期 ⇒ 我们每章都变＝永付创建费。隐式（1024 对齐）才是对端口。
  百炼唯一可用杠杆：`n`（1-4，仅 Qwen 非思考）把三票并成一发预填充。
- 服务层技巧（vLLM APC/SGLang RadixAttention/Mooncake/CacheBlend 的"非前缀内容分块复用"）
  **对走 API 的我们一概拿不到**——这恰是我们那 60% 重复行最想要的东西，只能在**入栈前**去重。

## 7. 明确不做（含本轮被否证的）

| 不做 | 理由（含出处） |
