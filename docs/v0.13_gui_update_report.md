## 1. 背景与目标

### 1.1 项目背景

`qianbi-novel`（GUI）和 `qianbi-Novel-TUI`（TUI）是**同源双端**项目：
- **业务核心共享**：`app/core/`、`app/llm/`、`app/prompts/`、`app/project/`、`app/presets/`
- **数据零迁移**：`pipeline_state.json`、`.versions/`、`.annotations/`、`~/.qianbi_novel/config.json` 双端可读
- **可同书交替使用**：用 GUI 创建项目后用 TUI 打开，反之亦然

### 1.2 为什么做这次升级

经过 12 个子代理的全量对比分析，识别出 TUI 在以下 31 项优于 GUI：

| 类别 | 数量 | 代表功能 |
|---|---|---|
| 题材预设 | 5 项 | 10 套 v2 / v2 分环节 / 独立预设库 / grow_block 参考块 |
| 审校体系 | 6 项 | 6 维审校 / 根因溯源 / 反馈环 / 传染链 / REJECT-HARD / ReviewIssueModal |
| 场景卡 | 4 项 | 6 类卡 / 中文关键词 / render_cards / hint_for_chapter |
| UI/UX | 8 项 | 3 主题 / 命令面板 / F1 帮助 / D14 外部驱动 / SVG 快照 / 输入历史 / LoadingIndicator / 窄屏降级 |
| 可脚本化 | 3 项 | headless / cmd.json 协议 / 17 action |
| 数据兼容 | 2 项 | 数据零迁移 / 跨项目兼容 |
| 端能力 | 3 项 | SSH 远程 / 真机回归 / Pilot Test |

本次升级目标：**将 10 项核心功能完整移植到 GUI 端**，使 GUI 在核心能力上**对齐甚至超过 TUI**。

### 1.3 不移植的内容

经过评估，以下功能**有意不移植**（与 GUI 端场景不匹配或价值低）：

| 功能 | 不移植原因 |
|---|---|
| `cmd.json` 外部命令驱动 | GUI 已有完整 UI 控件 + Qt 自动化测试基建 |
| headless 模式 | GUI 用户通常需要可视化 |
| D14 自动化驱动 | GUI 用 `tests/ui_drive.py`（UIA + PostMessage）已覆盖 |
| 输入历史 ↑/↓ | 共写档 Input 已自带 IME 兜底 |
| 窄屏降级 | GUI 默认窗口 > 110 列 |

| 评估角度 | 关键风险（修订前 → 修订后） |
|---|---|
| **架构** | R1 v1→v2 JSON 同 id 静默升级 → 加 `_migrate_v1_to_v2`；R2 `_chapter_review` 返 2→3 元组破坏 2 处解构 → 同步改；R3 6 维审校 REJECT 阻塞流水线 → 异步化 + 3 轮熔断 |

#### 3.3.4 升级 `app/ui/qml/Theme.qml`（3 主题 Singleton）

**挑战**：Theme.qml 是 `pragma Singleton`，QML Singleton 不能动态切换。**解决方案**：
- 内置 3 套色表 `_themes` dict（`qianbi_night` / `qianbi_parchment` / `qianbi_plain`）
- `property string _active` 缓存当前主题名
- 所有 `readonly property color` 改用 `_pick(name)` 函数从 `_themes[_active]` 取色
- `setActive(name)` 由 C++ Bridge 在 `themeChanged` 信号触发时调

**主题切换路径**：
```
Ctrl+T 快捷键 / SettingsPanel 按钮
    ↓
bridge.setTheme("qianbi_parchment")
    ↓
Bridge 写入 cfg.ui_theme + 发 themeChanged 信号
    ↓
Main.qml Connections.onThemeChanged → Theme.setActive(name)
    ↓
```

## 6. 关键设计决策

### 6.1 v1→v2 JSON 兼容性

**问题**：现有 GUI 项目中 `urban_destiny.json` / `cultivation.json` 是 v1（无 stage_hints），TUI 端是 v2（有 stage_hints）。

**决策**：直接覆盖（用 TUI 版）。`load_preset()` 加 `_migrate_v1_to_v2(data)` 兜底：
- 若 `version >= 2`：原样返回
- 若 `version == 1` 且无 stage_hints：把 `style_hint` 塞入 `stage_hints["prose"]`，加 `_v2_migrated=True` 标记
- 升级后第一次切预设时**自动**走 v1 fallback（`genre_block` 全量注入），用户无感

### 6.2 scene_cards 注入位置

**问题**：TUI 端 `scene_cards.py` 已有但 `stages.py` **未注入主线**（key finding from 评估阶段）。

**决策**：注入到 `CHAPTER_OUTLINE_PROMPT`（细纲阶段）而非 `PROSE_WRITING_PROMPT`（正文阶段），原因：
1. 细纲阶段先定型"主卡+子卡"，正文阶段引用细纲的卡片信息
2. 不展开 `example` 避免 prompt 膨胀（1300+ 字符 → 1 行）
3. 中文关键词独立字典（`_KEYWORDS`），路由优先级 `payoff > battle > emotion > dialogue > mystery > lowkey`

**输出**：
```
## 本章主卡：战斗｜子卡：日常
```

### 6.3 6 维审校反馈环异步化

**问题**：TUI 的 `_review_feedback_loop` 是同步递归，会阻塞 orchestrator 主线程。

**决策**：
1. `chapter_microcycle` 内部维护 `review_rounds` 计数
2. 第 1 轮：直接 `REVIEW_FIX_PROMPT` 修复
3. 第 2+ 轮：先调 `ROOT_CAUSE_PROMPT` 根因溯源，再修复
4. 3 轮不收敛 → 调 `mark_chapter_need_human()` 标 human，**不阻塞**后续章节
5. 流水线内每次 `_chapter_review` 都把 verdict 写到 `state["review_findings"]`

**优势**：
- 流水线不阻塞（用户不在场也能继续）
- 人工介入路径清晰（看 `chapter_need_human` 字典）
- ReviewIssueDialog 可在 reviewIssuesChanged 信号时弹出供用户选 A/B/C

### 6.4 Theme.qml 3 主题切换

**问题**：Theme.qml 是 `pragma Singleton`，QML Singleton 不能动态切换 readonly properties。

**决策**：间接切换
- 内置 3 套色表 `_themes` dict
- 所有 `readonly property color` 改用 `_pick(name)` 函数（每次访问查 `_themes[_active]`）
- `setActive(name)` 由 C++ 端在 `themeChanged` 信号时调
- QML 端所有 `Theme.bgPage` 等访问**自动**走最新色

**优势**：
- 保持 Singleton 兼容性（所有现有 QML 代码 `Theme.bgPage` 不变）
- 切换瞬时（不重建组件）
- Ctrl+T 全局快捷键

### 6.5 反馈环 vs 端到端测试

| 决策 | 理由 |
|---|---|
| mock 测试在前（30s） | 快速验证状态机逻辑，无 LLM 成本 |
| 真实测试在后（18.7min） | 验证 prompt 渲染、API 调用、超时重试 |
| 不强行 REJECT 触发 | 真实 DeepSeek 倾向给 PASS_WITH_NOTES，3 轮熔断未触发是好事 |
| 失败熔断 ≥2 章 | 真实跑失败自动停止并落 issues.md |

## 7. 风险与缓解

| 风险 | 等级 | 缓解 |
|---|---|---|
| v1→v2 JSON 同 id 静默升级 | 🟡 中 | `_migrate_v1_to_v2` 自动迁移 + 用户目录优先 |

| 真实 LLM thinking 模式空流 | 🟢 低 | 沿用 `llm/client.py` 的"空流关 thinking 重试" |
| 5 章 e2e 真实 LLM 调用有 rate limit | 🟢 低 | 5 章量小（48K token），无 429 风险 |
| `Theme.qml` Singleton 不能动态切 | 🟡 中 | 用 `_pick(name)` 函数 + `_active` 缓存间接实现 |
| 反馈环在重 UI 期间可能双触发 | 🟢 低 | orchestrator 走单线程主循环，事件总线串行分发 |
| Bridge 2682 行→2950 行不易维护 | 🟡 中 | 当前不拆（拆的风险大于收益），下一版可拆 `bridge_presets.py` / `bridge_review.py` |
