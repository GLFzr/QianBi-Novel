# 0.23.0 全量实测计划（预注册版）

- **模型/通道**：OpenRouter `stealth/space-bunny-alpha`（连接级 `stream: false` 非流式，C44 开关）
- **被测对象**：0.23.0 试验版工作区（qianbi-novel-0220exp，0.22.0+0.23.0 全部 60+ 卡）
- **对照基线**：0.20.1（最后一次真实长跑 = T3 v1，69 章，基线架构——T3-1 三根因即出自它）
- **纪律**：本文件为预注册判据——测试开始前锁定，测后按此评分，不允许事后改判据。

---

## 一、测试目的（为什么测）

1. **回归**：0.20.1 → 0.23.0 的 60+ 卡增量，在真实模型+真实长篇工作流下不破坏原有功能。
2. **有效性**：新机制（章纲合同化/账本六册/状态卡/度量层/review2/写作规约）在真实生成里真的运行并落账。
3. **防御力**：0.23 护栏（G1 断路器/G3 暂停/G4 看门狗/G5 告警/预算宪法/压缩保链断言）能拦住 T3-1 型真实故障。
4. **模型兼容**：对未见过的模型（stealth 系）开箱即用——验证「合同化+校验」路线的模型无关性。
5. **成本量化**：真实 tokens/次数/时长/估算费用，为正式轮预算提供数据。

## 四、测试阶段与内容

### Phase 1 共写档（先测）
- **驱动**：offscreen QGuiApplication + Bridge 实例（probe_update_ui 先例），脚本按序驱动共写 Slots；连接 stream:false。
- **步骤**：开项目 → ①核心设定 → ②大纲 → ③世界书 → ④单元细纲（合同化）→ ⑤正文生成 → ⑥supervisor 比对/审校 → 锁定；过程中插入：一次写作规约沉淀、一次「跳过比对并锁定」（F1 出口）、一次改写派单（F2）。
- **采集**：每阶段产物存在性与字数、LLM 调用次数/tokens/时长（gen_trace+usage）、状态卡内容、账本落账、指标值、toast/护栏事件。

### Phase 2 全自动档（后测）
- **驱动**：tests/long_run.py（同项目续跑，QIANBI_TEST_COST_STACK=1），3-5 章。
- **采集**：逐章——章纲合同解析结果（17 字段齐备率）、大纲覆盖拒收触发、草稿字数达标、G1/G2 触发、deslop 45 规则命中与 14 指标、审校 review2/retry、finalize 六册落账、G4 看门狗、成本。

### Phase 3 护栏专项（注入式）
- G1：用假 client 注入 10 倍稿→断言跳过后链；预算宪法：低配 gen_budget→熔断+回执；G4：模拟缺记账→看门狗暂停。（假件注入，不烧真钱）

### Phase 4 静态终验
- 全量 pytest / check_docs / dep_graph（SCC=0/39/49）/ probe 套件 / offscreen 冒烟。

## 五、预注册判据与量化（测后按此评分，不得改判据）

### 5.1 结构完成度（每阶段布尔）
阶段①-⑥产物存在且非空 = 通过。共写六阶段 6/6、自动档每章 7 段全走 = 满分。

### 5.2 机制有效性（量化）
| 机制 | 判据 | 量化 |
|---|---|---|
| 章纲合同化 | parse_directive 成功且 9 必填齐备 | 齐备率 ≥80%（N 章统计） |
| 大纲覆盖拒收 | 无缺失=不误触发；有缺失=拒收带清单 | 误触发=0 |
| 六册落账 | 设定/读者认知/伏笔(+advances)/爽点/钩子/事实 各 ≥1 条真实数据 | 6/6 |
| 状态卡 | 七栏齐备、预算 ≤12288B | 逐章 |
| 度量层 | 14 指标逐章产出 | 覆盖率 100% |
| 45 规则 | 千字命中密度 | 对照真人 700 章基线比值（记录，无硬阈） |
| 写作规约 | 沉淀 ≥1 条+下章注入命中 | 2/2 |

### 5.3 护栏防御力
| 护栏 | 判据 |
|---|---|
| G1 | 若真实触发：断路后零后续 LLM 调用（token 审计）；未触发不扣分 |
| G2 | 全程截断稿=0 进闸门 |
| G3/G4 | 触发须带章号与原因；未触发不扣分 |
| 预算宪法 | Phase 2 每章消耗 ≤147k tok；超限必熔断（Phase 3 注入验证） |
| anomalies | 全程条目均可解释 |

### 5.4 质量与成本量化
- 字数达标率（±15% 带内章数/总章数）≥80% 为理想；
- 成本：逐章 tokens（prompt/completion）/调用次数/耗时/估算费用（OpenRouter 价目）；单章成本与 T3 v1（deepseek ¥0.25/章）对比记录；
- 稳定性：全程崩溃=0；失败必须有 failure 现场。

### 5.5 评分卡
每阶段 0（失败）/1（完成但有缺陷）/2（理想），加权：共写 25% + 自动 35% + 护栏 20% + 质量指标 20%；总分 ≥80% = 达到「前所未有的成熟度」实测标准；60-80% = 带缺陷可用；<60% = 不达预期（逐项归因）。

## 六、缺陷处置规则

- **不阻断**（文案/格式/指标越界/单测偶发）：记录进报告「缺陷清单」，不修。
- **阻断**（管线失败/数据损坏/账本错乱/崩溃）：立刻修，commit 注明「实测阻断修复」，修复后受影响阶段重跑。
