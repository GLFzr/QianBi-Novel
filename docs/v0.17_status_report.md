# 项目现状报告 · v0.17.0

日期：2026-09-04 ｜ 范围：v0.16.0 → v0.17.0 ｜ 作者：1 人 + AI 协作

一句话：**v0.16 之后功能已经齐了，这一版解决「看起来不像成品」**——以 ZCode 桌面端与
Apple 呈现方式为设计基准的全量 UI 成熟化：高级化（明度阶梯/发丝线/克制强调色）、
风格化（控件全自绘）、成熟化（三轮截图验收零硬伤）。

---

## 1. 设计基准（8 条，全程执行）

1. 明度阶梯造深度：bgPanel < bgPage < bgCard，相邻层差 ≥8/255（旧夜间主题仅 ~5，是「糊成一片」的根源）
2. 边界定律：一切卡片必带 1px hairline；弹窗 borderStrong + 全屏遮罩；禁止同色裸贴
3. 单强调色小面积：accent 只用于主按钮/激活态/焦点环/细进度条；语义色降饱和保色相，禁止大色块
4. 字阶 6 档（补 fsMicro=10 收编 52 处裸字号）、圆角 4 档、间距 6 档，全部走 token
5. 控件全自绘：AppSelect/AppSwitch/AppScrollBar 替换原生 ComboBox/系统箭头/默认滚动条
6. 空态是设计：图标 + 标题 + 弱说明，消灭死黑大区（预设库详情/审校 0 项/生成配置/项目文件）
7. 动效 100-150ms；emoji/字符图标全部换 AppIcon 线性图标
8. ApplicationWindow 全局 palette + 弹窗 overlay 遮罩，原生控件缝隙不再漏白

## 2. 最重要的一个根因修复：面板零边距（「中列遮挡」悬案告破）

用户长期报告「Console 中列在大多数功能页遮挡部分 UI，一直没解决」。实机测量证明
**Console 从未遮挡任何东西**：设置/流水线/笔记三个面板的 ScrollView 内容写了
`Layout.margins: 12`，但 ScrollView 的 contentItem **不是 Layout，该属性被 Qt 静默忽略**
——内容左右顶死面板边缘，控件贴着边框线，看起来像被右侧编辑器「切掉/遮挡」；
Console 展开把面板推近编辑器后视觉更甚。

修复：改为真实 `x: 12; y: 12; width: parent.width - 24`。修后全部面板两侧各留 12px，
Console 折叠/展开两态实测零遮挡（截图存 tests_output/ui_gallery/）。

## 8. 一句立场

「成熟」不是加功能，是把用户每次视线扫过的地方都当作合同来履行：
边距是承诺、对比度是承诺、按钮的形态语义也是承诺。这一版把 UI 从「功能的陈列」
变成了「可以被信任的界面」——下一版继续还账。
