## 2. Q1：cheap 区间建模 ✅（s1_volume 校准）

### 2.1 校准的线性模型

s1_volume 实测：6 章总输入 5.22M tok、64 笔调用（≈10.7 笔/章）、hit 93.3%。
拟合：**总输入(N) ≈ 57.4k · N²**（N=卷内章数；6 章时代价 57.4k×91k=5.22M ✓）。
即：**每写一章，全部后续请求的输入增量 ≈ 115k·N tok**（历史在涨，每个请求都重读它）。

### 2.2 三项随 N 增长的成本

**① 缓存读税**（hit 价 $0.007/M = ¥0.0504/M，但乘的是巨大 token 量）：
第 N 章的 hit tok ≈ 107k·N → 读税 ≈ **¥0.0054 · N / 章**。
N=20：¥0.11 ｜ N=30：¥0.16 ｜ N=50：¥0.27 ｜ N=80：¥0.43/章——
**hit 不是免费的，它是 1/10 价的连续订阅**。当读税 = 内容基础成本（S3 实测 ¥0.21/章）时，
N ≈ **39 章**：此后每章成本的增长全部来自"重读历史"。

**② 延迟风险**：S1 实测均延迟 23s/笔（81k 均输入）是安全的；N=50 时单笔输入 ~1.2M tok，
缓存读的 prefill 时间与首字延迟尚未实测——**这是 20 章长卷要顺带测的指标**（⬜ 待长卷数据）。

**③ 灾难风险（最重要）**：会话越长，一次前缀破坏（bug/措辞变更/换模型）的爆炸半径越大
——N=50 时一次全 miss = 750k tok × $0.22/M = **¥1.19/笔**。风险敞口随 N 线性放大。

### 2.3 结论：cheap 区间

| 区间 | N（卷内章数） | 判定 |
|---|---|---|
| **黄金区** | **5 ~ 30 章** | 读税 < ¥0.16/章、命中 93→97%+、延迟可控 |
| 边际区 | 30 ~ 40 章 | 读税 ≈ 内容成本，延迟待实测，建议启动压缩 |
| 反噬区 | >40 章 | 读税 > ¥0.28/章且持续增长 + 灾难敞口过大，**必须压缩** |

**与商业结构天然吻合**：网文一卷 20-30 章——**卷界即压缩界**。
压缩重置的收益在 N>K 后线性显现（见 §4 模型），K 取 25-30 章。

## 4. Q3：小说专用压缩设计 v0（核心设计）

### 4.1 第一性原理：压缩只能发生在会话边界

前缀缓存三定律推论：**会话内的历史不可修改**（改一字全毁）。因此"压缩"不是在原会话里
删内容，而是——**用旧会话（全缓存）生成一份压缩产物，然后开启新会话，压缩产物成为
新前缀的一部分**。缓存数学：旧会话的最后一次调用 ~100% 命中（压缩请求是前缀扩展，
DSH 式接力）；新会话首笔一次性 miss 新前缀（~15-20k tok），此后恢复高命中。
**压缩的代价 = 一次性 miss + 摘要生成的输出 token；收益 = 读税封顶 + 延迟封顶 + 风险封顶。**

### 4.2 小说信息的"续写需求分层"（为什么小说可以高比例压缩）

续写第 51 章真正需要的信息，按**时间衰减**分三层：

| 层 | 内容 | 载体 | 压缩策略 |
|---|---|---|---|
| **近程（49-50 章）** | 直接衔接：结尾原文、场景连续性、文风、未收束的即时冲突 | **近程原文全保留**（不压缩）——这两章是"手感"与"戏"的来源 | 原样进新会话 |
| **中程（40-48 章）** | 状态与承诺：人物数值变化、新伏笔、关系变化、未决冲突 | **结构化台账**（角色状态/时间线/伏笔表——本就是结构化数据） | 并入卷终状态块 |
| **远程（1-39 章）** | 设定一致性、长线伏笔、名场面防复用、主线进度 | project_header（常驻）+ 全局摘要 + 台账 | 高比例压缩 |

**小说与通用 agent 的本质区别**：小说"必须精确"的信息（数值/名单/日期/物证位置）
**天然是结构化台账**——本项目早就有（追踪/*.md + 连续性台账.json），而"必须近期"的信息
天然集中在最后 2-3 章。两者都不依赖远程原文——**所以小说的合法压缩比远高于通用 agent**：
50 章历史 ~1.15M tok → 续写所需 ≈ 卷终状态块 3-4k + 近程原文 ~6k = **压缩比 ~97%**。

### 4.3 「接力压缩」协议（51 章续写的具体方案）

在第 50 章定稿后（清算/追踪完成后）执行，全程利用旧会话缓存：

1. **接力摘要调用**（DSH 式前缀扩展）：向旧会话追加一轮——
   「以下列格式生成本卷续写交接书：①近 3 章逐场景梗概（每场景 2 句，含人物/地点/未决点）
   ②人物近态速写（声口提醒一句/人）③当前主冲突与下一步张力 ④直接衔接点（第 50 章最后
   一个画面的精确状态）⑤文风注记（本章句长节奏/高频意象，供下章延续）⑥未决钩子清单」
   ——输入 = 全部历史（~100% hit），输出 = 交接书 ~2-3k tok（一次性输出成本 ~¥0.015）；
2. **新会话前缀**（按优先级）：
   system = project_header（全书冻结，逐字沿用——它是天然的新前缀共享段） + 写作指令库；
   随后首轮（新"开幕轮"）= 卷终状态块 = 接力书 + 台账快照（角色状态/时间线/伏笔表全文）
   + **49-50 章结尾原文**（50 章 800 字 + 49 章 400 字——近程原文保留，即"近全远压"）；
3. **台账零丢失保证**：交接书是叙事记忆，台账是精确记忆，两者互补冗余——数值/日期/物证
   位置以台账为准（清算器持续对账），叙事衔接以交接书为准；
4. **触发器**：卷界（优先，与商业结构对齐）/ 会话输入达到 1M tok 硬限的前 100k /
   读税监测（每章 hit tok 连续 3 章超过 550k 即提示压缩）。

### 4.3.1 DSH 研究带来的五条保险丝与一处修订（证据回填后）

修订：接回方式新增选项——**同会话替换**（DSH 式：摘要顶替旧历史 + 保留 16% 近程尾巴）
与本设计的**新会话接力**等价可行；卷界场景仍选新会话接力（与商业卷结构对齐），章界
应急压缩用同会话替换。五条保险丝（源码教训）：① 交接块 shrink 校验（压缩后必须显著
小于压缩前，否则 fail-open 不替换）；② 近程尾巴逐字保留（DSH 16%，我们取 49-50 章
结尾原文 ≈ 同策略的小说化）；③ 交接书**不得复述常驻注入**（system/台账已有内容禁止
重复——issue #5766 教训：重复注入引发行为异常）；④ 中文 token 计量必须用真实 usage
（DSH 自认 4 字符/token 启发式低估 CJK——我们的 usage.jsonl 本就是真值，天然合规）；
⑤ 交接书只做叙事记忆，精确锚点永远在台账（双层结构，设计确认）。

### 4.4 压缩后的命中账

新会话前缀 ≈ system 3k + 交接块 6k ≈ 9k tok——比 6 章卷的开局（~12k）还小。
重置后第 1 章 miss ≈ 12k + 章节增量，此后按 S1 曲线重新爬升。
**压缩不降低命中率天花板，只重置读税基数**——这是与"会话内压缩"（毁缓存）的本质区别。

### 6.2 内置化设计：压缩是流水线组件（不是实验脚本）

**模块**：`app/core/history_compaction.py`（S4 落地后实现，避免文件冲突）——与
volume_session 同级的一等公民，flag `writing.compaction`（默认关，S7 验收后翻默认）。

**触发器**（流水线在章循环里自动检查，零人工）：
① 卷界（大纲卷标题切换）；② 会话输入估算 ≥ 阈值（OpenCode 式 preflight，默认 800k tok）；
③ 用户手动（UI 按钮，章节视图）。

**产物与接回**（与 §4.3 协议一致，但实现内置化）：压缩产物 = 卷终交接块
（追踪/交接块_卷N.json + md 双写）→ 新 VolumeSession 的开幕块。断点续跑兼容
（交接块持久化，volume_session 的 load 链路识别）。

### 6.3 费用最小化：组装式压缩（目标：压缩操作 LLM 费用 ≈ ¥0）

关键洞察：**流水线每章已经在生产压缩所需的一切原料**——chapter_summary（每章）、
global_summary（每章）、角色状态/时间线/伏笔台账（tracking 每章更新）、连续性台账.json
（清算每章更新）。因此：

- **组装式压缩（默认路径，¥0）**：交接块 = 确定性装配既有产物——
  近 2 章结尾原文（800+400 字）+ 近 3 章 chapter_summary + 台账快照 + 全局摘要，
  **零 LLM 调用**，纯文件装配（scripts 级函数，费用精确为 0）；
- **LLM 接力书（可选增强档，默认关）**：DSH 式前缀扩展调用生成叙事交接书（~2-3k 输出
  ≈ ¥0.015/次），仅在盲评证明组装式连续性不足时启用；
- **费用验证**：两条路径的实际调用数与 token 记入 usage（phase=compaction），长文压测
  后对账"压缩功能自身费用/章"必须 ≤ ¥0.005（组装式应 = 0）。

**E3 假设（待证据）**：组装式（非 LLM 概括）的连续性足够——反证线索是台账+摘要本就
是无压缩时的全部远程记忆，压缩只是把它们集中；但"叙事衔接手感"是否受损必须盲评。

### 6.4 长文验证升级：60-100 章连续压测（终验）

- **规模**：单卷 30 章 × 3 卷（含 2 次压缩循环）或 60 章单卷 + 1 次压缩，按 S4 长卷
  能力择一；预算估算 ~¥6-12（S3 单章成本 × 章数 + 压缩 ¥0）；
- **测量**：逐章成本/延迟曲线（读税验证）、逐章 hit%、每 10 章盲评（质量随 N 的衰减曲线
  ——"第 80 章是否比第 10 章写得差"）、清算硬伤率随 N 趋势（一致性是否漂移）；
- **通过线**：60 章处单章成本 ≤ 20 章处的 1.5 倍（读税受控）、盲评分无趋势性衰减
  （线性回归斜率 ≥ -0.02/章）、压缩循环前后连续性维不降。
