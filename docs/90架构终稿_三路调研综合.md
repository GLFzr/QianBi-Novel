# 90% 综合命中率架构终稿（三路调研综合 + 实测校准）

> **生成**：2026-09-10 深夜（台前主代理）｜**上游**：《深度研究_下一代上下文架构_v1.md》
> + 三路定向调研（DeepSeek 生态 / 生产 Agent 缓存工程 / 论文+HF）
> **口径（用户裁定）**：综合命中率 = 命中 ÷（命中 + 未命中 + 输出），三者加总。
> **现状**：V10 八章中况 73.0%（H 173k/M 49k/O 14k 每章）｜**目标 ≥90%**。

## 1. 外部锚点：90% 有先例

Requesty 2026-04 八家 coding agent 实测：**Claude Code 91.9%** / OpenCode 89% /
Aider 84% / Roo 73.6% / Cline 61.4% / Kilo 45.5%（口径 cached/input）。结论原文：
"gap is architectural——跨顺序调用保持一致前缀的 agent 复用率显著更高"，
92% vs 46% 命中差 = **有效输入价差 5.4 倍**。DeepSeek 官方全站输入侧命中 56.3%
（open-infra-index）。**我们 73% 已超官方均值；90% = Claude Code 级架构纪律。**

## 2. 五条可搬做法 → 我们的落地映射

## 3. 理论模型（v11 配置，每章 DS 官方离峰）

- **H 冻结头 32k tok**（现 25.3k + 卷内不变节并入 + 全相位指令库）
- miss/章 ≈ **22k**（开幕瘦身 6k + 正文轮 2.5k + 三票轮 2.2k + 追踪 2k + 清算材料 3k
  + 摘要 0.3k + 写延迟残余 5k〔pacing 后〕）
- 输出/章 ≈ **8k**（prose high 2.5k + 三票瘦身 1.2k + audit low 1.2k + 追踪补丁 1.2k
  + 去味 0.5k + 摘要 0.3k + 杂 0.3k）
- **综合 = 288 ÷ (288 + 22 + 8) = 90.5% ✓**
- 每章成本 ≈ 288k×$0.007 + 22k×$0.22 + 8k×$0.66 = $0.0125 ≈ **¥0.09/章**
  （V10 ¥0.157 → -43%；0.19.0 基线 ¥0.386 → **-77%**）

## 4. 门槛与诚实边界

- 90% 的分母里输出只占 8k——**输出纪律是达标的一半**（effort 统一卷内、票瘦身、
  补尾、摘要降频缺一不可）；
- 40k 级冻结头的**质量影响必须过盲评**（预注册：D2/D4 ≥ -0.5）——40k 在 E0 安全区
  内但高于 V10 的 25k 实测带；
- effort 卷内统一（Lane A 警告：档位切换可能向 system 前端注入指令，打死冻结头）；
- 写延迟残余 5k/章是服务商语义，不可优化（E0 定案）。

## 5. 实施顺序（v11）

1. 八节瘦身 + 头扩容（卷内不变节并入，开幕轮只留逐章变）；
2. audit effort low + 投票紧凑 schema（max_tokens 上限）；
3. effort 卷内统一纪律（连接构造处强制）；
4. 全部旗标缺省关、字节锁、932+ 回归绿；
5. 3 章冒烟量测 → 13 章 A/B → 盲评闸门 → 达标转正。
