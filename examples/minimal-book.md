# 最小示例书（逐文件说明）

> 一本能在应用里正常打开、能继续往下写的书，最少需要哪些文件、每个文件长什么样。
> 文件名与字段都按应用真实读取格式写（`app/project.py`），照抄即可。

## 目录骨架（最小集）

```
我的书/
  设定/
    选题信息.md
    世界书.md
    正则.md
  大纲/
    大纲.md
  正文/            （空目录也行，写出第一章后出现 第001章_章名.md）
  追踪/
    角色状态.md
    伏笔.md
    时间线.md
    上下文.md
    章节摘要.md
    全局摘要.md
  pipeline_state.json   （可省略：没有它应用按全新项目处理）
```

> 「设定 / 大纲 / 正文 / 追踪」四个**子目录**必须存在（少一个，书架「打开目录」会报
> 「该目录不是写作项目」）；目录里的文件可以很空，但有几个字段是应用会读的，见下。

## 各文件最小内容

### 设定/选题信息.md

应用读取的四个字段：**题材 / 平台 / 预计总字数 / 灵感**（`read_idea_info` 按行匹配）：

```markdown
# 选题信息

- 题材：都市改命
- 平台：番茄
- 预计总字数：100 万字
- 灵感：社畜猝死回到入职前一天，这次他决定先跟未来的自己对账。
```

### 设定/世界书.md

条目化世界书，兼容四种写法，最简单的一种是 `- 名：述`：

```markdown
# 世界书

- 林晚：女主角，26 岁，殡葬师，能看见逝者残留的最后一段记忆。
- 对账簿：林晚随身的老账本，写下的债必须收回，否则折寿。
```

不需要手工标注锚点或优先级——`[常驻]` 标记与「追加登记」分区由应用在运行与反哺中维护。

### 设定/正则.md

本书硬规则。`must` 级会注入每一张写作 prompt 并进确定性复检：

```markdown
# 正则

每次改命必须索回等价代价｜level：must｜scope：全书
```

（非 must 的软约束直接写普通条目即可；正则语义出厂按「逻辑约束规则集」解读。）

### 大纲/大纲.md

```markdown
# 大纲

## 第一卷：对账
1. 林晚发现自己能听见「对账簿」翻页的声音。
2. 第一笔「债」到期，债务人暴毙，她意识到前世的自己欠了账。
```

细纲（`细纲_第NNN章.md`）可由应用按批次生成，手工准备也可以。

### 正文/第001章_章名.md

文件名格式 `第NNN章_章名.md`（三位章号）。空目录起步即可，应用会按队列落盘。

### 追踪/ 六件

这六份有出厂模板，空着也能打开（应用打开项目时会自动补齐，`ensure_tracking_files`）：
`角色状态.md`、`伏笔.md`（表头：伏笔/埋设章节/状态/计划回收/备注）、`时间线.md`、
`上下文.md`、`章节摘要.md`、`全局摘要.md`。建议从应用里新建一本书、把这六份的
模板抄过来，比自己手写快。

## 快速路径

不想手工造目录？直接在应用里 **书架 → 新建** 一本书（会生成全部骨架与模板），
再把你自己的内容填进去——效果与手工构造完全一致。
