# 千笔一文 Novel — AI 网文自动写作台

> **人定主题，AI 写书。** 输入题材与一句话灵感，自动完成设定、大纲、细纲与正文，全程可介入、可断点续跑。

千笔一文是一款由 AI 引擎驱动的网文写作桌面应用。它的定位不是"AI 辅助人写"的工作台，而是一条 **"AI 自动写、人随时介入"的写作流水线**：人只负责定主题、做判断，AI 负责把一本书从设定到完本跑完；每一章产出都经过本地 AI 味扫描、去味改写与一致性审校三道质量闸门。

## 核心理念

```
套路 = 确定性的情绪满足
先定情绪，再定故事
从验证过的模式出发，用模块组装，不要重新发明
无细纲不写正文 —— 细纲是"要发生什么"的契约，不是正文的形状
```

这套方法论被固化进了每一层 prompt：核心设定阶段先立**读者契约**（本书承诺的核心阅读快感）与**主角代理权**（主角不可替代的判断/选择/贡献）；细纲阶段要求每个情节点带字数预算与功能标签；正文阶段要求"爽点出手前要有可指认的危机/期待铺垫"。

## 它怎么工作

```
立项（你输入：题材/平台/一句话灵感/预计字数）
  → 核心设定（读者契约/主角代理权/金手指/世界观骨架）
  → 全书大纲（阶段划分 + 卷级大纲 + 终局储备边界）
  → 章节细纲（五段式细纲契约，分块生成、断点续传）
  → 章节微循环 ×N（每章全自动）：
      上下文组装 → 草稿 → AI味扫描(本地零成本) → 去味改写(仅阻断级) → 审校 → 定稿落库
  → 完本
```

- **AI 先跑，人随时介入**：暂停 / 停止 / 重写本章 / **带指导重写**（写下要求注入正文 prompt）/ 编辑任意项目文件后从断点续跑
- **断点续跑**：`pipeline_state.json` 记录进度状态机，关软件、改天再开都能接着写
- **记忆链**：追踪四文件（伏笔/时间线/角色状态/上下文）+ 全局摘要 + 章节摘要链，每章定稿自动更新，为长篇一致性提供锚点

## 质量闸门（每章自动过）

| 闸门 | 说明 |
|---|---|
| **字数闸门** | 不足目标 90% 自动扩写一次（`writing.chapter_word_target` 可调） |
| **本地 AI 味扫描** | 零 API 成本。破折号 / 不是A而是B / 音量反差腔 / 否定排比 / 章末预告 / 一级禁用词表 / 认知直述 / 比喻密度 / 微动作复读 / 碎句号 / 长段落… 分**阻断级**与**建议级**两级 |
| **去味改写** | 仅阻断级触发，最多 `gates.deslop_max_rounds` 轮；仍有阻断按策略处理 |
| **一致性审校** | 用审校槽对照 全局摘要/角色状态/伏笔/时间线 检查四类硬冲突（设定冲突/伏笔违背/角色崩坏/时间线矛盾）。分级标准：**只报读者会明显出戏的硬冲突，可商榷项一律归 ADVISORY**。修复带**回滚保护**：修复后复扫未改善则保留原稿，防止越修越糟 |
| **失败策略** | `gates.strategy`：`mark_continue`（默认）标「待修」继续写；`strict` 自动暂停等人处理 |

每章定稿结果（字数/去味阻断/审校阻塞/状态）写入 `pipeline_state.json` 历史，章节队列里一眼可见「通过 / 待修 / 写作中 / 排队」。

## 可靠性设计

- **LLM 分级重试**：网络错误/超时/429/5xx 指数退避重试（`llm.max_retries` 可调），4xx 其余错误立即报错不浪费重试；HTTP 200 但内容为空（`finish_reason=length`）也按可重试处理
- **细纲降级**：一批细纲生成失败自动拆半递归重试，单章失败跳过不阻断，下次运行自动补
- **失败现场**：异常时把最后 prompt 与日志尾部写入 `{项目}/pipeline_debug/failure_*.md`，审校阻塞问题追加 `review_findings.md`，不用重跑就能排查"当时模型收到了什么"
- **日志落盘**：`~/.qianbi_novel/logs/qianbi.log`（滚动 2MB×5）
- **原子写状态**：`pipeline_state.json` 先写临时文件再替换，防崩溃损坏
- **配置自动迁移**：旧版（`.oh_story_desktop`）目录/格式自动迁移，内置连接参数随版本升级，槽位指向失效连接自动修复，新内置连接模板自动补全

## 模型接入（酒馆式，三槽位路由）

### 三槽位路由

| 槽位 | 负责任务 | 建议 |
|---|---|---|
| **写作槽** | 核心设定 / 全书大纲 / 正文章节 / 扩写 / 去味改写 | 高质量模型 |
| **辅助槽** | 章节细纲 / 章节摘要 / 全局摘要 / 追踪更新 / 选题展开 | 快速低价模型 |
| **审校槽** | 每章一致性审校 / 审校修复 | 快速低价模型 |

每个槽位独立绑定连接与模型，可在「连接与模型」页配置；状态栏实时显示累计 tokens 与估算成本。

### 思考模式与思考强度（DeepSeek V4 系）

连接档案支持两档思考控制（参考 [DeepSeek 官方 Thinking Mode 文档](https://api-docs.deepseek.com/guides/thinking_mode/) 与 opencode-go provider 的 effort 映射实现）：

- **思考模式**：`默认` / `禁用` / `启用`——「启用」会发送 `thinking: {"type": "enabled"}`
- **思考强度**：`low / high / max`——作为顶层 `reasoning_effort` 参数发送，`max` 为 DeepSeek 最高档

> ⚠️ **重要**：启用思考会消耗大量输出预算。实测 max 档单次请求推理可达 2 万+ tokens，长任务（大纲/正文）请把 `max_tokens` 调到 **≥32768（推荐 65536）**，否则正文会被截断为空。长任务输入也会挤占预算，超长设定会自动截断（如大纲阶段核心设定只取前 4000 字符）。

### OpenCode Go 一键接入

内置连接模板 **ocgo-flash**（OpenCode Go · V4 Flash）：Base URL `https://opencode.ai/zen/go/v1`，模型 `deepseek-v4-flash`，思考模式启用 + 强度 max + max_tokens 65536。新建用户配置时自动出现，老用户加载配置时也会自动补全，填上 API Key 即可使用。

### 成本参考

- DeepSeek 系：120 章全书约几元到十几元（按官方价位估算）
- OpenCode Go 为订阅制，状态栏成本估算仅供参考
- ⚠️ max 思考档会显著增加 token 消耗（实测 3 章 + 设定/大纲/细纲 ≈ 37.7 万 tokens），追求性价比可在「连接与模型」把思考强度降为 high 或给辅助/审校槽单独降档

## 使用指南

### 第一步：配置连接与模型

1. 打开「连接与模型」页
2. 选择已有连接（如 ocgo-flash）填写 API Key，或「＋ 新建」一条：填名称、服务商、Base URL、模型名，点「测试连接」验证
3. 建议「拉取列表」确认模型名正确
4. 在底部「任务槽位绑定」把 写作槽 / 辅助槽 / 审校槽 指向你的连接
5. （可选）调整思考模式/强度与 max_tokens——见上文"思考模式"一节

### 第二步：新建项目

书架 →「＋ 新建项目」：
- **保存与命名**：保存位置、书名
- **创作设定**：题材、平台（番茄/起点/晋江/七猫/刺猬猫/其他）、预计总字数（决定全书章节数）
- **一句话灵感**：主角 + 核心设定 + 爽点方向；也可以点「✨ AI 展开」让模型先把灵感扩成 3 个可开书的选题方向再选

### 第三步：启动流水线

流水线页点「▶ 开始」，然后看着它写：
- **左栏章节队列**：每章状态一目了然（通过/待修/写作中/排队），点击章节阅读编辑，右键「重写本章」或「带指导重写…」
- **中栏写作工作区**：当前章状态、微循环步骤条、最近一章质量四格（AI味阻断/审校阻塞/AI味建议/字数）、快捷操作
- **右栏运行日志**：每步实时输出，可清空

> 💡 **想先看成品长什么样？** 仓库自带一本完整示例小说 `examples/改命笔记/`（AI 全自动产出的 3 章正文 + 设定/大纲/细纲/追踪全套），在书架「打开项目…」选择该目录即可查看、续写或改造，[示例说明](examples/改命笔记/README.md)。

写作过程中可随时：
- **⏸ 暂停**：当前 LLM 调用返回后停下（checkpoint 语义），处理完点「▶ 继续」
- **⏹ 停止**：尽快在安全点退出，进度已保存，下次点「开始」断点续跑
- **带指导重写**：停止后右键某章 →「带指导重写…」，写下要求（如"这章别写死女主"），点「开始」后该章会带着你的指导重新生成
- **📂 项目文件**：浏览/编辑 设定·大纲·追踪 下的所有 md 文件，改完保存即可，下游续跑自动读取新内容

### 第四步：完本

全部章节写完后流水线标记「完本」。正文以标准 markdown 存放在项目目录，可直接复制到平台发布。

## 常见问题 (FAQ)

**Q：max 思考下正文/大纲返回空内容？**
A：推理 token 吃光了 `max_tokens` 预算。把该连接的 max_tokens 调到 ≥32768（推荐 65536），或降低思考强度（high），或对辅助/审校槽单独降档。

**Q：细纲一次生成几章？为什么不是 5 章？**
A：实测 max 思考下 5 章批会把输出预算吃光（content=0），2 章批稳定（约 160 秒/批）。流水线按 2 章/批自动生成，失败自动拆半重试。

**Q：审校总说"未改善，保留原稿"？**
A：这是回滚保护：修复轮次后复扫，若阻塞数未减少说明模型改坏了，保留原稿并标「待修」，避免越修越糟。你可以在章节详情里手动修改，或「带指导重写」该章。

**Q：如何更换模型？**
A：「连接与模型」页新建/编辑连接，然后在「任务槽位绑定」把槽位指向它。任何 OpenAI 兼容接口都可以（含本地 Ollama / LM Studio）。

**Q：书稿存在哪？可以备份吗？**
A：所有书稿是纯 markdown 文件，存放在你新建项目时选的目录（默认 `~/Documents/千笔一文`）。整个项目文件夹复制即备份，也可以纳入 git 管理。

**Q：运行时报 QML 字体警告？**
A：Qt 不再捆绑字体，缺失字体时界面会回退默认字体。安装「思源宋体 / Source Han Serif SC」可还原设计效果。

## 开发指南

- **架构分层**：`ui/`（QML + bridge）→ `core/`（orchestrator/stages/gates/memory/state）→ `llm/`（router/client）→ `prompts/`（提示词资产）
- **新增一个创作阶段**：① 在 `prompts/` 写 prompt 模板 → ② 在 `core/stages.py` 实现 stage 函数 → ③ 在 `orchestrator.py` 的 `run()` 编排进流水线 → ④ 在 `core/state.py` 注册阶段 key 与标签
- **新增 UI 功能**：先往 `ui/bridge.py` 加 Slot/Property（QML 只能调 bridge 暴露的接口），再在对应 qml 页面接上；桥接层保持无界面逻辑
- **改 UI 后必跑**：`shot_ui.py`（无 QML 警告）+ `check_layout.py`（无越界）
- **改流水线后必跑**：`test_quality.py` + 一次小规模真实 e2e
- **提交前检查**：`git grep <你的key前缀>` 确认无密钥残留；`git status` 确认无 `tests_output/`、`.tmp_test/`、`__pycache__/` 混入
